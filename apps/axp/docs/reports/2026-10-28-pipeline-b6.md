## 1. 打包

### 1.1 类型增强失效与修复

B5 终审发现：`dist/esm/plugins/*.d.mts` 里的 `declare module "../types"` 对不上产物里的 `types.d.mts`。nodenext 下无扩展名的相对说明符不可解析，bundler 下也不会去探测 `.d.mts`，结果插件自带的请求选项扩展（`retry`、`cache` 等）在消费端整体失效。

修复在 `vite.config.ts` 的 `dtsAugmentationSpecifier`：dts 插件写完声明后，把产物里无扩展名的相对 `declare module` 说明符补上 `.mjs`（幂等，只处理 `.d.mts`）。dts 插件对这类写法的已知告警另行屏蔽，免得淹没真正要看的构建输出。

比较过的方案：

| 方案                                         | 结果                                                                   |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| 源码里直接写 `declare module "../types.mjs"` | TS2664，源码本身编不过                                                 |
| 源码里写 `.js` 或 `.ts` 后缀                 | 编译通过，但 dts 插件不会把它改写成 `.mjs`，产物仍然对不上             |
| 把所有请求选项集中声明到 `types.ts`          | 能用，但推翻"每个插件自带自己的选项扩展"的设计，插件作者要去改核心文件 |
| **构建时在产物上改写（采用）**               | 源码对 tsgo 与 IDE 保持正确写法，只有产物被改                          |

### 1.2 其它打包调整

- 新增 `tsconfig.build.json`（继承 `tsconfig.json`，只 include `src/**/*.ts`），声明产物只依据 src，不受 test、bench、e2e 影响。
- 插件入口在构建配置里显式列出 10 个公开插件。内部算法模块（`retry-timing`、`auth-match`、`cache-store`）不会因为放进 `plugins/` 目录就变成公开子路径。
- `TAxpAxiosConfig` 由 `Pick` 白名单改为 `Omit<AxiosRequestConfig, "cancelToken" | "signal">`，字段集不变，axios 以后加字段不用再同步白名单。
- 插件子路径会带出几个 `$` 前缀的测试钩子：`./cache` 的 `$defaultShouldCache`、`$resolveCloneFn`、`$shallowClone`，`./filter` 的 `$filter`、`defaultPredicate`，`./mock` 的 `$rewriteUrl`、`$shouldFallback`。按内部约定保留，文档不承诺。2026-10-29 起这些钩子（连同未写进文档的 `defaultPredicate`）标为 `@internal`，构建开启 `stripInternal`，不再出现在声明产物里；运行时导出保留，产物测试断言声明里没有 `$` 前缀导出。

### 1.3 产物集成测试

`test/integration/dist.integration.test.ts` 验证 `dist` 而不是 `src`，消费方程序放在临时目录，只经 `package.json` 的 `exports` 解析：

- `exports` 恰为 13 项（根入口、`./min`、10 个插件、`./package.json`），`exports`、`main`、`module`、`types` 指向的文件都存在。
- 每个子路径能被 Node 按 `exports` 实际导入；子路径与根入口共有的导出是同一引用，子路径独有的只有登记过的 `$` 钩子。
- 旧子路径 `./cancel`、`./key`、`./logger`、`./normalize` 不在 `exports` 里、无产物文件，导入报 `ERR_PACKAGE_PATH_NOT_EXPORTED`；三个内部算法模块同样不可导入。
- `./min` 与根入口混用时 `isAxpResponse` 互认（品牌是 `Symbol.for`），插件状态不共享。
- 声明产物里每个 `declare module` 的相对说明符都以 `.mjs` 结尾，且指向真实存在的 `.d.mts`。
- nodenext 与 bundler 两种解析下，消费方类型检查通过：请求选项增强生效、错误写法报错、`skipLibCheck` 关闭时产物声明本身无错。
- ES2020 及以上的 API 扫描（`min` 与 `esm` 逐文件），规则本身有自检。这是运行时底线 ES2019 的守门，起因是 `toSorted` 曾混进源码。
- dist 缺失或比 `src` / `vite.config.ts` / `package.json` 旧时，先 `npm run build` 再测，不跳过，也不每次重建。

`vp pack` 成功，产物测试通过。

## 4. B6 期间的质量收尾

细节见各提交，这里只记结论。

1. **lint 清零**（`133b67a`）：按项目配置 error 49 → 0，无豁免注释；tap 回调绑定到 tap 自身，方法式写法的 `this` 不再丢；src 覆盖率仍 100%。
2. **检查口径更正**（`901a336`，B5 报告 §3 已记）：此前误用裸 `vp check`（默认 printWidth 100、无类型感知 lint），改为 `npm run check`，整仓按项目配置重排一次，新增 `.gitattributes`（`eol=lf`）。
3. **统一精简**（`4bef080`，四个审查角度合成一轮修改）：
   - 运行时 API 底线 ES2019：去掉 `toSorted`（ES2023）与 `globalThis`，产物测试加扫描。
   - `resolveRequestOption` 收口七个插件的请求级解析；`waitAbortable` / `cancelIfAborted` 统一取消等待。
   - auth 路径匹配加快速路径（字面量与前缀通配），每请求省约 8µs 的 URLPattern。
   - filter 无可丢字段时不打补丁。
   - 缓存内存仓按清扫后的条目数节流清扫。Codex 复审指出固定间隔会让插入变成平方级，已改。
   - TokenManager 去掉 `#` 私有字段的降级代码，令牌放进不可枚举属性，`JSON.stringify` / `Object.keys` 不带出明文。
   - 两处行为变化：派生上下文的 `ctx.signal` 跟随补丁里的 `signal`；调用级 `undefined` 不再覆盖方法级的任意键（与 axios `mergeConfig` 一致）。
4. **类型**（`9324bfb`、`8875493`）：不写泛型时 `createAxp({ plugins })` 编译失败已修（`plugins`、`reject` 用 `NoInfer`）；插件作者类型 `AxpPlugin`、`AxpPluginInstance`、`AxpTap`、`AxpMiddleware`、`AxpNext`、`AxpContext` 的默认 R 改为 `AxpResponse`，文档里 `const p: AxpPlugin = {...}` 能直接装进默认客户端。

## 5. 性能

### 5.1 口径

测量时机器有外部负载：一个与 axp 无关、从根目录全盘搜索的 `find` 进程长时间占用 CPU，整机负载约 39%。所以这次的绝对值跨时段与 B0 不可比。做法是把 B0 的源码与 bench 导出到临时目录，与新 bench 交错各跑三轮（旧、新、旧、新、旧、新），按同一轮里相对 B1 的倍数和最小延迟比较。原始数据：`bench/ab-b0-{1,2,3}.json`、`bench/ab-new-{1,2,3}.json`。

额外开销 = (场景平均耗时 − B1 平均耗时) / B1 平均耗时；B5 列的是总耗时 / B1 平均耗时。负值表示比裸 axios 还快：B4 是缓存命中不进 axios；B2 旧版的小负值在噪声范围内。

### 5.2 数据

每格三轮依次列出。

| 场景                             | 旧：额外开销（B1 倍数） | 新：额外开销（B1 倍数） | 旧 min (µs)              | 新 min (µs)             |
| -------------------------------- | ----------------------- | ----------------------- | ------------------------ | ----------------------- |
| B2 无插件                        | -0.19 / -0.08 / -0.03   | 0.87 / 0.60 / 1.11      | 10.3 / 10.8 / 10.9       | 20.5 / 19.4 / 18.3      |
| B3 全插件缓存未命中              | 3.99 / 4.26 / 6.37      | 2.28 / 2.51 / 2.97      | 44.9 / 46.1 / 50.9       | 36.1 / 35.1 / 32.8      |

### 5.3 结论

| 场景 | test-plan 门槛             | 结果（三轮中位）                                                                                 | 结论                               |
| ---- | -------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------- |
| B3   | 额外开销比旧版降低 ≥ 20%   | 4.26 → 2.51，降 41%（逐轮 43% / 41% / 53%）；min 每轮都降：44.9 → 36.1、46.1 → 35.1、50.9 → 32.8 | **达标**                           |
| B4   | 不低于旧版                 | min 11.8 → 9.8µs，三轮都更快                                                                     | **达标**                           |
| B5   | 不低于旧版                 | 总耗时倍数 120.85 → 93.73；min 逐轮 1140.0 → 1098.6、1284.4 → 1071.1、1230.2 → 998.7，都更快     | **达标**                           |
| B2   | 额外开销 ≤ 旧版对应值      | 额外开销 -0.08 → 0.87；min 中位 10.8 → 19.4µs，多 8.6µs（逐轮 7.4–10.2µs）                       | 按原文**不达标**，按 A1 调整后达标 |
| B6   | 不低于旧版（验证按需克隆） | 额外开销 0.42 → 1.16；min 中位 15.6 → 23.1µs，多 7.5µs（逐轮 7.3–8.0µs）                         | 按原文**不达标**，按 A1 调整后达标 |

B2、B6 为什么多出这 7–10µs：这正是方案 A1 在入口用 `mergeConfig` 合并实例 defaults 的固定成本。B2 报告「方案 A1」一节实测为 +10.4µs，用户据此选定 A1。旧版无插件路径几乎零开销（B2 额外开销约 0），A1 之下不可能回到零。B6 的增量也是这份固定成本：POST 不在 retry 的默认方法里，retry 没有触发，也就没有请求体克隆；多出来的不是克隆，是入口合并。

B6 说明一点：B1 是不带请求体的 GET，旧版 B6 相对 B1 本来就有 3.3–3.8µs 的差，所以 B6 不宜和 B1 直接相减，应与旧版同场景比较。

**门槛调整**：B2、B6 按方案 A1 决策改为"相对 B1 的额外开销不超过约 10µs（入口合并 defaults 的固定成本）"，已写进 test-plan §8 的"实测结果"。真实网络请求在毫秒级，这约 10µs 占 1% 左右。

效率审查里提过 dispatch 阶段的 headers 合并优化，估计还能省约 3–6µs。2026-10-29 收尾批次试过：兼容 `false` 掩码与大小写覆盖规则的保守实现，交错 A/B 三轮 min 中位只省 B2 1.6µs、B6 1.8µs，不到 2µs 的保留门槛，已撤回（数据见 `bench/followups-ab.json`），B2、B6 维持按 A1 调整后的门槛。
