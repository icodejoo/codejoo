## 4. 规则、边界、组合与不变量

- resolveOption 覆盖四种写法、enable:false、总开关、null/undefined、非法类型、字段优先级、空数组整体替换、零值、输入不变及旧函数选项不求值。18 条旧 loading/filter 解析记录从 unit/context.unit.test.ts 改定位到 unit/options.unit.test.ts。
- loading 覆盖成功/失败、adapter/transformResponse 无 config 的异常、同回调并发合并、不同回调独立配对、混合参与、新一轮计数、delay/delayClose 与请求覆盖、同步抛错/异步拒绝、卸载定时器、旧快照和父子 setup 隔离。
- notify 覆盖默认成功/取消不通知、业务逻辑状态、消息回退、silent/请求关闭、自定义 R/ctx、空串/空白、缺 config/message/response、同步 stringify/notify 故障和异步 notify 拒绝、重名/卸载重装/多客户端复用。每次故障检查 console.error 且结果不变。
- repath 覆盖三种占位符、多段/重复变量、params 优先、空值回退、原始 data、removeKey、单段编码、host/query/hash 保留、缺值/无 URL、自定义模式和无捕获组、调用方不变。
- filter 覆盖默认生效/关闭、严格 true 的 predicate、异常原样抛出且不触网、豁免及 NaN/nullish/空数组覆盖、纯对象和无原型字典、特殊键、非纯对象原引用、调用方不变。
- envs 覆盖首个命中/短路、浅合并、无匹配/空规则、空/零值配置、规则异常、总开关、不进链、卸载不恢复。
- 组合覆盖反向注册仍按 loading→notify、repath→filter 排序；路径参数先编码消费再过滤；一对显示隐藏/一次通知；outer taps 看到最终 R，traceId 和对象身份保留，inspect 段序正确；最终失败直接抛 R 前已释放计数。

每个涉及 loading/notify 的运行时用例经 test/helpers/ui.ts 的 afterEach 调用 assertInvariants：I1 记录实际落定，I2 记录真实显示序列，I3 记录用户 signal 注册/注销净数并检查 pending，I4 按逻辑 signal 累计通知次数。父子共用回调测试先断言整体交错序列，再按已知进入/完成顺序把真实观测值分配到各客户端。纯类型用例不发送请求。

## 6. 规格不清与保守取舍

1. **loading 卸载时已显示的 UI**：规格仅明确取消定时器。为保持 I2 配对，卸载立即对已显示的每个回调通知 false，再禁止旧请求回调；尚未显示的窗口直接取消，不产生多余通知。隐藏回调故障仍隔离并 console.error。
2. **同回调不同请求的延迟**：delay 取触发 0→1 的请求，delayClose 取触发 1→0 的请求，沿用旧边界语义。零和负延迟即时；本批不另定义 NaN/Infinity 的业务含义。
3. **envs 的 enable 入口**：保留 axpEnvs([{ rule, config }])，补充 axpEnvs({ enable, rules }) 承载总开关；IEnvsOptions 名称保留并扩展为两种入口的联合类型。
4. **envs 旧清单恢复快照**：plugin-spec §7 和本任务明确“卸载不还原”，优先于历史 keep 行文字；分别验证 eject 和 dispose 后新 defaults 仍在。
5. **silent 与自定义 stringify**：按规格和迁移清单的扩展点，默认 stringify 执行 silent；自定义 stringify 原样收到 ctx.request.silent，可决定自行通知。notify:false / {enable:false} 对两种格式化方式都关闭本次通知。
6. **prepare 观测点**：B1 的 R.request 来自 axios 最终配置，axios 可能复制 params 或序列化 data。测试专用响应工厂保留内层 ctx.request，直接证明 patch 的值和引用身份；未给单插件规则混装观测插件，也未修改 B1。
7. **旧 benchmark 调用点**：B2 插件已无 install，不能继续传给 Axp.install。仅迁移 B3 并准确重命名；不恢复 axios 类型增强、不增加兼容 adapter，历史性能结果保持原样，本批不作跨场景性能比较。

六个 B2 文件和内核四文件的所有可测分支均实际命中，没有走不到的分支需要豁免，没有使用 v8 ignore。

### 7.1 四项实现

1. **管线使用有效配置**：client.ts 的公共 request 和动词入口统一由 dispatch 调用公开 `mergeConfig(axios.defaults, config)`，以合并结果构造根上下文。补齐 axios 发送时的默认 method 和小写化，再通过公开 AxiosHeaders.concat 展开通用、方法和请求头；signal 替换为逻辑 controller，并联动用户或 defaults 中的 signal。transport.ts 继续调用用户原 axios 实例，保留用户拦截器；对已删除的默认查询键补 null 禁用标记（含嵌套键），对已删除默认头补 false 标记，避免二次合并恢复。

### 7.3 mergeConfig 与 header 核查

本地 axios 为 1.18.0。包根 [index.js](https://github.com/axios/axios/blob/v1.18.0/index.js) 公开命名导出 mergeConfig，index.d.ts 同时声明该函数和 axios.mergeConfig。实现仅从 `axios` 包根导入，没有使用 unsafe 路径或复制内部合并实现。

核对同版本 mergeConfig.js：data、url、method 只采用请求级值，故 defaults.data 不会恢复，但默认 method 需要在入口补齐。transformRequest / transformResponse、adapter、timeout 等按请求值优先替换，不拼接转换器数组；回归用例检查每次实际尝试的转换器和用户拦截器各执行一次。

[AxiosHeaders 文档](https://github.com/axios/axios/tree/v1.18.0#axiosheaders) 明确 false 和 null 在 toJSON 时均省略，false 还可阻止未显式 rewrite 的后续 set。故被删除的默认头以 false 禁用，大小写不敏感；显式 false / null 均检查不会出现在 adapter 的 headers.toJSON()。用户拦截器若之后明确强制重写，仍遵从用户实例行为。默认参数的 null 标记只用于传输，默认 axios 查询序列化会跳过；自定义 paramsSerializer 若选择输出 null，仍遵从其自定义规则。

## 方案 A1：合并 defaults 的开销与优化（主会话，2026-10-28）

方案 A（请求开始时用 `mergeConfig` 合并实例 defaults）落地后实测开销远超最初估计的约 1µs：axios 的 `mergeConfig(defaults, config)` 单次约 8.5µs；把合并后的整份视图交给 `axios.request` 又让 axios 内部那次合并按全部字段计费，`createAxp` 无插件比裸 axios 慢约一倍（+18µs）。用户据此改选 A1，主会话做了两处优化：

1. 传输层比对根请求引用，各层没改动 params / headers 时跳过 null / false 掩码。
2. 交给 axios 的改为**差量**：以合并前的原始请求级配置为底，只叠加各层改动过的字段（逐键比对引用），层删除的字段交回 axios 按默认处理；axios 内部合并回到原始成本，结果等价。新增用例「各层未改动 params / headers 时原样透传，不做二次合并掩码」。

内存 adapter 三轮中位（安静度一般，看比值）：

| 场景             |    每次 | 相对裸 axios |
| ---------------- | ------: | -----------: |
| 裸 axios         | 13.95µs |            — |
| createAxp 无插件 |  24.4µs |      +10.4µs |
| 3 层直通         |  24.8µs | 每层约 0.2µs |
| 8 层直通         |  26.0µs |              |

### 为保持行为保留的实现

- 第 19 项可选的「仅靠 deepHash 回滚、删除浅空预检」未采用：深哈希只读自有字段，预检会读继承的可枚举字段；带自有空字段与继承 getter 的回归用例确认旧行为会抛原异常，删除预检会漏掉这次读取。其余 key 重构通过 12,000 组及全部现有用例逐位对照。
- 第 17 项没有把特殊对象的 getTime()/toString() 返回值无条件改成 String()：自定义对象的默认转换提示与字符串提示不同，Symbol 与空串相加原本会抛 TypeError。数字已用 String，非数字回退保留原提示与异常；曾出现的差分失败已修复，原差分用例未删。
- repath 的 params 使用 isObject，data 使用原对象标签及标量规则，保持原有差异；loading 的 NaN 延迟仍即时切换。
- 保护范围的既有/外部文档改动不回滚，故验收 4 仅能保证本轮未写保护文件，无法满足相对 HEAD 的字面空 diff 要求。
