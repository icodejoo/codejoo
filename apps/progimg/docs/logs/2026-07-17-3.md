# 2026-07-17-3: register 即自动接管 + 页面向预构建 SW 传参

## 变更原因

上一份日志(2026-07-17-2)决定"只文档不改代码"后,使用方进一步提出两点 API 诉求:

1. 不想每次都手动调一次 `auto()`,注册成功就应默认接管。
2. `registerImgprogressSW(dest, options)` 的 `options` 要能同时配置页面端接管行为和 SW 端处理参数。

经确认:不需要"关闭自动接管"的开关(注册即接管);返回值加上 `stop`。

## 目的

把接入收敛成一步:`registerImgprogressSW(swUrl, options)` 注册就绪后自动接管,选项在一个对象里同时覆盖页面端与 SW 端。

## 落地方案

### 关键约束:预构建 SW 是独立文件,页面配置怎么进去

预构建的 `imgprogress-sw.js` 是独立脚本,页面端拿不到它的作用域。评估了两条通道:

- **postMessage**:有时序窗口(SW 可能在收到配置前已用默认配置处理请求),且 SW 重启后配置丢失。否决。
- **SW 脚本 URL 的 query**(采用):SW 一启动就能从自身 `location.search` 读到,在 `setupImgprogress` 之前生效,无时序窗口;`scriptURL` 不变,重启也不丢。

限制:只有可 JSON 序列化的标量/普通对象能这样传。含函数(`onError`)或正则(`include`/`exclude` 的 RegExp)的选项无法跨进程传输,仍需走自建 SW。页面端 `onError` 不受影响——SW 出错本就通过 postMessage 回传页面。

### 涉及文件

- **新增 `src/shared/config-transport.ts`**:`appendSWConfig(swUrl, options)` 按白名单(threshold/colorBlock/fallbackColor/firstFrame/blurRadius/headBytes/firstFrameMaxBytes/staticProgressive/deferVideos/cache)挑出可传字段,JSON 编码进单个 query 参数 `__imgprogress_cfg__`;`parseSWConfig(search)` 同白名单二次过滤解析。
- **重写 `src/page/register.ts`**:`registerImgprogressSW(swUrl, options?)` 签名改为接受合并选项 `RegisterImgprogressSWOptions = ImgprogressAutoOptions & Partial<ImgprogressSWOptions>`;注册用 `appendSWConfig` 后的 URL → `await ready` → 内部调 `auto(options)` 启动接管;返回 `{ controlled, stop }`。SW 不支持/注册失败时优雅降级(仍返回 noop stop / 接管照挂但走原图)。
- **改 `src/sw-standalone.ts`**:`setupImgprogress(parseSWConfig(location.search))`。
- **README**:方式一改为"注册即接管"、`options` 双端配置说明与 query 传参限制;视频开关示例改为在 `registerImgprogressSW` 传 `videos: true`;"尽早注册 SW"一节补充"传 SW 参数会改变 scriptURL、与 head 无 query 预注册不互相复用"的坑;配置表补充"哪些能页面传/哪些只能自建 SW"。

### 已知取舍

- 传 SW 端参数会给 scriptURL 加 query,与 `<head>` 里无 query 的预注册不再是同一个 SW,失去复用。README 已提示:要传 SW 参数就用自建 SW,head 与应用注册同一无 query URL。
- 未引入"SW 未就绪先占位、就绪后接管"的运行时兜底(见 2026-07-17-2 的后续可选项),本次仅做"注册即接管"的接入简化。
