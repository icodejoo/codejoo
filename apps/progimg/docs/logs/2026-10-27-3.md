# 2026-10-27-3 包名改为 @codejoo/progimg,目录与标识符同步

## 变更原因

原包名 `@codejoo/imgprogress` 太长,装起来、写起来都费劲;展示名也想统一成 "Progressive Image"。该包尚未发布到 npm(registry 查询 404),现在改名没有迁移成本,趁早把目录、API、产物名一次改齐,免得新旧名混着出现。

## 目的

用更短、好拼的 `progimg` 替代 `imgprogress` / `picman`,并让包名、目录、代码标识符、文档保持同一个名字。

## 落地方案

- 候选名查过 npm 占用:`progimg`、`@codejoo/progimg` 均可用;最终选带 scope 的 `@codejoo/progimg`,与仓库内其他子应用风格一致。
- 目录 `apps/picman` → `apps/progimg`(`git mv`);`pnpm-lock.yaml` 的 importers 键、`apps/storage/ARCHITECTURE.md` 里的引用同步;`package.json` 的 `repository.directory` 同步为 `apps/progimg`。
- 标识符按 `Imgprogress`/`ImgProgress` → `Progimg`、`imgprogress` → `progimg`、`IMGPROGRESS` → `PROGIMG`、`picman` → `progimg` 整体替换,覆盖 `src/`、`test/`、`examples/`、`scripts/`、`vite.config.ts`、README、ARCHITECTURE、REQUIREMENTS、algorithms 文档。涉及对外名称:`registerProgimgSW`、`setupProgimg`、`ProgimgTask` 等 API,`progimg-sw.js` 产物,`data-progimg-bg` 属性。
- 文档里过期的 `<pic-man>` / `pic-man.ts` 顺手校正为现行的 `<img-progress>` / `element/index.ts`。
- 标签:Web Component `<img-progress>` → `<prog-img>`(自定义标签必须含连字符),`customElements.define` 注册名、README / ARCHITECTURE / REQUIREMENTS / 测试同步。源码文件名都是按职责起的通用名(sw/、element/ 等),没有带旧品牌名的,无需改。
- 不改:`docs/logs/`、`docs/plans/`、`docs/superpowers/` 里的历史记录保留原名。
