# 2026-07-17-5: 色块静态化、缓存跳色块、缩略缩放、多源接管(picture/video)一批需求

## 变更原因

使用方提出一批需求,目标是简化色块、统一缓存行为、规范缩略图大小,并把接管扩展到 picture/响应式 srcset 与多源 video。

## 需求清单与决策

1. **色块静态化**:不再读图片信息头取色,改用静态色,默认灰 `#e0e0e0`,初始化参数可覆盖;色块提前生成、所有请求就地复用以节约性能;`<img>`/`<picture>`/`<video>` 可用 `data-ske-color` 覆盖单元素颜色。**决策(路线1,SW 主导)**:SW 出静态默认色块(记忆化复用),`data-ske-color` 由页面端请求时经 `PARAM_SKE` 带色让 SW 生成。
2. **统一行为**:缓存已存在完整图则直接上缓存、跳过色块。
3. **缩略图缩放**:缓存按原图缩小 N 倍存储,全局配置默认倍数,`data-thumb-scale="x"` 按元素覆盖。
4. **缩放倍数参考值**:采用**边长缩小 8 倍**为默认(2 的幂、重采样质量好;面积 1/64;缩略 JPEG 约 3–8KB),并配**最长边上限 320px、下限 32px**兜底。用户原拍脑袋的 10 倍也在合理区间,取 8 更标准。
5. **video 多源**:facade 要处理多个 `<source>`(摘除/还原所有 source 的 src+type)。

配套(上一份日志已确认):picture/响应式 srcset 接管——key 用 `currentSrc`,切阶段时**所有候选 URL 都加 stage 参数、保留描述符**,保留响应式与动画播放。

## 分批实施

工程量大且横跨 SW 端与页面端,采用**分批实现、每批过测**的方式,避免一次性改动质量失控。

### Batch 1(本次,SW 端):需求 1 + 需求 2

- `shared/protocol.ts`:新增 `PARAM_SKE`(`__imgprogress_ske__`)、`PARAM_THUMB_SCALE`(`__imgprogress_thumb__`),`stripImgprogressParams` 一并剥除。
- `sw/pipeline.ts`:
  - 新增 `getColorBlock(w,h,color,mode)`,按 `color|mode|WxH` 记忆化;不再传 `palette`(不再取色)。
  - `mainFlow` 读 `PARAM_SKE` 得骨架色(缺省 `fallbackColor`);**统一用 `stripImgprogressParams` 后的规范 URL 做 fetch/缓存/通知**,不把标记参数泄漏给源站或写进 key(无参数时沿用原 Request 保留语义)。修掉了"原始请求带 ske 参数时通知 URL 未剥参、与页面端 key 对不上"的问题。
  - `handleImageRequest`:原始请求先查缓存,`matchStage(key,"1")` 命中则直接返回,跳过色块与重新下载(需求 2)。
- `shared/types.ts`:更新 `fallbackColor` 文档为"静态骨架色,可由 `data-ske-color` 逐元素覆盖"。
- 测试:新增"已缓存完整图直接回缓存不 fetch""`PARAM_SKE` 色块用指定色且通知 URL 为规范 URL"两例;`pnpm test` 111/111、build、fmt 均过。

### 后续批次(待做)

- **Batch 2(SW 端)需求 3**:缩略图按倍数缩小(OffscreenCanvas resize),读 `PARAM_THUMB_SCALE`;全局默认倍数 8 + 上下限;`makeFirstFrame`/`backgroundStatic` 的缩略生成接入倍数。
- **Batch 3(页面端)picture/srcset**:srcset 改写工具(全候选加/去 stage 参数、保留描述符),`track` key 用 `currentSrc`,`isOwnEcho` 纳入 srcset;并把 `data-ske-color`/`data-thumb-scale` 通过请求参数下发给 SW(打通需求 1/3 的页面侧)。
- **Batch 4(页面端)需求 5**:`videoFacade` 支持多个 `<source>`,`data-ske-color` 接入。

## 已知取舍

- 色块记忆化按(颜色,样式,尺寸)缓存:保持了正确的 intrinsic 尺寸(不引入 CLS),同尺寸同色请求复用;非"全站唯一一块",但去掉了取色这一真正的性能开销。
- `sniff` 仍会计算 `palette`(现已不被色块使用),可在后续批次从 sniff 移除以进一步省算力。
