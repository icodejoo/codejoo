## TL;DR

- **（2026-10-10 补）落地复测**：shimmer 光带默认降频 24 次/秒（global）、clip 不再挂 pulse、防火墙补钉 `--skz-tbg`、新增可选 tofu；2000 卡 global shimmer clip GPU 10.44 → 3.05 ms，pulse + clip 22.8 帧 / 33.7 ms → 60.4 帧 / 6.95 ms；4× 降速下默认档没收益。见「落地复测」。
- **（2026-10-09 晚补）默认文字模式已从 underline 改为 clip；下文 A~F、滚动、sweep 补测的全部数据都是 underline 默认时测得。** 补测见「默认文字模式改为 clip 后的补测」：fade / solid 没有变贵；shimmer GPU 约 3 倍；**pulse + global 在 16000 元素掉到 24 帧（防火墙疑似被 `--skz-tbg` 绕过，未验证）**；4× 降速下 svg shimmer 12.8 帧（underline 34.8）。
- 这份数据只有**一遍**正向、**没有 F 组（4× 降速）**，也没做反向复测；批内 CPU 均值 17.6%~27.3%（含 Chrome 自己），没做到"<10%"。差距在 2 倍以内的结论别当真，下面只下"差距很大"的结论。
- 默认路径（`base.css` + `global` + `enable()`，列表结构）16000 元素稳定 60 帧、样式重算约 4~5ms；滚动时仍 60 帧。纯 CSS 无 JS 在 16000 元素只有 13~25 帧（不同批相差较大，负载越高越低）。
- 防火墙在"根下只有几个大块、且都在视口里"的页面上等于没开：双栏表单 16000 元素默认路径 17 帧，和纯 CSS（15.6 帧）没区别。这类页面 svg 是 60 帧（样式重算 0.04ms）。
- **（已处理：`fps` 计时器已删除）`fps` 计时器在真实 DOM 上几乎走不到**：库只要根下任意一层有 ≥2 个子元素就启用防火墙并忽略 `fps`（`firewallItems` 的实现决定的）。表单页 `fps:"auto"` / `fps:24` 的数据与默认一致，`snap` 里没有 `skz-tick`。只有把 `IntersectionObserver` 置空才能走到计时器（D5/D6），那时 `auto` 16000 元素 45 帧，但 svg 同场景 60 帧。README "没有列表结构的大骨架用 `fps:"auto"`"的说法在本次测试里不成立。
- **sweep 的光带在根高度超过约 19~20k px 时看不见（已修复）**：连拍截图 12 张完全相同，把动画暂停在不同进度画面也不变；根高 18940px（140 张卡）还能看到，20293px（150 张卡）起消失，混合模式和 `skz-sweep="bg"` 一样。本次 A3/E6/E7/S2 的 500、2000 卡片（67k / 270k px）都落在不可见区间，**这几行原数据测的是看不见的动画，原数保留但不可当作 sweep 的真实成本**。后续排查（`bench/2026-10-09-sweep/NOTES.md`）查明根因是 `skewX(-12deg)` 绕根中心倾斜、根越高光带被斜得越远，不是 GPU 纹理上限；改成默认竖直（`--skz-sweep-skew: 0deg`）后任意高度可见。修复后真实数据和合并后的数据见「sweep 修复后补测」。
- `steps()` 降帧无效（35.6 vs 35.3ms，25 帧对 25 帧），已删除。`skz-cv` 只对"纯 CSS 无 JS"有用；与 `enable()` 叠加反而比单用 `enable()` 差，且开启贵 3 倍多。`fit:true` 每帧最便宜但开启要 ~520ms（16000 元素，约 8 倍）。
- explicit.css 在 `enable()` 路径下样式重算比 base 低约 40%（16000：2.60 vs 4.89ms），但两者都是 60 帧；收益主要在纯 CSS 路径（34 vs 21 帧）。

### 控制变量

- **同一份构建**：先 `pnpm build`；基底 `base.css` / `explicit.css`，变体按需叠加（`global.css`、`svg.css`、`sweep.css`），和用户引入方式一致。JS 用 `global-js.mjs` / `svg-js.mjs`（svg 行只引 svg，不叠 global）。纯 CSS 行只引 CSS，不加载任何变体 JS。
- **同一页面模板**：`perf.html`，卡片列表，每卡 8 个元素（500 张 = 4000 元素，2000 张 = 16000 元素）；D 组用双栏表单，每行也是 8 个元素，4003 / 16003 元素。
- **同一视口**：1200×800，DPR 1（`Emulation.setDeviceMetricsOverride`）。
- **同一套 trace**：`bench/kit/trace.mjs`，预热 0.8s，3 次 2.5s trace 取中位数，经 `bench/kit/run-locked.mjs` 加锁串行，端口 9351。
- **一律走真实 `enable()`**，除标明"纯 CSS 无 JS"的行（只写根属性）。
- 开启耗时：`enable()` 路径量真实的 `off(); enable(root, opts); 强制样式 + 布局` 7 次中位数（含防火墙、inert、blob）；纯 CSS 路径量切 `skz` 属性。**与旧报告（只切属性）口径不同，不能直接比**。
- 样式重算 = 每帧 `UpdateLayoutTree`（ms）；表里缺失的 PrePaint / Paint 按 0 计。
- 帧率由 rAF 循环计数得到，会强制每帧一次主线程帧，合成器动画（sweep、svg）的 PrePaint 也会被算进来（bench/README.md 里提过）。

### 对 kit 做的改动

都向后兼容、默认行为不变，细节见 `bench/2026-10-09-matrix/NOTES.md`：`trace.mjs` 加固定视口、场景 `cpu` 降速、`snap` 状态输出、窗口最小化 / 页面不可见时作废重测；`run-locked.mjs` 加 `PERF_SCRIPT` 环境变量以便跑正确性抽查脚本。第一轮数据因测试 Chrome 窗口被最小化（rAF 停摆）整批作废，留在 `results-discarded-minimized/`。

### 结论

- **fade / solid 没有变贵**。fade：4000 元素 GPU 1.32 vs 2.03、16000 元素 1.98 vs 1.94，样式重算、PrePaint 相同，Paint 都是 0；开启耗时 24 vs 26 ms、106 vs 97 ms（同场景金丝雀在 84~96 ms 之间浮动，属噪声）。solid 逐项相同。4× 降速下 fade 仍是 60 帧（GPU 1.71 vs 1.75），solid 60.8 帧。原因：fade 是根上的 opacity 合成动画，文字的 `background-clip:text` 只在开启时光栅一次，之后不再重绘。**不需要让 fade / solid 回到 underline 默认。**
- **shimmer 的 GPU 约 3 倍**（global 3.5 → 11 ms，svg 1.9~2.3 → 5.9~6.8 ms，表单页同）；svg 下 PrePaint 约 1.5~2 倍（4000 元素 1.92 → 3.95，16000 元素 8.31 → 12.98 ms）。正常速度下 fps 基本不掉：16000 元素 global 60.4 对 60.4，svg 58.8 对 60.4，表单 svg 52.8 对 60.4（这两处是本轮唯一看得见的掉帧）。开启耗时无差别（±10%）。
- **pulse + global + `enable()` 在 clip 下明显变差**：16000 元素 24.4 帧 / 样式重算 32.7 ms，underline 是 60.4 帧 / 6.15 ms（第二次尝试复现：28 帧 / 27.5 ms）；4000 元素样式重算 7.14 对 1.79 ms、PrePaint 0.69 对 0.05 ms。防火墙标记数相同（1992 项）。读 `_global.scss` / `tier1.scss` 推测：clip 在根上写 `--skz-tbg: var(--skz-fill, …)`，随 pulse 每帧变化的已展开值继承给所有后代，防火墙只重声明了 `--skz-fill` / `--skz-ul-fill` / `--skz-bg-pos`，挡不住它。**这只是读代码的推测，没做实验验证；已知的修法方向是让防火墙也钉住 `--skz-tbg`。** shimmer 路径没有这个问题（样式重算 7.01 对 6.68 ms）。
- **sweep**：浅 / 深都没有实质差别，但 clip 的 PrePaint 略高（16000 元素浅色 8.56 对 6.47、深色 6.46 对 5.37 ms，约 +20%~30%；本机噪声量级，没复测），GPU 0，开启耗时在噪声内。**fit**：每帧同 shimmer（GPU 9.43 对 3.33 ms），开启 767 对 649 ms。
- **4× CPU 降速（16000 元素）**：svg shimmer **12.8 帧 vs 34.8 帧**（PrePaint 66.4 对 22.2 ms、Paint 23.7 对 7.1 ms，是本轮最差的一格）；global shimmer 26.8 对 27.6 帧（样式重算主导，几乎持平，GPU 5.25 对 2.42 ms）；fade 60.0 对 60.4 帧、solid 60.8 对 60.8 帧。结论：低端机 / 降速下 svg + clip 的 shimmer 代价最大，这类场景建议 `text: "underline"`；global 路径基本不受影响。
- **没有变的**：开启耗时（除 fit 外 ±10%）、样式重算（shimmer / fade / solid）。

- 装饰线是否参与 `background-clip: text` 的裁剪，只在 Chrome 实测过；Firefox / Safari 没测，是已知风险（降级只能判断属性存在）。
- 直接写在 div 里的裸文字在 clip 下不出骨头（不可见），本节没为它设场景（原型阶段已确认，见 `bench/agents/a7-clip-underline/NOTES.md`）。

- 其余没测项同上一节「没测 / 不确定」。

## 各方案结论

- **fade / solid**：无论多少元素都是 60 帧、样式重算 <0.3ms。开启耗时随元素数线性增长（4000 元素约 22~24ms，16000 约 70~76ms）。
- **sweep**：原矩阵里光带可见的条件下（E8、E9）每帧样式重算 0.08~0.18ms、PrePaint 0.06~0.23ms；根高超过约 19~20k px 光带不显示的问题已修复（见「sweep 修复后补测」），修复后 16000 元素 60 帧、样式重算约 0.6~0.8ms、PrePaint 约 5~6ms、GPU 约 1.4~2.3ms。混合模式和容器色模式开销没区别（E6 vs E7），现已合并为一种按主题切换。
- **pulse / shimmer 纯 CSS 无 JS**：4000 元素 53~60 帧，16000 元素 13~25 帧（样式重算 36~56ms）。小骨架够用，大骨架不行。
- **global + `enable()`（防火墙）**：列表结构下 16000 元素 60 帧，样式重算 4.0~4.9ms，PrePaint ≈0.1，滚动时 60 帧（样式 5.2ms、PrePaint 2.2ms）。开启耗时和纯 CSS 基本一致（约 62~66ms）。**但只对"项多且大部分在视口外"的结构有效**，双栏表单上无效。pulse 与 shimmer 差别不大。文字模式 underline / leaf 无差别（C0 vs C1）。
- **svg**：所有结构下 60 帧、样式重算 ≈0.04ms，代价是 PrePaint 4.7~8ms（16000）和更贵的开启（16000 元素 105~134ms，A6p 一次测到 287ms，原因没查，单次异常）。是唯一在无列表结构页面上还能 60 帧的方案。
- **explicit.css**：`enable()` 路径 16000 元素样式重算 4.89 → 2.60ms（-47%）、4000 元素 1.75 → 1.14ms（-35%），开启 62.5 → 50.3ms；纯 CSS 路径 41.3 → 23.8ms，帧率 21 → 34。但 `enable()` 路径两者都是 60 帧。B5（explicit + svg）的 PrePaint 反而比 B4 高（7.8 vs 4.7），原因没查。
- **fit:true**：每帧最便宜（样式 3.3ms、Paint 0.5ms，只有 6 项可见），代价是开启 ~520ms（16000 元素）、500 张卡时 48ms，且 2000 项里 1994 项被 `display:none`。
- **skz-cv**：见候选表。

## 没测 / 不确定

- **F 组（CPU 降速 4×）没测**：被用户叫停，没有任何数据。`bench/kit/trace.mjs` 已支持场景里写 `"cpu": 4`，场景文件 `scenarios/sc-F.json` 已生成，可直接跑。
- **只有一遍正向**，没做反向第二遍；`scenarios/sc-*-rev.json` 已生成但没跑。每格是 3 次 trace 的中位数，但跨时间漂移没有第二遍可比。纯 CSS 16000 元素的帧率在不同批里 13~25 帧，说明负载敏感。
- CPU 环境没达到 <10%（见方法）。
- **`fallback:"fade"` 没测**：走不到降级分支。
- sweep 光带消失的根因已查明并修复（`skewX` 绕根中心倾斜，见 `bench/2026-10-09-sweep/NOTES.md`）；没测 sweep 在 DPR>1、独显上的性能；深色容器色模式只在浅/深两套自测页上验证过视觉，没在真实业务页上看过。
- 开启耗时是新口径（真实 `enable()`），与旧报告不可比；svg 开启耗时里 A6p 2000 的 287ms 只出现一次，没重测。
- A5/A6 的 4000 元素行 pulse 与 shimmer 的差异在噪声范围内，未下结论。
- D 组的"无列表结构"页是我设计的双栏表单；真实的大表单（单栏几百行字段）会被防火墙当成列表，行为接近 A5。
- 只测了桌面 Chrome 154；Safari / Firefox / 移动端 / 低端机都没测。
- 显式模式、leaf 与 svg 的组合只测了 shimmer。
