# skeletonizer

**Live demo: <https://icodejoo.github.io/codejoo/skeletonizer/>** (switch effects, tiers, dark mode, fit and more)

Skeleton screens for the web, Flutter-`skeletonizer` style: render your **real DOM** with **mock data**, mark which elements are bones (`skz-text` / `skz-bone` / `skz-leaf`), and let **pure CSS** paint them. No hand-drawn placeholder shapes to maintain.

> 中文文档（更详细）：[README.zh-CN.md](./README.zh-CN.md)
>
> Coding agents: read [llms.md](./llms.md) for the condensed usage guide (also shipped in the npm package); see [AI coding agents](#ai-coding-agents) to wire it in.

The package ships two builds, **pick one** (they are self-contained; do not load both on the same page):

- **full (default)**: `import "skeletonizer"`, one line (styles + runtime + the global `skz`). Everything: inheritance firewall (long lists), the SVG scheme and old-browser fallback, four text modes, lazy rendering, a much higher size limit.
- **lite**: `import "skeletonizer/lite"`. The smallest and simplest rules, for small to medium skeletons in modern browsers (up to about 2,000 elements under a single root).

How to choose is in [the comparison table below](#full-or-lite). Since 0.3.0 the entry points are exactly these two plus the framework adapters; coming from 0.2.x see [Upgrading to 0.3.0](#upgrading-to-030).

Bones are **marked by you** (the default since 0.2.0): unmarked content renders as-is. For third-party components whose markup you cannot edit, an opt-in `skz-auto` region falls back to tag-based inference. Upgrading from 0.1.x: see [Upgrading to 0.2.0](#upgrading-to-020).

## How it works

Three parts:

1. **Real DOM rendering**: write components in your usual JSX / Vue templates, just feed them mock data instead of real data.
2. **Mock data**: use `Bone` helpers to generate text, images and other placeholders; all deterministic (SSR friendly, no `Math.random`).
3. **You mark the bones, CSS paints them**: the bare attributes `skz-text` (text), `skz-bone` (images, avatars, buttons, colour blocks), `skz-leaf` (merge a subtree into one bone) and `skz-ignore` (keep as-is) say what becomes a bone; unmarked content renders untouched. Third-party components you cannot mark go inside a `skz-auto` region, where tag names and content are used to infer bones (see [Mark the bones](#5-mark-the-bones)).

The skeleton styles are pure CSS, with no UA sniffing and no JS gate: **the CSS works without any JS, the only switch is the `skz` attribute on the root** (JS only toggles it and writes the root attributes). The two ways degrade differently:

- **lite**: the target line is Chrome 119+ / Safari 16.4+ / Firefox 128+ (all of `@property`, relative colour syntax, `:has()`, `text-decoration-thickness` and `background-clip: text`). Browsers above the line get the "modern tier" (one `@supports`: `skz-text` bars in round / clip style, plus controls as one block, icon detection and the other inference inside `skz-auto` regions), and `pulse` / `shimmer` are driven by one CSS animation on the root. **Browsers below the line get tier 0 (static blocks per tag, `skz-auto` regions only), the `skz-bone` / `skz-leaf` marks and fade; `skz-text` bars need the modern tier**; there is no step-by-step progression.
- **full**: three progressive layers (tier 0 → tier 1 → tier 2), from Chrome 88 to the newest, plus an SVG animation fallback for old browsers. The tiers' inference only applies inside `skz-auto` regions; the `skz-text` marker is served by tiers 1 / 2.

## Full or lite

| Aspect                                     | **full (default)**                                                                                                                                                             | **lite**                                                                                                                                                          |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Good for                                   | Long lists / feeds / big forms; animations on old browsers; several text modes, lazy rendering; fine performance tuning; "just works for everything"                           | Small to medium skeletons in modern browsers: cards, detail pages, lists of a few dozen rows; "smallest bundle"                                                   |
| Browser bar                                | Full effect set on the line below; under it tiers 1 / 2, and pulse / shimmer fall back to SVG animation on old browsers                                                        | Chrome 119+ / Safari 16.4+ / Firefox 128+; below it: tier 0 static blocks (`skz-auto` regions), `skz-bone` / `skz-leaf` marks, fade; `skz-text` bars need the bar |
| Verification                               | **Chrome only**; Firefox / Safari are expected to work per the specs but were not tested                                                                                       | Same                                                                                                                                                              |
| Size guidance                              | A much higher limit: with the inheritance firewall 2,000 cards (16,000 elements) still run at 60 fps at normal speed; under a 4× throttle 4,000 elements drop to 47.6–57.6 fps | Up to about 2,000 elements under a single root (data in [the lite size limit](#the-lite-size-limit))                                                              |
| Effects                                    | fade / solid / pulse / shimmer; pulse / shimmer can use the global or svg implementation                                                                                       | fade (default) / solid / pulse / shimmer; pulse / shimmer are a pure-CSS root driver with the shimmer band throttled to 24 steps/s                                |
| Text modes                                 | round (default) / clip / underline / leaf                                                                                                                                      | round (default) / clip                                                                                                                                            |
| Marks and inference                        | Marks; `skz-auto` regions get the fallback + tiers 0 / 1 / 2, each taken as far as the browser allows                                                                          | Marks (`skz-text` / `skz-bone` / `skz-leaf` / `skz-ignore`); `skz-auto` regions add the tier 0 tag allow-list + one `@supports` modern tier                       |
| Inheritance firewall                       | Yes (`global` scheme)                                                                                                                                                          | No                                                                                                                                                                |
| svg scheme                                 | Yes (`svg` scheme, no `@property` needed)                                                                                                                                      | No                                                                                                                                                                |
| Lazy rendering (`skz-paused`) and `skz-cv` | Yes                                                                                                                                                                            | No                                                                                                                                                                |
| How to import                              | `import "skeletonizer"`                                                                                                                                                        | `import "skeletonizer/lite"`                                                                                                                                      |
| CSS                                        | `full.mjs` starts with `import "./full.css"`, so the bundler brings the styles; link `skeletonizer/full.css` yourself for SSR first paint / no bundler / CDN                   | `lite.mjs` starts with `import "./lite.css"`; link `skeletonizer/lite.css` yourself in those cases                                                                |
| Size (gzip)                                | JS 3.87 KB + CSS 2.33 KB = **6.20 KB**                                                                                                                                         | JS 2.22 KB + CSS 1.99 KB = **4.22 KB**                                                                                                                            |
| SSR                                        | The JS contains a CSS import, so it needs a bundler (see [SSR and Node](#ssr-and-node)); the global `skz` is installed on import                                               | Same                                                                                                                                                              |
| Types                                      | `EnableOptions` gains `text` / `shimmerMode` / `engine` / `fallback`, adapters follow                                                                                          | `EnableOptions` only has `effect` / `fit`, `SkzEffect` has four values                                                                                            |

How sizes are counted: the `pnpm build` output, each file compressed with `gzip -9 -n` (1 KB = 1024 bytes); every JS file is self-contained, so "JS" is just that one file. The breakdown is in [Entry points](#entry-points).

The short version: **full is the default**; if size matters most and your skeletons are small, switch to lite (`skeletonizer/lite`). Reasons to stay on full (or move to it):

- A single root grows past about 2,000 elements and you still want pulse / shimmer (lite has no inheritance firewall; on a desktop CPU it measured 60 fps up to about 4,000 elements, on slow devices far fewer; data in [the lite size limit](#the-lite-size-limit));
- Users below the browser bar must see animation too (full has the SVG fallback);
- You need underline / leaf text, or lazy rendering;
- A big skeleton without list structure (large form, long detail page) needs shimmer: the `svg` scheme.

**Do not load both** `skeletonizer` and `skeletonizer/lite` on one page: each carries its own copy of the core, so the extension registry and the global `skz` would split in two (the last one loaded wins the global `skz`).

## Quick start

### 1. Install

```bash
pnpm add skeletonizer
```

### 2. full (default): one import

```ts
import "skeletonizer"; // styles (full.css) + runtime + the global skz, all in one line
```

From then on the global `skz` is available everywhere, no import needed:

```ts
const off = skz.enable(document.querySelector("#card")!, { effect: "shimmer" });
const user = { name: skz.bone.text(8), bio: skz.bone.lines(2) };
// data arrived:
off();
```

Named imports work too and give fuller type hints (the members of `skz` are listed in [The global `skz`](#the-global-skz)):

```ts
import { enable, Bone } from "skeletonizer";
```

> `import skz from "skeletonizer"` gives you the same object as the global `skz` (same members for `skeletonizer` and `skeletonizer/lite`). It keeps working even when the global name is taken by someone else.

The full build already includes the global and svg schemes, so there is nothing else to import or pick; the schemes are chosen at runtime with the `engine` option.

**When to link `skeletonizer/full.css` yourself**: the entry ships its styles when a bundler handles it; in these cases you load them by hand:

- **SSR first paint**: write `<link rel="stylesheet" href="…/skeletonizer/full.css">` into the server-rendered HTML and put `skz` on the root; the first paint is already a skeleton, and `enable()` takes over when JS boots (idempotent). See [SSR and Node](#ssr-and-node) for running the JS on the server.
- **No bundler**: `<link>` the `full.css` and use an import map, see [No bundler](#no-bundler-use-it-straight-from-the-browser-import-map).
- **CDN**: same, with CDN URLs.

### 3. lite: the smaller build

```ts
import "skeletonizer/lite"; // styles (lite.css) + core runtime + the global skz
```

Everything in step 2 applies the same way (`skz`, named imports, `import skz from "skeletonizer/lite"`, linking `skeletonizer/lite.css` yourself). What lite does not have is listed in [Full or lite](#full-or-lite). **Do not import `skeletonizer` and `skeletonizer/lite` together.**

### 4. Turn it on

```ts
import { enable, Bone } from "skeletonizer"; // lite: "skeletonizer/lite"

const off = enable(document.querySelector("#card")!, { effect: "shimmer" });
// data arrived:
off();
```

Options of `enable()` (the "Version" column: Both = full and lite; Full only = ignored in lite if passed):

| Option     | Version   | Values                                            | Notes                                                                                                                                                                                                                                                  |
| ---------- | --------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `effect`   | Both      | `fade` (default) / `solid` / `pulse` / `shimmer`  | pulse / shimmer work out of the box in lite too (the root-driver CSS is in `lite.css`); in full their implementation can be `global` or `svg`                                                                                                          |
| `text`     | Full only | `round` (default) / `clip` / `underline` / `leaf` | how text bones are drawn, written to the root's `skz-text-mode`; see [Text bone modes](#text-bone-modes); lite has only round / clip and does not read this option (omitted = round, same as pure CSS)                                                 |
| `engine`   | Full only | `global` / `svg`                                  | implementation of `pulse` / `shimmer`; defaults to `global` (the full build registers both schemes); see the `engine` row of the [Feature reference](#feature-reference)                                                                               |
| `fallback` | Full only | `svg` (default) / `fade`                          | what the `global` scheme does on browsers without `@property`: JS attaches an SVG animation (`svg`) or keeps the base fade (`fade`); old browsers show fade until JS runs                                                                              |
| `fit`      | Both      | boolean (default `false`)                         | the skeleton never grows a scrollbar: the root is capped at the space left in its scroll ancestor (or the viewport) and list items fully outside it get `display: none`; re-measured on resize. `<skz-box fit>` / React / Vue / Svelte pass it through |

The CSS for `fit` is already part of `lite.css` / `full.css`; nothing else to import.

Calling `enable()` again is safe: attributes are re-synced, omitted options are cleared, list items / ignore regions / theme variables are re-read.

### 5. Mark the bones

Unmarked content renders as-is. Mark what should become a bone with bare attributes inside the root:

```html
<!-- the root is whatever you call enable() on / wrap with <SkzBox>; it gets `skz` -->
<div class="card">
  <img skz-bone src="…" width="48" height="48" />
  <h3><span skz-text>Name</span></h3>
  <p><span skz-text>A longer bio that wraps onto several lines.</span></p>
  <div skz-leaf class="stats"><b>128</b> posts · <b>3.2k</b> followers</div>
  <button skz-bone>Follow</button>
  <a skz-ignore href="/cancel">Cancel</a>
</div>
```

| Attribute    | Put it on                              | Effect                                                                                                                                                                                                                                                                                                                                   |
| ------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skz-text`   | a text element (inside the root)       | Its whole subtree becomes text bars that follow the real text lines (last line shorter), mixed content such as `Price: <b>$5</b>` included. **Put it on an inner `<span>`, not on the block element**: in the default `round` mode a block element becomes one whole rounded rectangle, an inline `<span>` gets one rounded bar per line |
| `skz-bone`   | an image, avatar, button, colour block | This element becomes one bone and its subtree is hidden; media content is pushed out of the box                                                                                                                                                                                                                                          |
| `skz-leaf`   | a container                            | Merges the whole subtree into one bone                                                                                                                                                                                                                                                                                                   |
| `skz-host`   | a Web Component host (Shadow DOM)      | The host is hidden and a `::before` paints one whole bone, so the shadow content stays hidden, see [Web Component hosts](#web-component-hosts)                                                                                                                                                                                           |
| `skz-ignore` | anything                               | Keep as real content, still clickable / focusable. Inside a `skz-text` / `skz-auto` region its text shows on top of the bar; to keep it clean write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`                                                                                                                 |
| `skz-auto`   | the root, or any element inside it     | Turns on tag-based inference for that subtree only, for third-party components you cannot mark (see below)                                                                                                                                                                                                                               |

For the complete attribute list (element marks, root attributes, runtime attributes the library writes) and how they behave under each text mode / entry point / animation effect / tier, see [Marks and attributes reference](#marks-and-attributes-reference).

`skz-text` / `skz-bone` / `skz-leaf` work anywhere under the root, inside or outside a `skz-auto` region; they are not read on the root itself. The look of text bars follows the root's `skz-text-mode` (the `text` option): `round` by default, see [Text bone modes](#text-bone-modes).

**`skz-auto` regions**: write the bare attribute `skz-auto` on the root or on any element inside it, and tag-based inference applies to that subtree only: text tags (`p` `span` `h1`–`h6` `a` `li` …), media and controls (`img` `video` `canvas` `svg` `input` `button` …), empty `<i>` and empty elements whose class contains `icon`. Limits: the rules work from a tag allow-list and CSS cannot select text nodes, so **bare text directly inside a `div`, a custom element or `code` is not covered (it stays invisible under round / clip)**: wrap it in `p` / `span` or mark it `skz-text`; a block-level text tag becomes one whole rounded rectangle under `round`; empty `div`s used as avatars or colour blocks are not inferred and need `skz-bone`.

### 6. Feed it mock data, render as usual

```ts
const user = loading ? { name: Bone.text(8), bio: Bone.lines(2), avatar: Bone.image(48, 48) } : data;
```

### Framework adapters

Adapters are subpath exports; the frameworks are optional peer dependencies. Adapters are thin glue (0.5–0.9 KB gzip each) and **contain no core code**: they find `enable` / `disable` through the private global key `globalThis[Symbol.for("skeletonizer")]`, which `skeletonizer` (full) or `skeletonizer/lite` installs when imported. So **import exactly one of them once at the app entry** (it also brings the styles); the adapters themselves ship no styles and install no global. If neither was imported, development builds `console.warn` once ("no implementation found") and the adapter calls do nothing. The option types of the adapters are based on `skeletonizer/lite` and widen once your project imports `skeletonizer` (see [Types](#types)), so the full-only options are type errors under lite and take effect at runtime under full.

```ts
// Vue 3: directive / component / composable / plugin
import { vSkeleton, SkzBox, useSkeleton, SkzPlugin } from "skeletonizer/vue";
// <div v-skeleton="{ loading, effect: 'shimmer' }">…</div>   or   <SkzBox :loading="loading" effect="shimmer">…</SkzBox>

// React: hook / component
import { SkzBox, useSkeleton } from "skeletonizer/react";
// <SkzBox loading={loading} effect="shimmer">…</SkzBox>

// Svelte: action
import { skeleton } from "skeletonizer/svelte";
// <div use:skeleton={{ loading, effect: 'shimmer' }}>…</div>

// Solid: directive / component (no JSX in the adapter, no compiler plugin needed)
import { skeleton, SkzBox } from "skeletonizer/solid";
// <div use:skeleton={{ loading: loading(), effect: 'shimmer' }}>…</div>   or   <SkzBox loading={loading()} effect="shimmer">…</SkzBox>
// A `use:` directive must be referenced in the file, otherwise TypeScript elides an import used only in `use:`: add `void skeleton;`

// Angular: no adapter; write a dozen-line directive that calls enable / disable, or use <skz-box>, see "Using with frameworks → Angular" below
```

### Custom element / pure HTML

```ts
import "skeletonizer"; // or "skeletonizer/lite": provides enable / disable, <skz-box> only forwards to it
import { defineSkzBox } from "skeletonizer/element"; // importing has no side effects; register explicitly
defineSkzBox();
```

```html
<skz-box loading effect="shimmer"><div class="card" skz>…</div></skz-box>
<!-- `loading` on the host is the switch; `skz` lands on its FIRST element child (the skeleton root), never on the host itself -->
<!-- SSR / no JS: write `skz` on that child yourself, e.g. <skz-box loading><div skz>…</div></skz-box>; the CSS (marks and the `skz-auto` inference) already works with no JS, and enable() is idempotent once JS boots -->
<!-- no JS: write the root attributes yourself (lite: no inert lock; full: also no firewall or runtime SVG) -->
<div skz skz-effect="shimmer">…</div>
```

`<skz-box>` lives in its own entry `skeletonizer/element` (glue only, no core code, no CSS; it finds `enable` / `disable` through the same private global key as the adapters, so import `skeletonizer` or `skeletonizer/lite` once at the app entry, otherwise development builds warn once). It only tracks its own `loading` attribute (plus `effect` / `text` / `fallback` / `engine` / `fit`); under lite, `text` / `engine` / `fallback` are ignored. It does not use a MutationObserver: if a framework replaces the first child, toggle `loading` once (off, then on) so the new child is picked up and the old one is disabled. Moving the host to another parent keeps the loading state.

### Editor hints for `skz-*` attributes

Autocomplete, value hints and doc links for the hand-written attributes (`skz`, `skz-text`, `skz-bone`, `skz-leaf`, `skz-host`, `skz-ignore`, `skz-auto`, `skz-effect`, `skz-text-mode`, `skz-shimmer-mode`, `skz-cv`):

- **WebStorm / JetBrains IDEs**: nothing to do. The package declares `"web-types": "./web-types.json"`, so the IDE picks it up once `skeletonizer` is in `node_modules`.
- **VS Code**: one line in `.vscode/settings.json`:

  ```json
  { "html.customData": ["./node_modules/skeletonizer/html-custom-data.json"] }
  ```

- **TypeScript in JSX / templates**: importing an adapter (`skeletonizer/react`, `/solid`, `/svelte`, `/vue`) is enough, no configuration. It merges the shared `SkzHtmlAttributes` type (exported from `skeletonizer/lite`) into the framework's `HTMLAttributes`, so `skz-effect="nope"` is a type error. Bare attributes are typed `""` (React and Vue; React drops an unknown attribute passed `true`) or `""` / `true` (Solid and Svelte, whose bare syntax passes `true`); `false` is not accepted because Vue and Solid would render it as `="false"`, which still matches `[skz-bone]`. In TSX, JSX does not check undeclared hyphenated attributes, so lite-only roots get no autocomplete for `skz-cv` / `skz-shimmer-mode` rather than an error.

All of it comes from one list, `src/attributes.ts`; `web-types.json` and `html-custom-data.json` are generated from it by `pnpm build` (or `pnpm gen:editor`) and committed, and a test keeps the list, the generated files, the TS types and the README tables in sync.

### SSR and Node

Since 0.3.0 every JS entry starts with a CSS import (`import "./full.css"` / `import "./lite.css"`), so **`skeletonizer` and `skeletonizer/lite` cannot be imported by plain Node without a bundler** (Node does not know `.css`). SSR frameworks run the server code through a bundler, which handles the CSS import, but many of them leave `node_modules` packages external and hand them straight to Node: tell them to bundle this one (Vite / Nuxt / SvelteKit: `ssr.noExternal: ["skeletonizer"]`; Next.js: `transpilePackages: ["skeletonizer"]`). The global `skz` is installed on the server too. Without a bundler at all, give Node a loader that turns `.css` into an empty module, or keep skeleton code out of the server bundle. The framework adapters (`skeletonizer/vue` / `/react` / `/svelte` / `/solid`) have no CSS import and import in Node fine; they only warn (development) when no implementation was imported.

### The global `skz`

Importing `skeletonizer` or `skeletonizer/lite` installs `skz` on `globalThis`, so you can use it without importing. The same API object is always installed on the private key `globalThis[Symbol.for("skeletonizer")]` as well (the adapters read it; it works even when the public name `skz` is taken by someone else):

| Member                       | Version | What it is                                                       |
| ---------------------------- | ------- | ---------------------------------------------------------------- |
| `skz.enable` / `skz.disable` | Both    | same as `enable` / `disable`                                     |
| `skz.bone`                   | Both    | the `Bone` class itself: `skz.bone.text(8)`, `skz.bone.lines(2)` |

- **Installed during SSR too**: importing in Node also writes to `globalThis`; if you don't use it there is no side effect.
- **An existing `skz` is never overwritten**: if someone else already owns the global name `skz` (not installed by us), it is left alone and development builds `console.warn` once, suggesting imports instead; one we installed ourselves is simply refreshed (several copies and hot reload do not warn). In production builds the call and its message are folded away by your bundler (see [Development warnings](#development-warnings)).
- The object is not frozen, because the full build adds properties to it; **the adapters (`/vue` `/react` `/svelte` `/solid`) do not install it**.
- Types: after importing any entry the global `skz` is typed (`SkzGlobal`); no declaration of your own needed.

### No bundler: use it straight from the browser (import map)

Without a bundler the JS entries cannot be imported directly (they start with a CSS import): link the CSS with `<link>` and give the module a copy without that line, or let your own tooling strip it. The simplest dependable way is a tiny build step; for a quick page you can fetch the file, drop the first `import "./full.css";` statement and serve it yourself. The files `exports` points at:

| Module name         | File            | Notes                                                             |
| ------------------- | --------------- | ----------------------------------------------------------------- |
| `skeletonizer`      | `dist/full.mjs` | full; starts with `import "./full.css"`; link `full.css` yourself |
| `skeletonizer/lite` | `dist/lite.mjs` | lite; starts with `import "./lite.css"`; link `lite.css` yourself |

CSS files: `dist/full.css` and `dist/lite.css`. Each `.mjs` is self-contained (no shared chunks), so one file is all you serve.

```html
<link rel="stylesheet" href="/vendor/skeletonizer/full.css" />

<script type="importmap">
  { "imports": { "skeletonizer": "/vendor/skeletonizer/full.mjs" } }
</script>

<script type="module">
  import { enable, Bone } from "skeletonizer"; // full.mjs with its first line (the CSS import) removed; importing also installs the global skz

  const off = enable(document.querySelector("#card"), { effect: "shimmer" });
  // when the data arrives: off();
</script>
```

- Put the import map before the first module script. Never import both `full.mjs` and `lite.mjs`.
- The browser would try to load `./full.css` as a module because of the first line; that is why the line has to go in this setup (a bundler turns it into a stylesheet link instead).

## Upgrading to 0.3.0

0.3.0 collapses the 37 files of `dist/` into **two self-contained builds plus the adapters**. Breaking changes (the complete record is in the [CHANGELOG](./CHANGELOG.md)):

| 0.2.x                                                                                                            | 0.3.0                                                                 |
| ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `import "skeletonizer"` (core, `core.css`)                                                                       | `import "skeletonizer/lite"` (`lite.css`)                             |
| `skeletonizer/full`, `/all`, `/global`, `/svg` (and `/all/js`, `/global/js`, `/svg/js`)                          | `import "skeletonizer"` (the new default, = old `all`)                |
| `skeletonizer/explicit`, `explicit.css`                                                                          | removed; use `skeletonizer/lite` (marks only was already the default) |
| `skeletonizer/core.css`                                                                                          | `skeletonizer/lite.css`                                               |
| `base.css`, `global.css`, `svg.css`, `all.css`, `style.css`                                                      | `skeletonizer/full.css` (= base + every variant)                      |
| `import "skeletonizer/base.css"` + `import "skeletonizer/global"` + `import { enable } from "skeletonizer/full"` | `import { enable } from "skeletonizer"`                               |

1. **The default entry is now the full build.** `import "skeletonizer"` brings the full runtime and `full.css`; the old core is `skeletonizer/lite`.
2. **All old subpaths are removed**: `./full`, `./explicit`, `./global`, `./svg`, `./all` (and their `/js` forms) and the CSS subpaths `./core.css`, `./base.css`, `./explicit.css`, `./global.css`, `./svg.css`, `./sweep.css`, `./all.css`, `./style.css`. The only CSS subpaths are `./full.css` and `./lite.css`.
3. **Every JS file is self-contained and starts with its CSS import**; the `node` condition and the pure-JS `*-js` builds are gone. Plain Node without a bundler can no longer import `skeletonizer` / `skeletonizer/lite` directly (see [SSR and Node](#ssr-and-node)).
4. **Do not import `skeletonizer` and `skeletonizer/lite` on the same page.** Each carries its own core copy.
5. **Adapters no longer bundle core.** They read the API from `globalThis[Symbol.for("skeletonizer")]`; import `skeletonizer` or `skeletonizer/lite` once at the app entry, otherwise development builds warn and the adapters do nothing. Adapter option types are based on `skeletonizer/lite` and widen when your project imports `skeletonizer`.
6. **`explicit` removed.** Marks only is the default behaviour (inference needs `skz-auto`), so `explicit.css` was a subset of `lite.css`. The lazy-rendering rules it carried only matter to the full JS, which has them.
7. **Types**: augmentation target changed from `declare module "skeletonizer"` to `declare module "skeletonizer/lite"`; code that augmented `"skeletonizer"` itself should now augment `"skeletonizer/lite"`.

## Upgrading to 0.2.0

> Entry and file names in this section are the 0.2.x ones; the mapping to today's names is in [Upgrading to 0.3.0](#upgrading-to-030).

0.2.0 changes the default from "infer bones from tags" to "you mark the bones". Breaking changes (the complete record is in the [CHANGELOG](./CHANGELOG.md)):

1. **Explicit marking is the default.** Without any marker, and outside a `skz-auto` region, content renders untouched. Put `skz-text` on text (on an inner `<span>` inside block elements), `skz-bone` on images / avatars / buttons / colour blocks, `skz-leaf` on containers to merge. For third-party markup you cannot edit, put the bare attribute `skz-auto` on the root or any element inside it: the old inference rules (tier 0, icons, controls, leaf mode) now apply to that subtree only. See [Mark the bones](#5-mark-the-bones).
2. **The root attribute `skz-text` is now `skz-text-mode`** (values `round` / `clip` / `underline` / `leaf`). The `text` option is unchanged and writes the new attribute; roots written by hand must be renamed. `skz-text` is now the element-level marker.
3. **New default text mode `round`.** Text bars become rounded background boxes (see [Text bone modes](#text-bone-modes)). For the old look write `skz-text-mode="clip"` on the root (full: `text: "clip"`). Core and `explicit.css` also understand `round` / `clip` when written by hand.
4. **`skz-has-ignore` is removed**; ignore regions work with `skz-ignore` alone, in pure CSS, and `enable()` no longer writes anything for them. The "turn off the underline of ancestors that contain an ignore region" fix is gone: inside a `skz-text` element or `skz-auto` region, an ignore region's text shows on top of the bar. For a clean ignore region write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`.
5. **`explicit.css` / `skeletonizer/explicit` now mean "no `skz-auto` inference rules"**, and they support `skz-text` (round / clip), `skz-bone`, `skz-leaf`, `skz-ignore`. `core.css` and `base.css` are the marks plus the inference gated on `skz-auto`.
6. **Browser bar**: the inference and marker rules are written with `:is()` / `:where()` (Chrome 88+ / Safari 14+ / Firefox 84+; the marker rules use `:not()` with selector lists). The CSS is lowered to exactly that line (chrome88 / firefox84 / safari14); the JS is ES2015, no polyfills.

CSS no longer depends on JS at all: with `skz` written on the root by hand, everything renders correctly (the lock, lazy pause, firewall and runtime SVG are performance / degradation paths, not part of correctness).

## Marks and attributes reference

The HTML attributes the library uses fall into three groups: **element marks** (you write them on descendants of the root), **root attributes** (written on the root, mostly by `enable()` on your behalf) and **runtime attributes** (the library writes them, do not write them by hand). Three attribute tables come first, then a few matrices show how they behave under different text modes, entry points, animation effects and browser tiers. In the tables, lite means `lite.css` plus the core JS (`skeletonizer/lite`) and full means `full.css` plus the full JS (`skeletonizer`). Every conclusion comes from the code in `src/styles/`, `src/core/` and `src/full/`.

### Element marks

Written on **descendants** of the root, all bare attributes (no value needed). The selectors are descendant selectors of the form `[skz] [skz-…]`, so writing one on the root itself does not match (`skz-auto` is the exception, it works on the root too).

| Attribute    | Put it on                                                | Value          | Purpose                                                                                                                                                                                                                                                                    | lite / full                                           |
| ------------ | -------------------------------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `skz-text`   | a text element (preferably an inner `<span>` of a block) | bare attribute | The text of its whole subtree becomes bars that follow the real text lines; on a container it covers mixed content; drawn according to the root's `skz-text-mode`; ignored on a `skz-bone` / `skz-leaf` / `skz-ignore` element itself and inside `skz-leaf` / `skz-ignore` | Both; lite has round / clip only, full has five modes |
| `skz-bone`   | any element (image, avatar, button, colour block)        | bare attribute | The element becomes one bone and its descendants get `visibility: hidden`; the real content of `img` / `video` / `canvas` is pushed out of the box; radius defaults to `--skz-radius`, an element's own `border-radius` is kept                                            | Both                                                  |
| `skz-leaf`   | a container                                              | bare attribute | Merges the whole subtree into one bone: descendants hidden, underlines in the subtree removed; drawn like `skz-bone` except that media content is not handled (use `skz-bone` on `img` etc.)                                                                               | Both                                                  |
| `skz-host`   | a Web Component host (Shadow DOM)                        | bare attribute | The host gets `visibility: hidden` and its `::before` paints one bone (same variables and animation as `skz-bone`); see [Web Component hosts](#web-component-hosts)                                                                                                        | Both                                                  |
| `skz-ignore` | any element                                              | bare attribute | Kept as-is, clickable and focusable; the `enable()` interaction lock skips branches that contain it; while the root contains one, the implicit default fade is off (needs `:has()`; an explicit `effect: "fade"` still runs)                                               | Both                                                  |
| `skz-auto`   | the root itself, or any element inside it                | bare attribute | Marks an inference region: inside it bones are inferred from a tag allow-list (text tags, media and controls, empty `<i>` and empty elements whose class contains `icon`); leaf mode inference also only works inside regions                                              | lite yes; full yes                                    |

### Root attributes

Written on the root. `skz`, `skz-effect`, `skz-text-mode`, `skz-fit` and `skz-engine` are normally written by `enable()` / the adapters from your options; writing them by hand is for plain HTML without JS.

| Attribute          | Put it on                          | Value                                                                    | Purpose                                                                                                                                                                                                                                               | lite / full                                                                   |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `skz`              | the root                           | bare attribute                                                           | Turns the skeleton on: styles, theme variables and the interaction lock hang off it. `<skz-box>` writes it on the host's first element child                                                                                                          | Both                                                                          |
| `skz-effect`       | the root                           | `fade` (default when omitted) / `solid` / `pulse` / `shimmer`            | The animation effect, matching the `effect` option; repeated `enable()` calls overwrite / clear it according to the options                                                                                                                           | Both                                                                          |
| `skz-text-mode`    | the root                           | `round` (default when omitted) / `clip` / `underline` / `leaf`           | How text bones are drawn, matching the `text` option (only the full JS writes it); a misspelled value falls back to the underline look                                                                                                                | `lite.css` only reads a hand-written `round` / `clip`; the rest are full only |
| `skz-shimmer-mode` | the root                           | `even` (default when omitted) / `fit`                                    | How the shimmer band sweeps, matching the `shimmerMode` option (written by the full JS): `even` moves all bones at the same speed in three viewport tiers, `fit` sweeps each bone inside its own box in a fixed 2s; an unknown value counts as `even` | Full only                                                                     |
| `skz-engine`       | the root                           | `svg` (the only value)                                                   | The SVG scheme's runtime images are attached; written by the library, see [Runtime attributes](#runtime-attributes-written-by-the-library-do-not-write-them)                                                                                          | Full only                                                                     |

| `skz-fit`             | the root                                                                      | Written by `enable(el, { fit: true })`; cleared when `fit` is omitted or on `disable()`                                                                                                                                                                                       | CSS fallback: `max-height: 100dvh` + `overflow: clip`, so the first frame does not overflow before the JS has measured                                                                          | Both                                                            |

| `aria-busy` / `inert` | the root / branches without ignore regions                                    | Written by `enable()` (`aria-busy="true"`, native `inert`) and cleared by `disable()`; browsers without `inert` use a `focusin` guard instead                                                                                                                                 | The interaction lock (no `skz-` prefix, listed here for completeness)                                                                                                                           | Both                                                            |

### How marks look in each text mode

The root's `skz-text-mode` decides how the text of `skz-text` and of `skz-auto` regions is drawn; `skz-bone` / `skz-leaf` / `skz-ignore` barely change with the mode.

| Target                                                                             | round (default)                                                                                              | clip                                                          | underline                                                     | leaf                                                                                                      |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `skz-text` on an inline element (`<span>`)                                         | One rounded bar per line, each wrapped line with its own corners                                             | A bar following the text lines, last line shorter, no corners | A thick underline along the text lines, real text transparent | The whole element is one bone, split into per-line fragments when it wraps                                |
| `skz-text` on a block element                                                      | One whole rounded rectangle (a short heading is stretched to full width)                                     | Same as inline: a bar following the text lines                | Same as inline: an underline along the text lines             | One whole rounded rectangle                                                                               |
| Text tags inside a `skz-auto` region                                               | Like `skz-text`: inline tags one bar per line, block tags (`p` `h1`–`h6` `li` …) one whole rounded rectangle | A bar following the text lines                                | A thick underline along the text lines                        | An element with no child elements but with text becomes one bone                                          |
| Bare text in a region outside the tag list (e.g. text written directly in a `div`) | Invisible                                                                                                    | Invisible                                                     | Underlined (all descendant text is drawn)                     | A `div` with no child elements becomes one bone; bare text mixed with elements gets no bone (transparent) |
| `skz-bone`                                                                         | One block of colour, descendants hidden; independent of the mode                                             | Same                                                          | Same                                                          | Same                                                                                                      |
| `skz-leaf`                                                                         | One block of colour, subtree hidden; independent of the mode                                                 | Same                                                          | Same                                                          | Same                                                                                                      |
| `skz-ignore`                                                                       | Kept as-is and clickable; inside `skz-text` / a region its text sits on top of the bar                       | Same                                                          | Same                                                          | Same                                                                                                      |

- The mode only applies to `skz-text` and to the text in `skz-auto` regions.
- An underline root nested inside a round / clip root does not inherit the outer round / clip variables; each draws its own way.
- Browsers without `box-decoration-break` (the `-webkit-` form included) get clip instead of round; in full, browsers without `background-clip: text` then fall back to underline (lite's bar has both, so lite has no such branch).
- Corners: round text bars always read `--skz-radius`, clip / underline have no corners; `skz-bone` / `skz-leaf` read `--skz-radius` and keep an element's own `border-radius`.
- Details and limits are in [Text bone modes](#text-bone-modes).

### How marks look under each animation effect

| Target                                                                      | fade                                                                                                             | solid              | pulse                                                                            | shimmer                                                                                                                                                                                                                |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| round / clip / leaf text bars, `skz-bone`, `skz-leaf`, tier 0 colour blocks | The whole root's opacity pulses, the bones themselves stay still                                                 | Static bone colour | Bone colour pulses between `--skz-color` and `--skz-highlight`                   | A highlight band sweeps inside each bone's own box (fixed 300px), all bones start together; cycle 2s / 2.8s / 3.6s by viewport width (`fit` mode 2s), the last 0.4s of each cycle is a rest, throttled to 24 updates/s |
| underline text                                                              | Same as above                                                                                                    | Static             | The underline / block glyph colour pulses                                        | Colour pulse (no band, throttled the same way)                                                                                                                                                                         |
| `skz-ignore`                                                                | Off by default while the root contains an ignore region (only on when written explicitly, and then it fades too) | As-is              | As-is                                                                            | As-is                                                                                                                                                                                                                  |
| List items carrying `skz-fw` (global)                                       | Not applicable                                                                                                   | Not applicable     | Bones inside stay still (colour pinned to `--skz-color`)                         | Bones inside stay still (band parked off-screen)                                                                                                                                                                       |
| svg engine                                                                  | Not applicable (the engine only handles pulse / shimmer)                                                         | Not applicable     | The shared SVG background pulses; text bars and bones move, underline stay still | The shared SVG band; text bars and bones move, underline stay still                                                                                                                                                    |
| Root outside the viewport (`skz-paused`)                                    | Stops                                                                                                            | Already still      | Stops                                                                            | Stops, the band background image is dropped                                                                                                                                                                            |

- With `prefers-reduced-motion: reduce` every animation stops and the bones stay still; there is no switch to turn that off.
- `skz-bone` / `skz-leaf` read the gradient-driven variables, so even when the root is in underline mode they still get the shimmer band; only the text pulses in colour.
- The root driver for pulse / shimmer needs `@property` (detected through the relative colour syntax): without it lite falls back to fade, and full's global switches to an SVG animation through JS (`fallback: "fade"` turns that off).
- The band throttling only applies to the root driver (lite and global); the svg engine's band speed is set by SMIL.

### Tiers and fallbacks

Tiers are picked by capability, with no UA sniffing; the column names match the demo's tier selector (tier 0 = theme, marks and fit only (no inference), 1 = + tier 0 and all effects, 2 = + tier 1, 3 = + tier 2).

| Target                      | Tier 0 (CSS variables + `:is()`)                                                              | Tier 1 (+ `text-decoration-thickness`)                                                 | Tier 2 (+ `:has()`)                                                                     |
| --------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `skz-text`                  | No rule, real text shows                                                                      | Text bars / underlines / block glyphs appear                                           | Same as tier 1                                                                          |
| `skz-bone` / `skz-leaf`     | Yes                                                                                           | Yes                                                                                    | Yes                                                                                     |
| `skz-ignore`                | Yes (backgrounds on its descendants are still cleared)                                        | Yes (same)                                                                             | Yes (leaf mode keeps backgrounds exactly)                                               |
| Inference inside `skz-auto` | Tag allow-list colour blocks, text tags as whole blocks, nested hits merge into larger blocks | Text lines become bars (round / clip / underline), controls are one block with no line | Plus leaf mode and icon detection (empty `<i>`, class containing `icon`)                |
| Animation                   | fade / solid; pulse / shimmer fall back to fade without `@property`                           | Same as tier 0                                                                         | Same as tier 0; the implicit fade is turned off when the root contains an ignore region |

- lite's modern tier is one `@supports` that needs both `text-decoration-thickness` and `:has()`, so for `skz-text` lite only has "yes / no"; in full, `skz-text` is already there at tier 1 (`text-decoration-thickness`).
- The `skz-text` rules for leaf mode have no `@supports` gate.
- Below the bar `skz-text` shows the real text instead of a bar, so keep this in mind: an explicit mark on an old browser is the same as no mark.
- Below tier 0 (no CSS variables or no `:is()`; this library's floor is Chrome 88), `skz-auto` regions simply show nothing: there is no fallback layer. It used to be a grey-block layer, but its selectors contained `:is()` too, so in practice no browser ever displayed it; see CHANGELOG 0.3.0.

## Types

`dist/*.d.mts` is the source of truth. `skeletonizer/lite` is the type base (the core types); `skeletonizer` (full) re-exports everything from it and adds the full-build API; the adapter types come from their own sub-paths and import their option types from `skeletonizer/lite`.

```ts
// lite: the core types (also the base of full)
import { enable, disable, Bone, registerExtension, ROOT_ATTR } from "skeletonizer/lite";
import type { EnableOptions, SkzEffect, SkzEffectMap, SkzExtension, SkzGlobal } from "skeletonizer/lite";

// full: everything above (re-exported) plus what it adds
import { registerEngine } from "skeletonizer";
import type { SkzTextMode, SkzShimmerMode, SkzFallback, SkzEngine, SkzEngineImpl } from "skeletonizer";

// element: the <skz-box> custom element (a separate entry, not part of lite / full)
import { defineSkzBox, SkzBox } from "skeletonizer/element";
```

### How the types widen with the version

The types of `skeletonizer/lite` only describe what lite has. The type declarations of `skeletonizer` (full) carry a `declare module "skeletonizer/lite"` augmentation: **as soon as your project pulls in the types of `skeletonizer` (that is, you import it), the types below widen automatically** (and the adapters' too, since theirs come from lite), with no change to existing code:

| Type                                       | Lite only                                   | After importing full                             |
| ------------------------------------------ | ------------------------------------------- | ------------------------------------------------ |
| `EnableOptions`                            | `effect`, `fit`                             | also `text`, `shimmerMode`, `engine`, `fallback` |
| `SkzEffect`                                | `"fade" \| "solid" \| "pulse" \| "shimmer"` | same                                             |
| `SkzGlobal` (the type of the global `skz`) | `enable` / `disable` / `bone`               | same                                             |
| Adapter props (`SkzBox` and others)        | follow `EnableOptions`                      | widen along with it                              |

The mechanism: `SkzEffect` is `keyof SkzEffectMap`, `EnableOptions` and `SkzGlobal` are interfaces, and the full build adds members through interface merging (anyone writing their own extension can add an effect name the same way, by augmenting `"skeletonizer/lite"`). So:

- With lite only, `enable(el, { text: "leaf" })`, and `{ engine: "svg" }` are **type errors** (lite ignores them at runtime too); that is deliberate: you find out at compile time that you used an option lite does not have;
- The augmentation is **project-wide**: as soon as one file imports `skeletonizer`, `EnableOptions` is wider everywhere in the project (interface merging in TypeScript is global), so in a project that mixes both the types will not stop you from passing a full-only option to lite (do not mix them on one page anyway);
- `test/types` verifies this against the build output (lite only, full, and the two in one project).

### `EnableOptions`

The options shared by `enable()`, the `<skz-box>` attributes and the three adapters; every field is optional (the "Version" column: Both = lite and full):

| Field      | Version   | Type          | Default                                          | Notes                                                                                            |
| ---------- | --------- | ------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `effect`   | Both      | `SkzEffect`   | `"fade"`                                         | Animation effect, written to the root's `skz-effect`                                             |
| `fit`      | Both      | `boolean`     | `false`                                          | The skeleton never grows a scrollbar (capped root height, off-screen list items `display: none`) |
| `text`     | Full only | `SkzTextMode` | `"round"`                                        | How text bones are drawn, written to the root's `skz-text-mode`                                  |
| `engine`   | Full only | `SkzEngine`   | `global` (the full build registers both schemes) | Implementation of `pulse` / `shimmer`, only affects those two effects                            |
| `fallback` | Full only | `SkzFallback` | `"svg"`                                          | What the `global` scheme does on browsers without `@property`                                    |

What each value means is in the options table of [Quick start](#4-turn-it-on).

### Functions and constants

```ts
// lite (skeletonizer/lite)
function enable(el: HTMLElement, opts?: EnableOptions): () => void; // returns the off function
function disable(el: HTMLElement): void;
function registerExtension(ext: SkzExtension): void; // the generic extension point, only for writing your own
const ROOT_ATTR: "skz";

// full (skeletonizer) adds
function registerEngine(impl: SkzEngineImpl): void; // where scheme implementations register; the built-in schemes call it on load, normally not by you

// element (skeletonizer/element)
function defineSkzBox(tag?: string): void; // default tag name "skz-box"; calling it twice is safe
```

- `SkzExtension`: `{ name: string; sync(el, opts): void; release(el): void }`, the generic extension point. Every `enable()` call runs each extension's `sync` in registration order, turning the skeleton off runs each `release`, and a later registration under the same name replaces the earlier one. The full version's text modes, scheme dispatch and lazy rendering are three extensions hooked in through it.
- `SkzEngineImpl`: `{ engine: SkzEngine; sync(el, opts): void; release(el): void }`, the registration through which the `global` / `svg` schemes plug into the full build's scheme dispatch (it used to be `registerExtension({ engine, … })`, renamed in 0.1.0, see the [CHANGELOG](./CHANGELOG.md)).
- `SkzGlobal`: the shape of the global `skz`; the members are listed in [The global `skz`](#the-global-skz).

## Comparison

> **Naming in the measurements**: the benchmark scripts and the numbers below were taken before 0.3.0 and are **not re-run**; "core" there is today's `skeletonizer/lite`, "full" / `global` / `all` is today's `skeletonizer` (full), `base.css` is the base inside `full.css`, and "`explicit.css`" rows measured a base that has since been merged into `lite.css` (marks only, no inference). ### The lite size limit

core has no inheritance firewall: pulse / shimmer re-calculate the style of every element under the root each frame, so the element count under one root has a ceiling. This section answers two questions: does core hold 60 fps for pulse / shimmer within about 2,000 elements, and beyond how many elements should you move to the full version.

**Test conditions** (scripts, scenarios and raw data are in `bench/2026-10-10-core/`): Chrome 154.0.8037.98, Windows 10, Intel i5-13500 + UHD 770 integrated GPU, viewport 1200×800, DPR 1; a frozen snapshot of the `pnpm build` `dist/`, served by a separate static server (not the vite dev server); the benchmark page loads `core-js.mjs` + `core.css` through an import map (full comparison: `base.css` + `global.css` + `full.mjs` + `global-js.mjs`, equivalent to `skeletonizer/global`, with the inheritance firewall); default text mode clip; each card has 8 elements (125 / 250 / 500 cards ≈ 1,000 / 2,000 / 4,000 elements); **every cell loads the page fresh**, median of 3 traces. Each cell is fps / style recalc ms / PrePaint ms / Paint ms / GPU ms / enable ms (style recalc and the others are per-frame costs; "enable" is the time of a real `enable()` call, median of 5, noisy, read it as an order of magnitude only).

**Conclusions**:

1. **Does core hold 60 fps for pulse / shimmer within about 2,000 elements? On a desktop-class CPU at normal speed: yes.** 1,000 / 2,000 elements are both 60.4 fps, and 4,000 elements give pulse 59.2 / shimmer 60.4 (repeat: 58.4 / 60), so about 2,000 elements leaves a 2× margin. **On a slow device (4× throttle): no**: 2,000 elements give pulse 21.2 / shimmer 17.2 fps, and even 504 elements give only 40.8 / 52 fps (full under the same throttle: 58.8 / 58.4 fps at 2,000 elements).
2. **Beyond how many elements should you move to full?** On a desktop-class CPU pulse starts dropping frames beyond about 4,000 elements and shimmer beyond about 6,000 (6,000 elements: pulse 46.4, shimmer 58 fps; 8,000: 39.6 / 52; 12,000: 25.6 / 24.4; 16,000: 18.4 / 16.8), so **move to full beyond about 4,000 elements**. When slow devices (mobile / low-end) matter the bar is much lower: under the 4× throttle pulse / shimmer at 504 elements already miss 60 fps (smaller sizes were not measured); either keep a single root very small, or use full, or use only fade / solid in core (core's fade / solid were not measured under the 4× throttle).
3. The boundary is set by main-thread compute: style recalc milliseconds grow linearly with the element count, and a slower CPU shifts the whole line left in proportion, so the "about 4,000 elements" above only holds for desktop CPUs like this one.
4. The full version is not unlimited either: at normal speed 16,000 elements are still 60.4 fps, but under the 4× throttle 4,000 elements drop to 47.6 (pulse) / 57.6 (shimmer) fps (the "full" rows in the table).
5. The main batch was run a second time in full (`after2`, whole-machine CPU mean 30.8%): core at 1,000 / 2,000 elements is again 60.4 fps, at 4,000 elements pulse 58.4 / shimmer 60 fps; under the 4× throttle at 2,000 elements pulse 18 / shimmer 16 fps (main batch 21.2 / 17.2); full under the 4× throttle at 2,000 elements 55.2 / 59.6 fps (main batch 58.8 / 58.4). ## Schemes in detail

### fade / solid (built into both builds)

- **fade** (default, what you get without `skz-effect`): the whole root pulses its opacity on the compositor thread, nearly free however many elements there are. With `skz-ignore` inside the root the implicit default skips fade (it would dim the ignored content); pass `effect: "fade"` to force it.
- **solid**: static, no animation.

### Root-driven pulse / shimmer and the global scheme

```ts
import "skeletonizer"; // full: the root driver is in full.css, and enable() starts the firewall / old-browser fallback; lite ("skeletonizer/lite") has the root driver too, without the firewall
enable(el, { effect: "shimmer" }); // or "pulse"
```

- **How it works** (`lite.css` and `full.css` both carry this root driver): one CSS animation on the root drives variables registered with `@property` (shimmer position, pulse colour); bones only read the inherited values and carry no animation of their own. Colours come from `--skz-color` / `--skz-highlight`, so they follow the theme exactly.
- **shimmer**: each bone slides a gradient inside its own box (`background-size: 300px 100%`, position `calc(progress * (100% + 600px) - 300px)`, the band enters from outside the bone's left edge and leaves past its right edge, wider bones move it faster so all finish together; the band width is fixed rather than a share of the bone, so small elements get a soft brighten-and-fade instead of a thin line; no `fixed` background, so iOS behaves like desktop), and a single progress variable on the root drives them all, so every bone stays in sync; round / clip mode put the band inside the text bars, while explicit underline text cannot take a gradient and uses a colour pulse instead (only these two modes get an extra pulse animation on the root; clip / leaf do not, which saves per-frame style work that would do nothing).
- **Throttling**: the band updates 24 times per second by default (the default of `--skz-shimmer-timing` follows the viewport tier: `steps(38)` over the 1.6s sweep of the 2s cycle, `steps(58)` over 2.4s, `steps(77)` over 3.2s): frames whose computed value did not change are not repainted, so GPU time for 2,000 clip cards drops from 11 ms to about 3 ms. `steps(18)` is cheaper, `linear` restores smoothness; the step count is tied to the duration (see the Feature reference) and only the root driver is throttled (lite and full's global scheme; the svg engine is not).
- **lite has no inheritance firewall**: every element under the root takes part in the per-frame style recalculation, so lite is meant for about 2,000 elements under a single root; data in [the lite size limit](#the-lite-size-limit); move bigger skeletons to the full version.
- **Inheritance firewall (automatic, the full build's `global` scheme only)**: when enabled through `enable()` / an adapter, the library looks for list items from the root down (skipping wrappers with a single child, so "root > list container > cards" hits the cards) and marks the ones outside the viewport with `skz-fw` via one shared `IntersectionObserver`. CSS pins the animated variables to static values on those items, so their descendants stop recalculating every frame. Bones in off-screen items are static and resume 200px before they scroll in; items inserted after enabling join on the next `enable()` call (until then they animate normally, they just do not save anything). **Do not make list items `display: contents`**: they stay static, see [The inheritance firewall and `display: contents`](#the-inheritance-firewall-and-display-contents).
- **Old-browser fallback (the full build's `global` scheme only; lite has none, browsers below the bar only get fade)**: without `@property`, JS attaches an SVG animation by default (generated as a blob, exact colours); `fallback: "fade"` keeps the base fade instead. Before JS runs (SSR first paint) and when blob generation fails, old browsers show fade.

### svg: shared SVG animation background

```ts
import { enable } from "skeletonizer"; // full has the svg scheme built in
enable(el, { effect: "shimmer" }); // with global also imported, write engine: "svg"
```

- **How it works** (the full build's `svg` scheme only): every bone's background carries one SMIL-animated SVG that all bones share, so CSS does not change per frame and there is no style recalculation; no `@property` needed.
- **Colours**: through `enable()` the SVG is generated at runtime from the root's `--skz-highlight` and `--skz-duration` (blob URL; the band is 60% of the image, which is stretched to each bone's own box: the SMIL animation lives inside the image, so it cannot use a fixed px width; the root driver uses a fixed 300px, so small elements look different between the two), so colour and duration match the theme; one copy is shared per parameter set, released when nobody uses it, and regenerated on a system light/dark change. Without JS, or if the theme variables cannot be read, the root gets no `skz-engine` attribute and shows the base fade (the CSS ships no built-in SVG fallback image). When enabled through `enable()` the two images are written on the root as inline variables `--skz-svg-shimmer` / `--skz-svg-pulse`; with a hand-written `skz-engine="svg"` you can supply those variables yourself (not verified).
- **Costs**: explicit underline text is coloured rather than painted with the image and stays static under the svg engine (round, clip and leaf mode have no such problem); the `--skz-shimmer-timing` throttle does not apply to it; a strict CSP must allow `img-src blob:` (the runtime image).

### Marks and `skz-auto`

Marks are the default in every base. Unmarked content renders as-is, and the bones are what you mark:

```html
<div skz>
  <img skz-bone src="..." />
  <h3><span skz-text>Title</span></h3>
  <p>This paragraph is not marked and renders as-is</p>
  <div skz-leaf>…merged into one bone…</div>
</div>
```

`skz-text` makes text bars (see [Text bone modes](#text-bone-modes)), `skz-bone` makes the element one bone, `skz-leaf` merges the subtree into one bone, `skz-ignore` keeps it as-is; descendants of a bone are hidden and media bones push their real content out of the box. Bones default to `var(--skz-radius)`, but an element that sets its own `border-radius` (a round avatar) keeps its shape.

For third-party components you cannot mark, write `skz-auto` on the root or on any element inside it: tag-based inference (tier 0, icons, controls, leaf modes) then applies to that subtree only. See [Mark the bones](#5-mark-the-bones) for its limits.

The former `explicit.css` (marks only, no `skz-auto` rules) was removed in 0.3.0: it was a subset of `lite.css`, and the default is already marks only (inference needs `skz-auto`), so `skeletonizer/lite` is the "marks, smallest rules" choice; `skz-text` in lite knows only `round` / `clip`.

### Lazy rendering and `skz-cv`

Lazy rendering (full only) only watches the root: when a huge root has just one corner in view, the whole root's animation keeps running. `skz-cv` (in `full.css`, not in `lite.css`) covers that blind spot by making the root's direct children skip rendering while outside the viewport, but stacked on `enable()` (the inheritance firewall) it does worse, so prefer the firewall when there is list structure. For the triggers, costs and numbers see the "Lazy rendering" and `skz-cv` rows of the [Feature reference](#feature-reference).

## Bone helpers

`Bone` is a plain object (not a class, `new Bone()` is not a thing) whose methods generate placeholder data. Every result is deterministic (no `Math.random`): the same input always gives the same output under SSR, so hydration is safe. They only create data, rendering stays with your real components.

### Text placeholder

```js
Bone.text(n, { seed });
```

Generates placeholder text of n characters, words separated by spaces, wrapping naturally. `seed` changes the word-length distribution (default 0).

```js
Bone.text(12); // "███ ████ ███" (word lengths illustrative)
Bone.text(30, { seed: 1 }); // the same seed always gives the same distribution
```

### Paragraph placeholder

```js
Bone.lines(k, { perLine, seed });
```

Generates a placeholder paragraph of about k lines. `perLine` is the estimated characters per line (default 40).

```js
Bone.lines(3); // 120 characters (3 × 40) of placeholder text
Bone.lines(3, { perLine: 30 }); // 90 characters
```

### CJK text placeholder

```js
Bone.cjk(n, { seed });
```

Generates a CJK placeholder string: pure blocks with a zero-width space every 3–6 characters for line breaks.

```js
Bone.cjk(20); // 20 blocks with sensible break points
```

### Number placeholder

```js
Bone.number(digits);
```

Generates a fixed-width digit placeholder (full-width blocks).

```js
Bone.number(4); // "████" (4 digits)
Bone.number(); // "███" (3 digits by default)
```

### Image placeholder

`Bone.image(w?, h?)` has three shapes depending on the arguments:

```js
Bone.image(); // no args: base64 data URI of a 1×1 transparent GIF, best compatibility
Bone.image(48); // w only: h defaults to w, a 48×48 square transparent SVG
Bone.image(160, 100); // w and h: a 160×100 transparent SVG with an intrinsic aspect ratio
```

- **No arguments**: a GIF has no intrinsic size, so give it `width` / `height` attributes or CSS, otherwise it collapses to 1px:
  `<img :src="Bone.image()" width="160" height="100" />`
- **With a size**: the SVG carries its aspect ratio and causes little layout shift; `Bone.image(48)` is the handiest for avatars and icons.
- Invalid arguments (0, negative) fall back to the 1px GIF.

**Note:** if a strict CSP does not allow `img-src data:`, use a self-hosted transparent image.

## Theming

### Text bone modes

Set on the root: `enable(el, { text })` (full) or `skz-text-mode="…"` written by hand. lite only knows **round** and **clip** (a hand-written `skz-text-mode="round"` / `"clip"` works there too); the other three modes and the `text` option are **full only**. The modes apply to `skz-text` elements and to text inside `skz-auto` regions.

- **`round`** (default: what you get when `text` / `skz-text-mode` is omitted; needs `box-decoration-break`): the text goes transparent and the element gets a rounded background box. An inline element wraps into **one rounded bar per line**; a block element (`p` / `h3` / `div` / a flex item) is drawn as **one whole rounded rectangle**, whatever its length. So **put `skz-text` on an inner `<span>`** inside block elements. The bars take the shimmer band (`clone`: after wrapping each line fragment sweeps in its own box, in sync), the firewall, the dark theme and `--skz-radius` like any other bone. GPU is about half of clip (prototype measurement), and it does not depend on decorations taking part in `background-clip: text`, which was only verified in Chrome. Browsers without `box-decoration-break` (the `-webkit-` spelling is checked too) automatically fall back to clip; write `skz-text-mode="clip"` to choose clip explicitly. Known limits: (1) under Microsoft YaHei / Segoe UI / system-ui the bar is about 0.1–0.16em taller than clip's (the bar height is the font's content area; Arial / Georgia / Consolas / SimSun / Times match clip pixel for pixel); (2) with `line-height: 1.2` multi-line bars can overlap and leave notches (YaHei bar height 1.32em, overlap 0.12em); (3) a block-level target is one whole rectangle (a long paragraph is one big block, a short heading is stretched to the full row) and there is no pure-CSS fix: wrap an inline `<span skz-text>` inside, or choose `clip`; (4) the corner radius is fixed at `--skz-radius` (default 4px) and does not scale with the font size; (5) verified in Chrome 154 only, Firefox / Safari untested.
- **`clip`** (explicit `text: "clip"` / `skz-text-mode="clip"`; needs `background-clip: text`): the shape is one thick underline following the real text lines (shorter last line; mixed text such as `Price: <b>$5</b>` is covered too), the fill is the background gradient, so the text bars get a real shimmer band and move under the svg engine as well. It works by making the text and its decoration transparent while the decoration still takes part in `background-clip: text`, which clips the background into a 1.22em thick underline. Pixel for pixel what 0.1.x drew by default. Costs: more expensive than `underline` and `round` (numbers in [Comparison](#comparison)); the spec requires decorations to take part in the clip but it is **verified only in Chrome, Firefox / Safari untested (a known risk)**; in full, browsers without `background-clip: text` drop the clip rules via `@supports not` and fall back to `underline`; inside a `skz-auto` region, bare text outside the text-tag list (e.g. text directly in a div) gets no bone.
- **`underline`** (full only; explicit `text: "underline"` / `skz-text-mode="underline"`; needs `text-decoration-thickness`): one thick underline under the real text, following the real text lines with the last line naturally shorter; mixed text is covered too. **The cheapest**; the cost is no gradient: under shimmer the text uses a colour pulse (static under svg). Use it on low-end devices or when you want the lowest cost.
- **`leaf`** (full only; needs `:has()`): a `skz-text` element becomes one whole bone like `skz-bone`; inside a `skz-auto` region an element with no child elements but some text becomes one whole bone that can shimmer and has rounded corners. The cost is that multi-line block text becomes one rectangle, and bare text nodes in mixed content get no bone.

```html
<div skz skz-text-mode="leaf">...</div>
```

### Custom colours, radius, duration

Theme variables are declared on the root itself, so set them **on the root element** (inline `style` or a selector that hits the root); setting them on `:root` has no effect:

```css
[skz] {
  --skz-color: #e0e0e0; /* bone colour (default #d9dde3, dark #374151) */
  --skz-highlight: #f0f0f0; /* highlight: shimmer band, pulse peak (default #eceff3, dark #4b5563) */
  --skz-radius: 6px; /* bone radius (default 4px) */
  --skz-duration: 1.2s; /* animation duration (unset: pulse and shimmer are 2s; when set, they use it) */
  --skz-ul-thickness: 1em; /* underline thickness */
  --skz-ul-offset: -0.85em; /* underline offset */
}
```

Dark mode switching (`prefers-color-scheme` / `data-skz-theme`), the fit variables, reduced motion and the rest are in the "Theme variables" and "Automatic behaviour" rows of the [Feature reference](#feature-reference).

## Browser support and fallbacks

Styles come in progressive tiers and each browser takes what it can; no UA sniffing:

| Browser capability                                    | What you get                                                                                                                                                                                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CSS variables                                         | Tier 0: tag-whitelist bones (`skz-auto` regions), the `skz-bone` / `skz-leaf` / `skz-ignore` marks, fade / solid, the svg scheme; lite also stays at this tier below its bar (static blocks + marks + fade)                         |
| `text-decoration-thickness`                           | Tier 1: `skz-text` bars and underline text bones (full; lite needs it together with `:has()` before it turns on the modern tier)                                                                                                    |
| `background-clip: text`                               | Fill of the clip text mode (and the fallback of round); in full, without it the clip rules are dropped via `@supports not` and text falls back to underline (decoration-in-clip verified only in Chrome; Firefox / Safari untested) |
| `:has()`                                              | Tier 2: leaf mode, icon detection (full; same for lite), and turning off the implicit fade when the root holds an ignore region                                                                                                     |
| `@property` (detected through relative colour syntax) | root-driven pulse / shimmer (in lite and full); without it lite falls back to fade and full's global scheme falls back to an SVG animation by default                                                                               |
| `box-decoration-break` (also the `-webkit-` spelling) | Round text bars (the default); without it text bars fall back to clip                                                                                                                                                               |
| `:is()` / `:where()`                                  | The `skz-auto` inference and the marker rules are written with them (Chrome 88+ / Safari 14+ / Firefox 84+); without `:where()` bones also lose the default radius (it yields to the element's own `border-radius`)                 |
| `IntersectionObserver`                                | Lazy rendering and the inheritance firewall (full only; lite does not use it); skipped without it (still animated, just not optimised)                                                                                              |

**The lite bar**: the target line is Chrome 119+ / Safari 16.4+ / Firefox 128+ (all the capabilities in the table above are present on that line). Browsers below it step down according to what is missing: without `text-decoration-thickness` or `:has()`, lite gets tier 0 static blocks (`skz-auto` regions), the `skz-bone` / `skz-leaf` marks and fade, but no `skz-text` bars; without `@property` / relative colour syntax, pulse / shimmer fall back to fade (lite has no SVG fallback). To give those browsers animation or finer inference, use the full version.

**Verification status**: lite and full were both tested in Chrome only; Firefox / Safari are expected to work per the specs but were not tested. Everything was verified on desktop Chrome; Safari, Firefox, iOS, Android WebView and old browsers are **untested**, and the fallback paths were only simulated in Chrome by forcing the detection to fail.

## Known limitations and constraints

### Limits of lite

- **Size**: lite has no inheritance firewall, so pulse / shimmer re-calculate the style of every element under the root each frame; up to about 2,000 elements under one root it runs at 60 fps in desktop Chrome at normal speed, beyond that or on a slow CPU (4× throttle) it drops frames; the numbers and the advice are in [the lite size limit](#the-lite-size-limit).
- **Browser bar**: the target line is Chrome 119+ / Safari 16.4+ / Firefox 128+; below it, a missing `text-decoration-thickness` or `:has()` leaves tier 0 static blocks (`skz-auto` regions), the `skz-bone` / `skz-leaf` marks and fade (no `skz-text` bars), a missing `@property` / relative colour syntax makes pulse / shimmer fall back to fade, with **no SVG fallback**. **Tested in Chrome only**; Firefox / Safari are expected to work per the specs but were not tested (the decoration-in-clip behaviour above all).
- **Text**: round (default) and clip only. Inside a `skz-auto` region, text written directly inside a div gets no bone (invisible): put it in `p` / `span`, mark it `skz-text`, or use the full build's `text: "underline"`. lite's rules only match roots with no `skz-text-mode`, or `round` / `clip`; a hand-written `underline` / `leaf` has no matching rules in lite.
- **What it does not have**: inheritance firewall, svg scheme, underline / leaf modes, lazy rendering (`skz-paused`), `skz-cv`; use the full version for those, see [Full or lite](#full-or-lite).
- **Types**: with lite only, `text` / `engine` / `fallback` are type errors, see [How the types widen with the version](#how-the-types-widen-with-the-version).

### Development warnings

In development builds (`process.env.NODE_ENV` not `production`) these two misuses `console.warn` once each (one message per case); in production builds they are gone: each call site is wrapped in a guard `try { if (process.env.NODE_ENV !== "production") … } catch {}`, and `process.env.NODE_ENV` stays verbatim in the output for your bundler to replace in its own mode, so after replacement plus minification the call and the message text are removed (the tests check this against a production vite build). Loaded straight in a browser (no `process`) the guard is false and it stays silent.

- **The global `skz` is taken**: someone else already owns the global name `skz`; we do not overwrite it and suggest using imports instead.
- **`engine` misconfiguration** (only when assembling from the source modules): naming a scheme that is not registered, either only `global` loaded with `engine: "svg"` or only `svg` loaded with `engine: "global"`, points to `registerEngine` (or to using the full build, which registers both).

### The inheritance firewall and `display: contents`

This is a known defect and is not fixed for now. It only affects the full build's `global` scheme (lite has no firewall).

The firewall first marks every list item it finds under the root with `skz-fw`, then an `IntersectionObserver` removes the mark once an item enters the viewport. An element with `display: contents` has no box, so the observer always reports it as outside the viewport and its `skz-fw` is never removed: **even inside the viewport, its pulse / shimmer stays static, and so do its descendants**. `fit` uses the same list items and cannot measure such an item either, so it is not hidden as expected.

```html
<!-- ❌ the list items themselves are display: contents: they never animate -->
<div skz>
  <div style="display:contents"><p skz-text>…</p></div>
  <div style="display:contents"><p skz-text>…</p></div>
</div>

<!-- ✅ use list items that have a box (display: contents further inside the item is fine) -->
<div skz>
  <div><p skz-text>…</p></div>
  <div><p skz-text>…</p></div>
</div>
```

Watch out for box-less wrappers that frameworks tend to add (for example a component root wrapping each item in `display: contents`): either give it a box, or keep that root off the `global` scheme with `engine: "svg"`, or accept lite's scale limit without a firewall.

### Colours and backgrounds in `skz-ignore` regions

Text is hidden with `-webkit-text-fill-color` and `color` is left alone, so the text colour of `skz-ignore` regions and their descendants stays as-is at every tier. Remaining points:

- Backgrounds on descendants of an ignore region are still cleared in Tier 0 and 1; Tier 2's leaf background mode preserves them exactly.
- Borders / outlines / box-shadows on containers inside the skeleton that rely on `currentColor` will show; give them explicit colours, or handle them separately in the skeleton state.
- Inside a `skz-text` element or a `skz-auto` region the text of an ignore region shows on top of the bar (real text colour over the grey bar); the old "turn off the underline of ancestors that contain an ignore region" fix was removed together with `skz-has-ignore`. For a clean ignore region write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`.

### Web Component hosts

Write the `skz-host` marker on the host element (Shadow DOM). The rule is static CSS in both `lite.css` and `full.css`: the host gets `visibility: hidden` (it inherits into the shadow tree, so the inside is hidden too) and a `::before` bone painted like any other bone, reading the inherited `--skz-fill` / `--skz-bg-img` / `--skz-bg-pos`, so pulse / shimmer, the `global` throttle, the `svg` engine and the firewall all apply to hosts:

```html
<div skz>
  <my-card skz-host></my-card>
</div>
```

The host's own background colour is hidden by `visibility` as well. Hosts inside a `skz-ignore` element are not touched. Styles inside a shadow root are your own to import (the page stylesheet does not reach into it); the host rule lives outside, so it works as is.

### `inert` support

`enable()` locks interaction with native `inert` by default. With `skz-ignore` inside the root it does not lock the whole root, only the branches that contain no ignore region, so ignore regions stay clickable and focusable (if the ignore regions change after enabling, call `enable()` again to re-lock). Browsers without `inert` fall back to CSS `pointer-events:none` plus a `focusin` interceptor (ignore regions are let through too), but that branch has not been verified on real devices.

### Text modes and shimmer throttling

Constraints only; the mechanics and numbers are behind the links.

- **round (default)**:
  - a block element carrying `skz-text` is one whole rounded rectangle (short headings are stretched to the full row): put `skz-text` on an inner `<span>`;
  - under Microsoft YaHei / Segoe UI / system-ui the bars are about 0.1–0.16em taller than clip's, and with `line-height: 1.2` multi-line bars can overlap into notches; the corner radius is fixed at `--skz-radius`;
  - browsers without `box-decoration-break` fall back to clip; verified in Chrome 154 only;
  - see [Text bone modes](#text-bone-modes).
- **clip** (`skz-text-mode="clip"`):
  - inside a `skz-auto` region, bare text written directly in a div gets no bone (invisible); put the text in `p` / `span`, mark it `skz-text`, or use `text: "underline"`;
  - decorations taking part in `background-clip: text` is **verified only in Chrome, Firefox / Safari untested** (a known risk that `@supports` cannot detect);
  - multi-line clip: an inline `skz-text` wraps with `box-decoration-break: slice`, which would lay the lines out as one joined strip (the band sweeping line 1 and then line 2). So in clip mode the direct parent of a `skz-text` takes over the background (painted on the parent with `background-clip: text`), and all lines sweep together. The cost: that parent's own background is covered, and unmarked text inside it is unaffected (it stays opaque). A `skz-text` placed directly under the root, or whose parent is an inline element, still wraps line by line (the root is never taken over; an inline parent wraps the same way); round (`clone`) is not affected;
  - browsers without `background-clip: text` drop the clip rules via `@supports not` and fall back to the underline look (static grey, no band);
  - see [Text bone modes](#text-bone-modes).
- **Shimmer throttling** (`--skz-shimmer-timing`):
  - under a 4× CPU throttle the default gains nothing (measured with `steps(36)`; the small-tier default is now `steps(38)`) (clip 18.4 fps, level with 18.0 before landing); set `steps(18)` (clip reaches 40 fps; underline stay at 14–15 fps);
  - it only affects the root driver (lite and full's global); the svg engine's band is not throttled by this variable;
  - by default 24 updates/s (`steps(38)` / `steps(58)` / `steps(77)` for the three viewport tiers; 24/s = sweep seconds × 24, with sweep seconds = total × the tier's share since the band rests 0.4s at the end of each cycle); when you set `--skz-duration` yourself, change the step count to match;
  - see the `--skz-shimmer-timing` row of the [Feature reference](#feature-reference) and the post-landing re-test in [Comparison](#comparison).

### Buttons and form controls

- Inside a `skz-auto` region, `button` is a control and becomes **one whole bone** (outside one, write `skz-bone` on the button yourself): its background turns into the bone colour and its inner `span` / icons / text are all hidden, so no small bones are stacked on the button block.
- Radius: a `border-radius` the button sets itself is kept; otherwise `--skz-radius` applies.
- `input` / `textarea` / `select` are controls too: one whole bone each, no underline.
- A button inside a `skz-ignore` region is not turned into a bone and its content is visible again, but the button's own background is cleared to transparent (backgrounds on descendants of an ignore region are still cleared, see [Colours and backgrounds in `skz-ignore` regions](#colours-and-backgrounds-in-skz-ignore-regions)); to keep a button exactly as-is and clickable (e.g. "cancel loading"), put `skz-ignore` on the button itself (verified in Chrome 154).
- Without `skz-auto` none of these inference rules apply: a button is only a bone when it carries `skz-bone`.

## Using with frameworks

skeletonizer is plain ESM plus a standard custom element. Vue / React / Svelte also have ready-made adapters (see "Framework adapters" above, sub-paths such as `skeletonizer/vue`); the snippets below integrate without an adapter.

Either way, import `skeletonizer` (full) or `skeletonizer/lite` once at the app entry: it brings the styles and installs the implementation the adapters read (see [Framework adapters](#framework-adapters)); the adapters and direct `enable()` calls then share that one core.

### Vue 3

Use `isCustomElement` so Vue leaves the `skz-box` tag alone (the adapter's `<SkzBox>` component does not need this step):

```js
// vite.config.js
export default {
  plugins: [
    vue({
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag === "skz-box",
        },
      },
    }),
  ],
};
```

Use it directly in a template:

```vue
<template>
  <skz-box :loading="isLoading" effect="pulse">
    <div class="card">
      <h3>
        <span skz-text>{{ user.name }}</span>
      </h3>
      <p>
        <span skz-text>{{ user.bio }}</span>
      </p>
    </div>
  </skz-box>
</template>

<script setup>
import { ref, onMounted } from "vue";
import { Bone } from "skeletonizer";
import { defineSkzBox } from "skeletonizer/element";

defineSkzBox();

const isLoading = ref(true);
// while loading, use mock data from Bone: empty text has no size and produces no bone
const user = ref({ name: Bone.text(8), bio: Bone.lines(2) });

onMounted(async () => {
  const data = await fetchUser(); // replace fetchUser with your own request function
  user.value = data;
  isLoading.value = false;
});
</script>
```

### React 18+

React 18 passes attributes to custom elements as strings natively, so use it directly:

```jsx
import "skeletonizer";
import { defineSkzBox } from "skeletonizer/element";

defineSkzBox();

// while isLoading is true, pass mock data from Bone as `user` (e.g. { name: Bone.text(8), bio: Bone.lines(2) })
export function CardSkeleton({ isLoading, user }) {
  return (
    <skz-box loading={isLoading} effect="pulse">
      <div className="card">
        <h3>
          <span skz-text="">{user.name}</span>
        </h3>
        <p>
          <span skz-text="">{user.bio}</span>
        </p>
      </div>
    </skz-box>
  );
}
```

On React 17, or when you need finer control, use `enable()` / `disable()`:

```jsx
import { useEffect, useRef } from "react";
import { enable, disable } from "skeletonizer";

// while isLoading is true, pass mock data from Bone as `user`
export function CardSkeleton({ isLoading, user }) {
  const ref = useRef(null);

  useEffect(() => {
    if (isLoading) {
      const off = enable(ref.current, { effect: "pulse" });
      return () => off();
    } else {
      disable(ref.current);
    }
  }, [isLoading]);

  return (
    <div ref={ref}>
      <div className="card">
        <h3>
          <span skz-text="">{user.name}</span>
        </h3>
        <p>
          <span skz-text="">{user.bio}</span>
        </p>
      </div>
    </div>
  );
}
```

### Solid

Directive (the adapter has no JSX; your own app compiles `use:` with the usual `babel-preset-solid` / `vite-plugin-solid`):

```tsx
import { createSignal } from "solid-js";
import "skeletonizer";
import { skeleton } from "skeletonizer/solid";

// TypeScript elides an import that only a `use:` directive references: keep one real reference
void skeleton;

function UserCard() {
  const [loading, setLoading] = createSignal(true);
  return (
    <div use:skeleton={{ loading: loading(), effect: "pulse" }}>
      <div class="card">{/* content: mark text with <span skz-text>, images with skz-bone */}</div>
    </div>
  );
}
```

Or the component: `<SkzBox loading={loading()} effect="pulse" as="section" class="box">…</SkzBox>`. `solid-js` is an optional peer dependency (`>=1.6.0`).

### Angular

There is no dedicated adapter: an Angular library has to go through the Angular compiler (ng-packagr) into the partial Ivy format to work in AOT builds, and a whole build toolchain is not worth it for a directive of a dozen lines. Pick either of these.

**Write a directive** (copy it into your project; it calls `enable` / `disable` directly):

```ts
import { Directive, ElementRef, Input, OnChanges, OnDestroy, inject } from "@angular/core";
import { enable, disable, type EnableOptions } from "skeletonizer"; // or "skeletonizer/lite"

/** Toggles the skeleton with loading: <div [skzSkeleton]="loading" [skzOptions]="{ effect: 'shimmer' }"> */
@Directive({ selector: "[skzSkeleton]", standalone: true })
export class SkzSkeletonDirective implements OnChanges, OnDestroy {
  /** Whether it is loading */
  @Input("skzSkeleton") loading = false;
  /** Skeleton options, same as enable() */
  @Input() skzOptions: EnableOptions = {};
  private readonly el = inject<ElementRef<HTMLElement>>(ElementRef).nativeElement;

  ngOnChanges(): void {
    // enable() is idempotent; calling it again applies the new options
    if (this.loading) enable(this.el, this.skzOptions);
    else disable(this.el);
  }

  ngOnDestroy(): void {
    disable(this.el);
  }
}
```

**Or use `<skz-box>`**: call `defineSkzBox()` at the app entry (see the `<skz-box>` section above), declare `schemas: [CUSTOM_ELEMENTS_SCHEMA]` in the component, then write `<skz-box [loading]="loading" effect="shimmer"><div class="card">…</div></skz-box>` (`[loading]` binds the element's `loading` property).
