# skeletonizer

**Live demo: <https://icodejoo.github.io/codejoo/skeletonizer/>** (switch effects, tiers, dark mode, fit and more)

Skeleton screens for the web, Flutter-`skeletonizer` style: render your **real DOM** with **mock data**, mark which elements are bones (`skz-text` / `skz-bone` / `skz-leaf`), and let **pure CSS** paint them. No hand-drawn placeholder shapes to maintain.

> 中文文档（更详细）：[README.zh-CN.md](./README.zh-CN.md)
>
> Coding agents: read [llms.md](./llms.md) for the condensed usage guide (also shipped in the npm package); see [AI coding agents](#ai-coding-agents) to wire it in.

The package has two ways to use it, **side by side**; pick by scenario:

- **core (default)**: `import "skeletonizer"` and you are done (styles + runtime + the global `skz`). Smallest, simplest rules. For small to medium skeletons in modern browsers (up to about 2,000 elements under a single root).
- **Full**: `import "skeletonizer/full"` plus the CSS and variants you opt into. Inheritance firewall (long lists), the SVG scheme and old-browser fallback, more text modes, sweep, lazy rendering and more; a much higher size limit (inheritance firewall), at the price of a larger bundle and more setup.

How to choose is in [the comparison table below](#core-or-full).

Bones are **marked by you** (the default since 0.2.0): unmarked content renders as-is. For third-party components whose markup you cannot edit, an opt-in `skz-auto` region falls back to tag-based inference. Upgrading from 0.1.x: see [Upgrading to 0.2.0](#upgrading-to-020).

## How it works

Three parts:

1. **Real DOM rendering**: write components in your usual JSX / Vue templates, just feed them mock data instead of real data.
2. **Mock data**: use `Bone` helpers to generate text, images and other placeholders; all deterministic (SSR friendly, no `Math.random`).
3. **You mark the bones, CSS paints them**: the bare attributes `skz-text` (text), `skz-bone` (images, avatars, buttons, colour blocks), `skz-leaf` (merge a subtree into one bone) and `skz-ignore` (keep as-is) say what becomes a bone; unmarked content renders untouched. Third-party components you cannot mark go inside a `skz-auto` region, where tag names and content are used to infer bones (see [Mark the bones](#5-mark-the-bones)).

The skeleton styles are pure CSS, with no UA sniffing and no JS gate: **the CSS works without any JS, the only switch is the `skz` attribute on the root** (JS only toggles it and writes the root attributes). The two ways degrade differently:

- **core**: the target line is Chrome 119+ / Safari 16.4+ / Firefox 128+ (all of `@property`, relative colour syntax, `:has()`, `text-decoration-thickness` and `background-clip: text`). Browsers above the line get the "modern tier" (one `@supports`: `skz-text` bars in round / clip style, plus controls as one block, icon detection and the other inference inside `skz-auto` regions), and `pulse` / `shimmer` are driven by one CSS animation on the root. **Browsers below the line get tier 0 (static blocks per tag, `skz-auto` regions only), the `skz-bone` / `skz-leaf` marks and fade; `skz-text` bars need the modern tier**; there is no step-by-step progression.
- **Full**: four progressive layers (fallback → tier 0 → tier 1 → tier 2), from the oldest browsers to the newest, plus an SVG animation fallback for old browsers. The fallback layer and the tiers' inference only apply inside `skz-auto` regions; the `skz-text` marker is served by tiers 1 / 2.

## Core or full

| Aspect                                     | **core (default)**                                                                                                                                                | **Full**                                                                                                                                                                       |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Good for                                   | Small to medium skeletons in modern browsers: cards, detail pages, lists of a few dozen rows; "one import, smallest bundle"                                       | Long lists / feeds / big forms; animations on old browsers; several text modes, sweep, lazy rendering; fine performance tuning                                                 |
| Browser bar                                | Chrome 119+ / Safari 16.4+ / Firefox 128+; below it: tier 0 static blocks (`skz-auto` regions), `skz-bone` / `skz-leaf` marks, fade; `skz-text` bars need the bar | Same line for the full effect set; below it a fallback layer (no CSS variables), tiers 1 / 2, and pulse / shimmer fall back to SVG animation on old browsers                   |
| Verification                               | **Chrome only**; Firefox / Safari are expected to work per the specs but were not tested                                                                          | Same                                                                                                                                                                           |
| Size guidance                              | Up to about 2,000 elements under a single root (data in [the core size limit](#the-core-size-limit))                                                              | A much higher limit: with the inheritance firewall 2,000 cards (16,000 elements) still run at 60 fps at normal speed; under a 4× throttle 4,000 elements drop to 47.6–57.6 fps |
| Effects                                    | fade (default) / solid / pulse / shimmer; pulse / shimmer are a pure-CSS root driver with the shimmer band throttled to 24 steps/s                                | Plus sweep; pulse / shimmer can use the global or svg implementation                                                                                                           |
| Text modes                                 | round (default) / clip                                                                                                                                            | round (default) / clip / underline / leaf / tofu                                                                                                                               |
| Marks and inference                        | Marks (`skz-text` / `skz-bone` / `skz-leaf` / `skz-ignore`); `skz-auto` regions add the tier 0 tag allow-list + one `@supports` modern tier                       | Marks; `skz-auto` regions get the fallback + tiers 0 / 1 / 2, each taken as far as the browser allows                                                                          |
| Inheritance firewall                       | No                                                                                                                                                                | Yes (`global` variant)                                                                                                                                                         |
| svg scheme                                 | No                                                                                                                                                                | Yes (`svg` variant, no `@property` needed)                                                                                                                                     |
| sweep                                      | No                                                                                                                                                                | Yes (`sweep.css`)                                                                                                                                                              |
| tofu                                       | No                                                                                                                                                                | Yes (`tofu.css`)                                                                                                                                                               |
| Lazy rendering (`skz-paused`) and `skz-cv` | No (not in `core.css`); only with the `explicit` base (`explicit.css`) + full JS                                                                                  | Yes (in `base.css` / `explicit.css`)                                                                                                                                           |
| `registerCustomElements`                   | No                                                                                                                                                                | Yes                                                                                                                                                                            |
| How to import                              | `import "skeletonizer"` (marks only, no inference rules: `skeletonizer/explicit`)                                                                                 | `import "skeletonizer/full"` and add styles; or `skeletonizer/global`, `/svg`, `/all` (styles + the matching variant included)                                                 |
| CSS                                        | `core.css` ships with it; link `skeletonizer/core.css` yourself for SSR first paint / no bundler / CDN                                                            | Pick: `base.css` (or `explicit.css`) + `global.css` / `svg.css` / `sweep.css` / `tofu.css`, or `all.css`                                                                       |
| Size (gzip)                                | JS 3.10 KB + CSS 1.64 KB = **4.74 KB**                                                                                                                            | `full` + `base.css` 6.55 KB; with the global scheme 8.34 KB; `all` 10.44 KB                                                                                                    |
| SSR                                        | The `node` condition gives pure JS without CSS, importing never throws; the global `skz` is also installed during SSR                                             | `skeletonizer/full` is plain JS and safe; the CSS-bundling `/global` `/svg` `/all` need a bundler, use their `/js` builds in Node                                              |
| Types                                      | `EnableOptions` only has `effect` / `fit`, `SkzEffect` has four values                                                                                            | After importing it, `EnableOptions` gains `text` / `engine` / `fallback`, `SkzEffect` gains `sweep`, and the global `skz` gains `registerCustomElements`                       |

How sizes are counted: the `pnpm build` output, each file compressed with `gzip -9 -n` and summed (the entry plus the shared chunks it depends on; 1 KB = 1024 bytes). The breakdown is in [Entry points](#entry-points).

The short version: **start with core**, and move to full when any of these apply:

- A single root grows past about 2,000 elements and you still want pulse / shimmer (core has no inheritance firewall; on a desktop CPU it measured 60 fps up to about 4,000 elements, on slow devices far fewer; data in [the core size limit](#the-core-size-limit));
- Users below the browser bar must see animation too (full has the SVG fallback);
- You need underline / leaf / tofu text, sweep, lazy rendering or `registerCustomElements`;
- A big skeleton without list structure (large form, long detail page) needs shimmer: the full `svg` scheme.

**Do not load both** (above all, do not import the `skeletonizer` default entry in a full-version project); the reason is in [Migrating from the old layout](#migrating-from-the-old-layout).

## Quick start

### 1. Install

```bash
pnpm add skeletonizer
```

### 2. core (default): one import

```ts
import "skeletonizer"; // styles (core.css) + runtime + the global skz, all in one line
```

From then on the global `skz` is available everywhere, no import needed:

```ts
const off = skz.enable(document.querySelector("#card")!, { effect: "shimmer" });
const user = { name: skz.bone.text(8), bio: skz.bone.lines(2) };
// data arrived:
off();
```

Named imports work too and give fuller type hints (the members of `skz` are listed in [The global `skz`](#the-global-skz)):

```ts
import { enable, Bone } from "skeletonizer";
```

> `import skz from "skeletonizer"` gives you the same object as the global `skz` (`skeletonizer/explicit` and `skeletonizer/full` too; the full one also has `registerCustomElements`). It keeps working even when the global name is taken by someone else.

If you never use `skz-auto` regions, `import "skeletonizer/explicit"` is a smaller core (no inference rules; `skz-text` / `skz-bone` / `skz-leaf` / `skz-ignore` work the same); everything else is the same.

**When to link `skeletonizer/core.css` yourself**: the root entry ships its styles when a bundler handles it; in these cases you load them by hand:

- **SSR first paint**: write `<link rel="stylesheet" href="…/skeletonizer/core.css">` into the server-rendered HTML and put `skz` on the root; the first paint is already a skeleton, and `enable()` takes over when JS boots (idempotent). In Node, `import "skeletonizer"` resolves through the `node` condition to the pure-JS build without CSS and does not throw.
- **No bundler**: `<link>` the `core.css`, map `skeletonizer` to `dist/core-js.mjs` with an import map, see [No bundler](#no-bundler-use-it-straight-from-the-browser-import-map).
- **CDN**: same, with CDN URLs.
- **With a framework adapter**: adapters ship no styles and install no global, so load the styles once yourself (`import "skeletonizer/core.css"`).

### 3. Full: `skeletonizer/full` + styles + variants

```ts
import "skeletonizer/base.css"; // base: theme, interaction lock, marks, four-tier `skz-auto` inference, fade / solid, lazy pause
import "skeletonizer/global"; // variant: inheritance firewall + old-browser SVG fallback for pulse / shimmer, ships global.css
import { enable, Bone } from "skeletonizer/full"; // runtime: core + the full-version extensions, no CSS
```

- The full runtime API (`enable` / `Bone` / `registerCustomElements` / `registerEngine` …) is imported from **`skeletonizer/full`**; **do not import `skeletonizer` as well** (it brings `core.css`, loading the styles twice, see [Migrating from the old layout](#migrating-from-the-old-layout)).
- `skeletonizer/global`, `/svg` and `/all` already include the full extensions and also install the global `skz` (with `registerCustomElements`); they are "extensions + the variant's runtime + styles", with the same paths and usage as before.
- Don't want to pick? `import "skeletonizer/all";` (all styles + all variants).
- Other variants: `skeletonizer/svg` (the SVG scheme only), `skeletonizer/sweep.css`, `skeletonizer/tofu.css` (only for `text: "tofu"`), and the explicit base `skeletonizer/explicit.css` (instead of `base.css`).
- The full list of entries and sizes is in [Entry points](#entry-points).

### 4. Turn it on

```ts
import { enable, Bone } from "skeletonizer"; // full: "skeletonizer/full"

const off = enable(document.querySelector("#card")!, { effect: "shimmer" });
// data arrived:
off();
```

Options of `enable()` (the "Version" column: Both = core and full; Full only = ignored in core if passed):

| Option     | Version   | Values                                                              | Notes                                                                                                                                                                                                                                                                                   |
| ---------- | --------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `effect`   | Both      | `fade` (default) / `solid` / `pulse` / `shimmer`; full adds `sweep` | `sweep` needs the full version + `sweep.css`. pulse / shimmer work out of the box in core (the root-driver CSS is in `core.css`); in full their implementation can be `global` or `svg`, and with no variant loaded the pure-CSS root driver of global is used                          |
| `text`     | Full only | `round` (default) / `clip` / `underline` / `leaf` / `tofu`          | how text bones are drawn, written to the root's `skz-text-mode`; see [Text bone modes](#text-bone-modes); `tofu` needs `tofu.css` on top; core has only round / clip and does not read this option (omitted = round, same as pure CSS)                                                  |
| `engine`   | Full only | `global` / `svg`                                                    | implementation of `pulse` / `shimmer`; defaults to whichever variant is loaded (`global` wins when both are); what happens when you name a variant that is not loaded is described in the `engine` row of the [Feature reference](#feature-reference), and development builds warn once |
| `fallback` | Full only | `svg` (default) / `fade`                                            | what the `global` scheme does on browsers without `@property`: JS attaches an SVG animation (`svg`) or keeps the base fade (`fade`); old browsers show fade until JS runs                                                                                                               |
| `fit`      | Both      | boolean (default `false`)                                           | the skeleton never grows a scrollbar: the root is capped at the space left in its scroll ancestor (or the viewport) and list items fully outside it get `display: none`; re-measured on resize. `<skz-box fit>` / React / Vue / Svelte pass it through                                  |

The CSS for `fit` is already part of `core.css` / `base.css` / `explicit.css`; nothing else to import.

Calling `enable()` again is safe: attributes are re-synced, omitted options are cleared, list items / ignore regions / theme variables are re-read.

### 5. Mark the bones

Unmarked content renders as-is. Mark what should become a bone with bare attributes inside the root:

```html
<!-- the root is whatever you call enable() on / wrap with <SkzBox>; it gets `skz` -->
<div class="card">
  <img skz-bone src="…" width="48" height="48" />
  <h3><span skz-text>Name</span></h3>
  <p><span skz-text>A longer bio that wraps onto several lines.</span></p>
  <div skz-leaf class="stats"><b>128</b> posts · <b>3.2k</b> followers</div>
  <button skz-bone>Follow</button>
  <a skz-ignore href="/cancel">Cancel</a>
</div>
```

| Attribute    | Put it on                              | Effect                                                                                                                                                                                                                                                                                                                                   |
| ------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skz-text`   | a text element (inside the root)       | Its whole subtree becomes text bars that follow the real text lines (last line shorter), mixed content such as `Price: <b>$5</b>` included. **Put it on an inner `<span>`, not on the block element**: in the default `round` mode a block element becomes one whole rounded rectangle, an inline `<span>` gets one rounded bar per line |
| `skz-bone`   | an image, avatar, button, colour block | This element becomes one bone and its subtree is hidden; media content is pushed out of the box                                                                                                                                                                                                                                          |
| `skz-leaf`   | a container                            | Merges the whole subtree into one bone                                                                                                                                                                                                                                                                                                   |
| `skz-ignore` | anything                               | Keep as real content, still clickable / focusable. Inside a `skz-text` / `skz-auto` region its text shows on top of the bar; to keep it clean write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`                                                                                                                 |
| `skz-auto`   | the root, or any element inside it     | Turns on tag-based inference for that subtree only, for third-party components you cannot mark (see below)                                                                                                                                                                                                                               |

For the complete attribute list (element marks, root attributes, runtime attributes the library writes) and how they behave under each text mode / entry point / animation effect / tier, see [Marks and attributes reference](#marks-and-attributes-reference).

`skz-text` / `skz-bone` / `skz-leaf` work anywhere under the root, inside or outside a `skz-auto` region; they are not read on the root itself. The look of text bars follows the root's `skz-text-mode` (the `text` option): `round` by default, see [Text bone modes](#text-bone-modes).

**`skz-auto` regions**: write the bare attribute `skz-auto` on the root or on any element inside it, and tag-based inference applies to that subtree only: text tags (`p` `span` `h1`–`h6` `a` `li` …), media and controls (`img` `video` `canvas` `svg` `input` `button` …), empty `<i>` and empty elements whose class contains `icon`. Limits: the rules work from a tag allow-list and CSS cannot select text nodes, so **bare text directly inside a `div`, a custom element or `code` is not covered (it stays invisible under round / clip)**: wrap it in `p` / `span` or mark it `skz-text`; a block-level text tag becomes one whole rounded rectangle under `round`; empty `div`s used as avatars or colour blocks are not inferred and need `skz-bone`.

### 6. Feed it mock data, render as usual

```ts
const user = loading ? { name: Bone.text(8), bio: Bone.lines(2), avatar: Bone.image(48, 48) } : data;
```

### Framework adapters

Adapters are subpath exports; the frameworks are optional peer dependencies. Adapters use the core modules directly: **they ship no styles and do not install the global `skz`**, so load the styles once yourself: core users `import "skeletonizer/core.css"`, full users `base.css` plus a variant (`skeletonizer/global` and so on). The option types of the adapters widen automatically with the version you import (see [Types](#types)); for the full-only options to take effect at runtime, also import `skeletonizer/full` (or `/global` `/svg` `/all`) once at the app entry to register the full extensions.

```ts
// Vue 3: directive / component / composable / plugin
import { vSkeleton, SkzBox, useSkeleton, SkzPlugin } from "skeletonizer/vue";
// <div v-skeleton="{ loading, effect: 'shimmer' }">…</div>   or   <SkzBox :loading="loading" effect="shimmer">…</SkzBox>

// React: hook / component
import { SkzBox, useSkeleton } from "skeletonizer/react";
// <SkzBox loading={loading} effect="shimmer">…</SkzBox>

// Svelte: action
import { skeleton } from "skeletonizer/svelte";
// <div use:skeleton={{ loading, effect: 'shimmer' }}>…</div>
```

### Custom element / pure HTML

```ts
import { defineSkzBox } from "skeletonizer"; // full: "skeletonizer/full"; or skz.defineSkzBox()
defineSkzBox();
```

```html
<skz-box loading effect="shimmer"><div class="card" skz>…</div></skz-box>
<!-- `loading` on the host is the switch; `skz` lands on its FIRST element child (the skeleton root), never on the host itself -->
<!-- SSR / no JS: write `skz` on that child yourself, e.g. <skz-box loading><div skz>…</div></skz-box>; the CSS (marks, and the fallback layer inside `skz-auto`) already works with no JS, and enable() is idempotent once JS boots -->
<!-- no JS: write the root attributes yourself (core: no inert lock; full: also no firewall or runtime SVG) -->
<div skz skz-effect="shimmer">…</div>
```

`<skz-box>` only tracks its own `loading` attribute (plus `effect` / `text` / `fallback` / `engine` / `fit`); without the full extensions loaded, `text` / `engine` / `fallback` are ignored. It does not use a MutationObserver: if a framework replaces the first child, toggle `loading` once (off, then on) so the new child is picked up and the old one is disabled. Moving the host to another parent keeps the loading state.

SSR-safe: `skeletonizer` (through the `node` condition), `skeletonizer/explicit`, `skeletonizer/full` and the `/js` entries of the variants import without errors in Node; the variant entries that ship CSS (`/global`, `/svg`, `/all`) need a bundler that handles CSS, see the next section.

### The global `skz`

Importing any of `skeletonizer`, `skeletonizer/explicit`, `skeletonizer/full` (and `/global`, `/svg`, `/all`, which include it) installs `skz` on `globalThis`, so you can use it without importing:

| Member                       | Version   | What it is                                                                                                       |
| ---------------------------- | --------- | ---------------------------------------------------------------------------------------------------------------- |
| `skz.enable` / `skz.disable` | Both      | same as `enable` / `disable`                                                                                     |
| `skz.bone`                   | Both      | the `Bone` class itself: `skz.bone.text(8)`, `skz.bone.lines(2)`                                                 |
| `skz.defineSkzBox`           | Both      | same as `defineSkzBox`                                                                                           |
| `skz.registerCustomElements` | Full only | only after importing the full version (`skeletonizer/full` or `/global` `/svg` `/all`); the type appears with it |

- **Installed during SSR too**: importing in Node also writes to `globalThis`; if you don't use it there is no side effect.
- **An existing `skz` is never overwritten**: if someone else already owns the global name `skz` (not installed by us), it is left alone and development builds `console.warn` once, suggesting imports instead; one we installed ourselves is simply refreshed (several copies and hot reload do not warn). In production builds the warning is stripped together with `process.env.NODE_ENV`.
- The object is not frozen, because the full version adds properties to it; **the adapters (`/vue` `/react` `/svelte`) do not install it**.
- Types: after importing any entry the global `skz` is typed (`SkzGlobal`); no declaration of your own needed.

### No bundler: use it straight from the browser (import map)

Without a bundler, the entries that ship CSS (`skeletonizer`, `skeletonizer/global` and friends start with `import "./x.css"`) cannot be imported directly: use the pure-JS files, link the CSS yourself with `<link>`, and let an import map map the bare module names to concrete files. The targets are the files that `exports` in `package.json` points at:

| Module name              | File                   | Notes                                                                                        |
| ------------------------ | ---------------------- | -------------------------------------------------------------------------------------------- |
| `skeletonizer`           | `dist/core-js.mjs`     | core, pure JS (what the `node` condition in `exports` resolves to); link `core.css` yourself |
| `skeletonizer/explicit`  | `dist/explicit-js.mjs` | explicit mode, pure JS; link `explicit.css` yourself                                         |
| `skeletonizer/full`      | `dist/full.mjs`        | full runtime, never contains CSS                                                             |
| `skeletonizer/global/js` | `dist/global-js.mjs`   |                                                                                              |
| `skeletonizer/svg/js`    | `dist/svg-js.mjs`      |                                                                                              |
| `skeletonizer/all/js`    | `dist/all-js.mjs`      |                                                                                              |

CSS files: `dist/core.css`, `base.css`, `explicit.css`, `global.css`, `svg.css`, `sweep.css`, `tofu.css`, `all.css` (`style.css` is the same file as `all.css`).

core:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/skeletonizer/dist/core.css" />

<script type="importmap">
  { "imports": { "skeletonizer": "https://cdn.jsdelivr.net/npm/skeletonizer/dist/core-js.mjs" } }
</script>

<script type="module">
  import { enable, Bone } from "skeletonizer"; // importing also installs the global skz

  const off = enable(document.querySelector("#card"), { effect: "shimmer" });
  // when the data arrives: off();
</script>
```

Full:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/skeletonizer/dist/base.css" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/skeletonizer/dist/global.css" />

<script type="importmap">
  {
    "imports": {
      "skeletonizer/full": "https://cdn.jsdelivr.net/npm/skeletonizer/dist/full.mjs",
      "skeletonizer/global/js": "https://cdn.jsdelivr.net/npm/skeletonizer/dist/global-js.mjs"
    }
  }
</script>

<script type="module">
  import { enable, Bone } from "skeletonizer/full";
  import "skeletonizer/global/js"; // registers the global scheme (firewall + old-browser SVG fallback)

  const off = enable(document.querySelector("#card"), { effect: "shimmer" });
  // when the data arrives: off();
</script>
```

- Put the import map before the first module script. Only the entry files are mapped: the `.mjs` files in `dist/` reference their shared chunks by relative path (hashed file names that change with the version), so serve the whole `dist/` as-is from one path.
- The CDN URLs above point at the published package; to try local changes instead, put the `dist/` from `pnpm build` in your own static directory and swap the URLs for those paths (`bench/2026-10-10-core/perf.html` does exactly this, loading `core-js.mjs` + `core.css` through an import map; verified in Chrome 154).

## Entry points

Styles and runtime are split; load only what you use. Sizes are `gzip -9 -n` of the `pnpm build` output, each file compressed and summed (1 KB = 1024 bytes; "JS" = the entry file plus the shared chunks it depends on, without CSS).

### core and the explicit base

| Entry                       | What                                                                                                                                                                                                                                               | Size (JS + CSS)           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |

## Upgrading to 0.2.0

0.2.0 changes the default from "infer bones from tags" to "you mark the bones". Breaking changes (the complete record is in the [CHANGELOG](./CHANGELOG.md)):

1. **Explicit marking is the default.** Without any marker, and outside a `skz-auto` region, content renders untouched. Put `skz-text` on text (on an inner `<span>` inside block elements), `skz-bone` on images / avatars / buttons / colour blocks, `skz-leaf` on containers to merge. For third-party markup you cannot edit, put the bare attribute `skz-auto` on the root or any element inside it: the old inference rules (tier 0, fallback layer, icons, controls, leaf mode, tofu) now apply to that subtree only. See [Mark the bones](#5-mark-the-bones).
2. **The root attribute `skz-text` is now `skz-text-mode`** (values `round` / `clip` / `underline` / `leaf` / `tofu`). The `text` option is unchanged and writes the new attribute; roots written by hand must be renamed. `skz-text` is now the element-level marker.
3. **New default text mode `round`.** Text bars become rounded background boxes (see [Text bone modes](#text-bone-modes)). For the old look write `skz-text-mode="clip"` on the root (full: `text: "clip"`). Core and `explicit.css` also understand `round` / `clip` when written by hand.
4. **`skz-has-ignore` is removed**; ignore regions work with `skz-ignore` alone, in pure CSS, and `enable()` no longer writes anything for them. The "turn off the underline of ancestors that contain an ignore region" fix is gone: inside a `skz-text` element or `skz-auto` region, an ignore region's text shows on top of the bar. For a clean ignore region write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`.
5. **`explicit.css` / `skeletonizer/explicit` now mean "no `skz-auto` inference rules"**, and they support `skz-text` (round / clip), `skz-bone`, `skz-leaf`, `skz-ignore`. `core.css` and `base.css` are the marks plus the inference gated on `skz-auto`.
6. **Browser bar**: the inference and marker rules are written with `:is()` / `:where()` (Chrome 88+ / Safari 14+ / Firefox 84+; the marker rules use `:not()` with selector lists).

CSS no longer depends on JS at all: with `skz` written on the root by hand, everything renders correctly (the lock, lazy pause, firewall and runtime SVG are performance / degradation paths, not part of correctness).

## Migrating from the old layout

This section covers the pre-0.1.0 preview layout. The package was split into core and full. The breaking changes are these (the complete record is in the [CHANGELOG](./CHANGELOG.md)):

1. **The old `import … from "skeletonizer"` (the former full core) → `skeletonizer/full`.** Anything that uses `text` / `engine` / `fallback` / `sweep` / `registerCustomElements` must change; code that only uses `effect` / `fit` can stay, but `skeletonizer` is now core and ships `core.css` with it (see point 4).
2. **`registerExtension({ engine, sync, release })` → `registerEngine({ engine, sync, release })`**, exported from `skeletonizer/full`. `registerExtension` is now the generic extension point `{ name, sync, release }` (exported by core).
3. **Loading only `base.css` (or `explicit.css`) without `global` now already gives pure-CSS pulse / shimmer animation** (Chrome 119+ and other browsers with relative colour syntax; it used to fall back to fade). `global` is now only the inheritance firewall and the old-browser SVG fallback.
4. **Full-version users must not import the `skeletonizer` default entry as well.** It ships `core.css`: with both style sets present, core's rules only match text-bar roots (no `skz-text-mode`, or `round` / `clip`), which is redundant but identical for default roots; but when `core.css` comes **after** the full styles, its shimmer root rule (same specificity, last one wins) overrides the pulse animation that underline / tofu / unknown-value roots rely on, and the text colour of those roots turns static (`bench/2026-10-10-layering/NOTES.md`, section `dup`, has the per-item data). Users of the `skeletonizer` default entry alone are unaffected.
5. **The adapters' types widen with the version you import**: after importing `skeletonizer/full` (or `/global` `/svg` `/all`), `EnableOptions` gains `text` / `engine` / `fallback`, `SkzEffect` gains `sweep`, and the adapter props follow; the adapter import paths stay the same.
6. Other: with clip now a positive selector, **any unknown `skz-text-mode` value now looks like underline** (it used to look like clip); `registerCustomElements` is exported by the full version only; `explicit.css` keeps the lazy-rendering (`skz-paused`) and `skz-cv` rules, `core.css` does not have them.

## Marks and attributes reference

The HTML attributes the library uses fall into three groups: **element marks** (you write them on descendants of the root), **root attributes** (written on the root, mostly by `enable()` on your behalf) and **runtime attributes** (the library writes them, do not write them by hand). Three attribute tables come first, then a few matrices show how they behave under different text modes, entry points, animation effects and browser tiers. In the tables, core means `core.css` (the default `skeletonizer` entry) and full means `base.css` plus the full JS; where `explicit.css` (the explicit base shared by core and full) differs, it is called out. Every conclusion comes from the code in `src/styles/`, `src/core/` and `src/full/`.

### Element marks

Written on **descendants** of the root, all bare attributes (no value needed). The selectors are descendant selectors of the form `[skz] [skz-…]`, so writing one on the root itself does not match (`skz-auto` is the exception, it works on the root too).

| Attribute    | Put it on                                                | Value          | Purpose                                                                                                                                                                                                                                                                    | core / full                                                                         |
| ------------ | -------------------------------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `skz-text`   | a text element (preferably an inner `<span>` of a block) | bare attribute | The text of its whole subtree becomes bars that follow the real text lines; on a container it covers mixed content; drawn according to the root's `skz-text-mode`; ignored on a `skz-bone` / `skz-leaf` / `skz-ignore` element itself and inside `skz-leaf` / `skz-ignore` | Both; core has round / clip only, full has five modes                               |

| `skz-leaf`   | a container                                              | bare attribute | Merges the whole subtree into one bone: descendants hidden, underlines in the subtree removed; drawn like `skz-bone` except that media content is not handled (use `skz-bone` on `img` etc.)                                                                               | Both                                                                                |
| `skz-ignore` | any element                                              | bare attribute | Kept as-is, clickable and focusable; the `enable()` interaction lock skips branches that contain it; while the root contains one, the implicit default fade is off (needs `:has()`; an explicit `effect: "fade"` still runs)                                               | Both                                                                                |
| `skz-auto`   | the root itself, or any element inside it                | bare attribute | Marks an inference region: inside it bones are inferred from a tag allow-list (text tags, media and controls, empty `<i>` and empty elements whose class contains `icon`); leaf / tofu mode inference also only works inside regions; full adds the fallback layer         | core yes; `explicit.css` has no inference rules, so it does nothing there; full yes |

Written on the root. `skz`, `skz-effect`, `skz-text-mode`, `skz-fit` and `skz-engine` are normally written by `enable()` / the adapters from your options; writing them by hand is for plain HTML without JS.

### How marks look in each text mode

The root's `skz-text-mode` decides how the text of `skz-text` and of `skz-auto` regions is drawn; `skz-bone` / `skz-leaf` / `skz-ignore` barely change with the mode.

| Target                                                                             | round (default)                                                                                              | clip                                                          | underline                                                     | leaf                                                                                                      | tofu                                                                                                                       |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `skz-text` on an inline element (`<span>`)                                         | One rounded bar per line, each wrapped line with its own corners                                             | A bar following the text lines, last line shorter, no corners | A thick underline along the text lines, real text transparent | The whole element is one bone, split into per-line fragments when it wraps                                | Text switches to block glyphs, wrapping still uses the block widths                                                        |
| `skz-text` on a block element                                                      | One whole rounded rectangle (a short heading is stretched to full width)                                     | Same as inline: a bar following the text lines                | Same as inline: an underline along the text lines             | One whole rounded rectangle                                                                               | Same as inline: block glyphs                                                                                               |
| Text tags inside a `skz-auto` region                                               | Like `skz-text`: inline tags one bar per line, block tags (`p` `h1`–`h6` `li` …) one whole rounded rectangle | A bar following the text lines                                | A thick underline along the text lines                        | An element with no child elements but with text becomes one bone                                          | The tag and its descendants switch to block glyphs; elements that contain an ignore region fall back to the underline look |
| Bare text in a region outside the tag list (e.g. text written directly in a `div`) | Invisible                                                                                                    | Invisible                                                     | Underlined (all descendant text is drawn)                     | A `div` with no child elements becomes one bone; bare text mixed with elements gets no bone (transparent) | Falls back to the underline look                                                                                           |
| `skz-bone`                                                                         | One block of colour, descendants hidden; independent of the mode                                             | Same                                                          | Same                                                          | Same                                                                                                      | Same                                                                                                                       |
| `skz-leaf`                                                                         | One block of colour, subtree hidden; independent of the mode                                                 | Same                                                          | Same                                                          | Same                                                                                                      | Same                                                                                                                       |
| `skz-ignore`                                                                       | Kept as-is and clickable; inside `skz-text` / a region its text sits on top of the bar                       | Same                                                          | Same                                                          | Same                                                                                                      | Kept as-is; a text element containing it falls back to underline, the ignore region gets no block glyphs                   |

- The mode only applies to `skz-text` and to the text in `skz-auto` regions; `skz-bone` / `skz-leaf` / `skz-ignore` have one exception, tofu (see the table).
- An underline / tofu root nested inside a round / clip root does not inherit the outer round / clip variables; each draws its own way.
- Browsers without `box-decoration-break` (the `-webkit-` form included) get clip instead of round; in full, browsers without `background-clip: text` then fall back to underline (core's bar has both, so core has no such branch).
- Without `tofu.css`, tofu looks like underline; when a CSP blocks the font, the real text shows through in the bone colour.
- Corners: round text bars always read `--skz-radius`, clip / underline have no corners; `skz-bone` / `skz-leaf` read `--skz-radius` and keep an element's own `border-radius`.
- Details and limits are in [Text bone modes](#text-bone-modes).

### How marks look under each animation effect

| Target                                                                      | fade                                                                                                             | solid              | pulse                                                                                   | shimmer                                                                                                                                                               | sweep (full only)                                         |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------ | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| round / clip / leaf text bars, `skz-bone`, `skz-leaf`, tier 0 colour blocks | The whole root's opacity pulses, the bones themselves stay still                                                 | Static bone colour | Bone colour pulses between `--skz-color` and `--skz-highlight`                          | A highlight band sweeps through viewport coordinates, all bones in sync; a fixed 400px band, cycle 2s / 2.8s / 3.6s by screen width (three tiers), sweeps for the first 62.5% of the cycle, rests for the last 37.5%, throttled to 24 updates/s | Bones stay still, the root's `::after` band sweeps across |
| underline / tofu text                                                       | Same as above                                                                                                    | Static             | The underline / block glyph colour pulses                                               | Colour pulse (no band, throttled the same way)                                                                                                                        | Static bone colour, the band sweeps across                |
| `skz-ignore`                                                                | Off by default while the root contains an ignore region (only on when written explicitly, and then it fades too) | As-is              | As-is                                                                                   | As-is                                                                                                                                                                 | Still swept by the band                                   |
| List items carrying `skz-fw` (global)                                       | Not applicable                                                                                                   | Not applicable     | Bones inside stay still (colour pinned to `--skz-color`)                                | Bones inside stay still (band parked off-screen)                                                                                                                      | Not applicable                                            |
| svg engine                                                                  | Not applicable (the engine only handles pulse / shimmer)                                                         | Not applicable     | The shared SVG background pulses; text bars and bones move, underline / tofu stay still | The shared SVG band; text bars and bones move, underline / tofu stay still                                                                                            | Not applicable                                            |
| iOS Safari (no `fixed` backgrounds)                                         | Unaffected                                                                                                       | Unaffected         | Unaffected                                                                              | global: every mode switches to a bone-colour pulse; svg: uses the pulse image instead                                                                                 | Unaffected                                                |
| Root outside the viewport (`skz-paused`)                                    | Stops                                                                                                            | Already still      | Stops                                                                                   | Stops, the band background image is dropped                                                                                                                           | The band stops too                                        |

- With `prefers-reduced-motion: reduce` every animation stops and the bones stay still; there is no switch to turn that off.
- `skz-bone` / `skz-leaf` read the gradient-driven variables, so even when the root is in underline / tofu mode they still get the shimmer band; only the text pulses in colour.
- The root driver for pulse / shimmer needs `@property` (detected through the relative colour syntax): without it core falls back to fade, and full's global switches to an SVG animation through JS (`fallback: "fade"` turns that off); `sweep` does not depend on it.
- The band throttling only applies to the root driver (core and global); the svg engine's band speed is set by SMIL.

### Tiers and fallbacks

Tiers are picked by capability, with no UA sniffing; the column names match the demo's tier selector (tier 0 = fallback layer only, 1 = + tier 0 and all effects, 2 = + tier 1, 3 = + tier 2).

| Target                      | Fallback layer only (full only)                                     | Tier 0 (CSS variables + `:is()`)                                                              | Tier 1 (+ `text-decoration-thickness`)                                                 | Tier 2 (+ `:has()`)                                                                     | core below the bar                              |
| --------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `skz-text`                  | No rule, real text shows                                            | No rule, real text shows                                                                      | Text bars / underlines / block glyphs appear                                           | Same as tier 1                                                                          | Real text shows                                 |
| `skz-bone` / `skz-leaf`     | Yes                                                                 | Yes                                                                                           | Yes                                                                                    | Yes                                                                                     | Yes                                             |
| `skz-ignore`                | Yes                                                                 | Yes (backgrounds on its descendants are still cleared)                                        | Yes (same)                                                                             | Yes (leaf mode keeps backgrounds exactly)                                               | Yes                                             |
| Inference inside `skz-auto` | Direct children get one grey block each, descendants hidden, static | Tag allow-list colour blocks, text tags as whole blocks, nested hits merge into larger blocks | Text lines become bars (round / clip / underline), controls are one block with no line | Plus leaf mode and icon detection (empty `<i>`, class containing `icon`)                | Tier 0 colour blocks (static)                   |
| Animation                   | None (no animation rules at demo tier 0)                            | fade / solid; pulse / shimmer fall back to fade without `@property`                           | Same as tier 0                                                                         | Same as tier 0; the implicit fade is turned off when the root contains an ignore region | fade / solid; pulse / shimmer fall back to fade |

- core's modern tier is one `@supports` that needs both `text-decoration-thickness` and `:has()`, so for `skz-text` core only has "yes / no"; in full, `skz-text` is already there at tier 1 (`text-decoration-thickness`).
- The `skz-text` rules for leaf mode have no `@supports` gate, and neither do tofu's; once `tofu.css` is loaded they render with the font.
- Below the bar `skz-text` shows the real text instead of a bar, so keep this in mind: an explicit mark on an old browser is the same as no mark.
- The fallback layer only paints the direct children of a `skz-auto` region as one grey block each and hides their descendants; it sits at the very top of `base.css`, and the "exit fallback" rules after it (same selector, later in the file) cancel the whole layer. Both layers' selectors contain `:is()`, so, going by the code, any browser that can parse them cancels the layer, and it is already absent from the build output `dist/base.css`; today only the demo's tier 0 shows what the fallback layer looks like.

## Types

`dist/*.d.mts` is the source of truth. The core types are exported from `skeletonizer`; the full runtime is exported from `skeletonizer/full` (it re-exports everything from core and adds the full-version API); the adapter types come from their own sub-paths.

```ts
// core (also the base of full)
import { enable, disable, defineSkzBox, Bone, SkzBox, registerExtension, ROOT_ATTR } from "skeletonizer";
import type { EnableOptions, SkzEffect, SkzEffectMap, SkzExtension, SkzGlobal } from "skeletonizer";

// what full adds on top of core
import { registerCustomElements, registerEngine } from "skeletonizer/full";
import type { SkzTextMode, SkzFallback, SkzEngine, SkzEngineImpl, RegisterOptions } from "skeletonizer/full";
```

### How the types widen with the version

The core types only describe what core has. The type declarations of the full entries (`skeletonizer/full`, and `skeletonizer/global`, `/svg`, `/all`, which include it) carry a `declare module "skeletonizer"` augmentation: **as soon as your project pulls in the types of any of those entries (that is, you import one of them), the types below widen automatically**, with no change to existing code:

| Type                                       | Core only                                      | After importing full              |
| ------------------------------------------ | ---------------------------------------------- | --------------------------------- |
| `EnableOptions`                            | `effect`, `fit`                                | also `text`, `engine`, `fallback` |
| `SkzEffect`                                | `"fade" \| "solid" \| "pulse" \| "shimmer"`    | also `"sweep"`                    |
| `SkzGlobal` (the type of the global `skz`) | `enable` / `disable` / `bone` / `defineSkzBox` | also `registerCustomElements`     |
| Adapter props (`SkzBox` and others)        | follow `EnableOptions`                         | widen along with it               |

The mechanism: `SkzEffect` is `keyof SkzEffectMap`, `EnableOptions` and `SkzGlobal` are interfaces, and the full version adds members through interface merging (anyone writing their own extension can add an effect name the same way). So:

- With core only, `enable(el, { text: "leaf" })`, `{ effect: "sweep" }` and `{ engine: "svg" }` are **type errors** (core ignores them at runtime too); that is deliberate: you find out at compile time that you used an option core does not have;
- The augmentation is **project-wide**: as soon as one file imports a full entry, `EnableOptions` is wider everywhere in the project (interface merging in TypeScript is global), so in a project that mixes core and full the types will not stop you from passing a full-only option to core;
- `test/types` verifies this against the build output, entry by entry (core only, `/full`, `/global`, `/svg`, `/all` and their `/js` builds).

### `EnableOptions`

The options shared by `enable()`, the `<skz-box>` attributes and the three adapters; every field is optional (the "Version" column: Both = core and full):

| Field      | Version   | Type          | Default                                                                                      | Notes                                                                                            |
| ---------- | --------- | ------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `effect`   | Both      | `SkzEffect`   | `"fade"`                                                                                     | Animation effect, written to the root's `skz-effect`                                             |
| `fit`      | Both      | `boolean`     | `false`                                                                                      | The skeleton never grows a scrollbar (capped root height, off-screen list items `display: none`) |
| `text`     | Full only | `SkzTextMode` | `"round"`                                                                                    | How text bones are drawn, written to the root's `skz-text-mode`                                  |
| `engine`   | Full only | `SkzEngine`   | Follows the loaded variants: `global` if present, `svg` if only svg is loaded, else `global` | Implementation of `pulse` / `shimmer`, only affects those two effects                            |
| `fallback` | Full only | `SkzFallback` | `"svg"`                                                                                      | What the `global` scheme does on browsers without `@property`                                    |

### Functions and constants

```ts
// core (skeletonizer)
function enable(el: HTMLElement, opts?: EnableOptions): () => void; // returns the off function
function disable(el: HTMLElement): void;
function defineSkzBox(tag?: string): void; // default tag name "skz-box"
function registerExtension(ext: SkzExtension): void; // the generic extension point, only for writing your own
const ROOT_ATTR: "skz";

// full (skeletonizer/full) adds
function registerCustomElements(root?: Document | ShadowRoot, opts?: RegisterOptions): { refresh(): string[]; dispose(): void };
function registerEngine(impl: SkzEngineImpl): void; // where scheme implementations register; the variant entries call it on load, normally not by you
```

- `RegisterOptions`: `{ tags?: string[]; watch?: boolean }`. `tags` adds custom element tag names by hand, `watch` rescans automatically on DOM changes.
- Return value of `registerCustomElements()`: `refresh()` rescans `root` and returns the array of matched tag names (including `opts.tags`, sorted alphabetically); `dispose()` stops watching and removes the stylesheet this call mounted.
- `SkzExtension`: `{ name: string; sync(el, opts): void; release(el): void }`, the generic extension point. Every `enable()` call runs each extension's `sync` in registration order, turning the skeleton off runs each `release`, and a later registration under the same name replaces the earlier one. The full version's text modes, scheme dispatch and lazy rendering are three extensions hooked in through it.
- `SkzEngineImpl`: `{ engine: SkzEngine; sync(el, opts): void; release(el): void }`, the registration through which the `global` / `svg` variants plug into the full version's scheme dispatch (it used to be `registerExtension({ engine, … })`, see [Migrating from the old layout](#migrating-from-the-old-layout)).
- `SkzGlobal`: the shape of the global `skz`; the members are listed in [The global `skz`](#the-global-skz).

## Comparison

> All numbers in this chapter were measured before 0.2.0 and were **not re-run**: text mode **clip** (the default back then, written as "default clip" below; today that means `skz-text-mode="clip"` / `text: "clip"`), and inference rules active over the whole root. Since 0.2.0 the default text mode is `round` (prototype measurement: GPU about half of clip) and inference only runs inside `skz-auto` regions.

### The core size limit

core has no inheritance firewall: pulse / shimmer re-calculate the style of every element under the root each frame, so the element count under one root has a ceiling. This section answers two questions: does core hold 60 fps for pulse / shimmer within about 2,000 elements, and beyond how many elements should you move to the full version.

**Test conditions** (scripts, scenarios and raw data are in `bench/2026-10-10-core/`): Chrome 154.0.8037.98, Windows 10, Intel i5-13500 + UHD 770 integrated GPU, viewport 1200×800, DPR 1; a frozen snapshot of the `pnpm build` `dist/`, served by a separate static server (not the vite dev server); the benchmark page loads `core-js.mjs` + `core.css` through an import map (full comparison: `base.css` + `global.css` + `full.mjs` + `global-js.mjs`, equivalent to `skeletonizer/global`, with the inheritance firewall); default text mode clip; each card has 8 elements (125 / 250 / 500 cards ≈ 1,000 / 2,000 / 4,000 elements); **every cell loads the page fresh**, median of 3 traces. Each cell is fps / style recalc ms / PrePaint ms / Paint ms / GPU ms / enable ms (style recalc and the others are per-frame costs; "enable" is the time of a real `enable()` call, median of 5, noisy, read it as an order of magnitude only).

**Conditions and limits**: the test machine is a daily workstation, **not in a quiet state**: whole-machine CPU before a run was about 22%–24% (it never got under 15%), the in-batch whole-machine CPU mean was 31.2% for the main batch and 33.7% for the limit batch (three tries at 33.7%–35.8%, the lowest one kept; the batch mean includes the benchmarked Chrome itself and was not separated out); **Chrome only**, Firefox / Safari were not tested; "4× throttle" is CDP's `Emulation.setCPUThrottlingRate`, a rough stand-in for slow devices, not a real device.

**Conclusions**:

1. **Does core hold 60 fps for pulse / shimmer within about 2,000 elements? On a desktop-class CPU at normal speed: yes.** 1,000 / 2,000 elements are both 60.4 fps, and 4,000 elements give pulse 59.2 / shimmer 60.4 (repeat: 58.4 / 60), so about 2,000 elements leaves a 2× margin. **On a slow device (4× throttle): no**: 2,000 elements give pulse 21.2 / shimmer 17.2 fps, and even 504 elements give only 40.8 / 52 fps (full under the same throttle: 58.8 / 58.4 fps at 2,000 elements).
2. **Beyond how many elements should you move to full?** On a desktop-class CPU pulse starts dropping frames beyond about 4,000 elements and shimmer beyond about 6,000 (6,000 elements: pulse 46.4, shimmer 58 fps; 8,000: 39.6 / 52; 12,000: 25.6 / 24.4; 16,000: 18.4 / 16.8), so **move to full beyond about 4,000 elements**. When slow devices (mobile / low-end) matter the bar is much lower: under the 4× throttle pulse / shimmer at 504 elements already miss 60 fps (smaller sizes were not measured); either keep a single root very small, or use full, or use only fade / solid in core (core's fade / solid were not measured under the 4× throttle).
3. The boundary is set by main-thread compute: style recalc milliseconds grow linearly with the element count, and a slower CPU shifts the whole line left in proportion, so the "about 4,000 elements" above only holds for desktop CPUs like this one.
4. The full version is not unlimited either: at normal speed 16,000 elements are still 60.4 fps, but under the 4× throttle 4,000 elements drop to 47.6 (pulse) / 57.6 (shimmer) fps (the "full" rows in the table).
5. The main batch was run a second time in full (`after2`, whole-machine CPU mean 30.8%): core at 1,000 / 2,000 elements is again 60.4 fps, at 4,000 elements pulse 58.4 / shimmer 60 fps; under the 4× throttle at 2,000 elements pulse 18 / shimmer 16 fps (main batch 21.2 / 17.2); full under the 4× throttle at 2,000 elements 55.2 / 59.6 fps (main batch 58.8 / 58.4). The three independent tries of the limit batch agree with each other (for example core at 6,000 elements: pulse 46.4–49.2 fps, shimmer 58–60.4 fps); the 4×-throttle cells fluctuate more (for example core shimmer at 125 cards: 18.4–26.8 fps), and the tables above take the try with the lowest CPU mean; `bench/2026-10-10-core/NOTES.md` has all the tries and the repeated run of the main batch.

- `sweep` is a compositor animation: very little style work, a fixed PrePaint / GPU cost, and style side effects on the root.

## Schemes in detail

### fade / solid (built into the base)

- **fade** (default, what you get without `skz-effect`): the whole root pulses its opacity on the compositor thread, nearly free however many elements there are. With `skz-ignore` inside the root the implicit default skips fade (it would dim the ignored content); pass `effect: "fade"` to force it.
- **solid**: static, no animation.

### Root-driven pulse / shimmer and the global variant

```ts
import "skeletonizer"; // core: the root driver is already in core.css; full: base.css has it too, add import "skeletonizer/global" (or /global/js + global.css) for the firewall / old-browser fallback
enable(el, { effect: "shimmer" }); // or "pulse"
```

- **How it works** (core.css / explicit.css / base.css all carry this root driver): one CSS animation on the root drives variables registered with `@property` (shimmer position, pulse colour); bones only read the inherited values and carry no animation of their own. Colours come from `--skz-color` / `--skz-highlight`, so they follow the theme exactly.
- **shimmer**: a `background-attachment: fixed` gradient slides through viewport coordinates, so all bones stay in sync; round / clip mode put the band inside the text bars, while explicit underline / tofu text cannot take a gradient and uses a colour pulse instead (only these two modes get an extra pulse animation on the root; clip / leaf do not, which saves per-frame style work that would do nothing).
- **Throttling**: the band updates 24 times per second by default (`--skz-shimmer-timing` is tiered by screen width: `steps(30)` / `steps(42)` / `steps(54)`, over the 62.5% sweep of each tier's cycle, 1.25s for the 2s small-screen tier): frames whose computed value did not change are not repainted, so GPU time for 2,000 clip cards drops from 11 ms to about 3 ms. `steps(18)` is cheaper, `linear` restores smoothness; the step count is tied to the duration (see the Feature reference) and only the root driver is throttled (core and full's global scheme; the svg engine is not).
- **core has no inheritance firewall**: every element under the root takes part in the per-frame style recalculation, so core is meant for about 2,000 elements under a single root; data in [the core size limit](#the-core-size-limit); move bigger skeletons to the full version.
- **Inheritance firewall (automatic, the full version's `global` variant only)**: when enabled through `enable()` / an adapter, the library looks for list items from the root down (skipping wrappers with a single child, so "root > list container > cards" hits the cards) and marks the ones outside the viewport with `skz-fw` via one shared `IntersectionObserver`. CSS pins the animated variables to static values on those items, so their descendants stop recalculating every frame. Bones in off-screen items are static and resume 200px before they scroll in; items inserted after enabling join on the next `enable()` call (until then they animate normally, they just do not save anything). **Do not make list items `display: contents`**: they stay static, see [The inheritance firewall and `display: contents`](#the-inheritance-firewall-and-display-contents).
- **Old-browser fallback (the full version's `global` variant only; core has none, browsers below the bar only get fade)**: without `@property`, JS attaches an SVG animation by default (generated as a blob, exact colours); `fallback: "fade"` keeps the base fade instead. Before JS runs (SSR first paint) and when blob generation fails, old browsers show fade.

### svg: shared SVG animation background

```ts
import "skeletonizer/svg"; // with only svg imported, pulse / shimmer default to svg
enable(el, { effect: "shimmer" }); // with global also imported, write engine: "svg"
```

- **How it works** (the full version's `svg` variant only): every bone's background carries one SMIL-animated SVG that all bones share, so CSS does not change per frame and there is no style recalculation; no `@property` needed.
- **Colours**: through `enable()` the SVG is generated at runtime from the root's `--skz-highlight` and `--skz-duration` (blob URL; when the duration is unset the shimmer tier is picked from the viewport width at generation time, the band is converted from 400px and nothing is recomputed on window resize), so colour and duration match the theme; one copy is shared per parameter set, released when nobody uses it, and regenerated on a system light/dark change. Without JS, or if the theme variables cannot be read, the root gets no `skz-engine` attribute and shows the base fade (the CSS ships no built-in SVG fallback image). When enabled through `enable()` the two images are written on the root as inline variables `--skz-svg-shimmer` / `--skz-svg-pulse`; with a hand-written `skz-engine="svg"` you can supply those variables yourself (not verified).
- **Costs**: explicit underline / tofu text is coloured rather than painted with the image and stays static under the svg engine (round, clip and leaf mode have no such problem); the `--skz-shimmer-timing` throttle does not apply to it; a strict CSP must allow `img-src blob:` (the runtime image); iOS has no fixed backgrounds, so shimmer uses the pulse image.

### sweep: highlight bar (pure CSS)

```ts
import "skeletonizer/sweep.css";
enable(el, { effect: "sweep" });
```

(Full only.) One `::after` bar over the whole root, moved by `transform` on the compositor thread; the band is tilted 12° by default (`--skz-sweep-skew`; set `0deg` on long roots). There is only one sweep, switched by theme: light uses a lighten blend that only brightens the bones; dark automatically sweeps with the container colour (band colour from `--skz-sweep-bg-rgb`, default `31, 41, 55`), so the container never leaks light. It changes the root element's own styles:

- the root becomes `position: relative`, so absolutely positioned descendants now resolve against it;
- the root gets `overflow-x: clip`, so dropdowns and badges poking out of its left / right edges are clipped;
- the root's `::after` is taken, so any `::after` you wrote on the root is overridden.

Give sweep a dedicated, unstyled wrapper div as its root. If your dark theme uses another container colour, override `--skz-sweep-bg-rgb` on the root (use the lightest container background inside it). It must be set on the skeleton root itself: set on an ancestor it is overridden by the `[skz]` dark default.

### Marks, `skz-auto` and `explicit.css`

Marks are the default in every base. Unmarked content renders as-is, and the bones are what you mark:

```html
<div skz>
  <img skz-bone src="..." />
  <h3><span skz-text>Title</span></h3>
  <p>This paragraph is not marked and renders as-is</p>
  <div skz-leaf>…merged into one bone…</div>
</div>
```

`skz-text` makes text bars (see [Text bone modes](#text-bone-modes)), `skz-bone` makes the element one bone, `skz-leaf` merges the subtree into one bone, `skz-ignore` keeps it as-is; descendants of a bone are hidden and media bones push their real content out of the box. Bones default to `var(--skz-radius)`, but an element that sets its own `border-radius` (a round avatar) keeps its shape.

For third-party components you cannot mark, write `skz-auto` on the root or on any element inside it: tag-based inference (tier 0, fallback layer, icons, controls, leaf / tofu modes) then applies to that subtree only. It is not in `explicit.css`. See [Mark the bones](#5-mark-the-bones) for its limits.

`explicit.css` (core: `import "skeletonizer/explicit"`) = the marks without any `skz-auto` rule, so both per-frame style recalc and enabling are cheaper (see [Comparison](#comparison)); `skz-text` in it knows only `round` / `clip`.

### Lazy rendering and `skz-cv`

Lazy rendering (full only) only watches the root: when a huge root has just one corner in view, the whole root's animation keeps running. `skz-cv` (in `base.css` / `explicit.css`, not in `core.css`) covers that blind spot by making the root's direct children skip rendering while outside the viewport, but stacked on `enable()` (the inheritance firewall) it does worse, so prefer the firewall when there is list structure. For the triggers, costs and numbers see the "Lazy rendering" and `skz-cv` rows of the [Feature reference](#feature-reference).

## Bone helpers

`Bone` offers static methods that generate placeholder data. Every result is deterministic (no `Math.random`): the same input always gives the same output under SSR, so hydration is safe. They only create data, rendering stays with your real components.

### Text placeholder

```js
Bone.text(n, { seed });
```

Generates placeholder text of n characters, words separated by spaces, wrapping naturally. `seed` changes the word-length distribution (default 0).

```js
Bone.text(12); // "███ ████ ███" (word lengths illustrative)
Bone.text(30, { seed: 1 }); // the same seed always gives the same distribution
```

### Paragraph placeholder

```js
Bone.lines(k, { perLine, seed });
```

Generates a placeholder paragraph of about k lines. `perLine` is the estimated characters per line (default 40).

```js
Bone.lines(3); // 120 characters (3 × 40) of placeholder text
Bone.lines(3, { perLine: 30 }); // 90 characters
```

### CJK text placeholder

```js
Bone.cjk(n, { seed });
```

Generates a CJK placeholder string: pure blocks with a zero-width space every 3–6 characters for line breaks.

```js
Bone.cjk(20); // 20 blocks with sensible break points
```

### Number placeholder

```js
Bone.number(digits);
```

Generates a fixed-width digit placeholder (full-width blocks).

```js
Bone.number(4); // "████" (4 digits)
Bone.number(); // "███" (3 digits by default)
```

### Image placeholder

`Bone.image(w?, h?)` has three shapes depending on the arguments:

```js
Bone.image(); // no args: base64 data URI of a 1×1 transparent GIF, best compatibility
Bone.image(48); // w only: h defaults to w, a 48×48 square transparent SVG
Bone.image(160, 100); // w and h: a 160×100 transparent SVG with an intrinsic aspect ratio
```

- **No arguments**: a GIF has no intrinsic size, so give it `width` / `height` attributes or CSS, otherwise it collapses to 1px:
  `<img :src="Bone.image()" width="160" height="100" />`
- **With a size**: the SVG carries its aspect ratio and causes little layout shift; `Bone.image(48)` is the handiest for avatars and icons.
- Invalid arguments (0, negative) fall back to the 1px GIF.

**Note:** if a strict CSP does not allow `img-src data:`, use a self-hosted transparent image.

## Theming

### Text bone modes

Set on the root: `enable(el, { text })` (full) or `skz-text-mode="…"` written by hand. core and `explicit.css` only know **round** and **clip** (a hand-written `skz-text-mode="round"` / `"clip"` works there too); the other three modes and the `text` option are **full only**. The modes apply to `skz-text` elements and to text inside `skz-auto` regions.

- **`round`** (default: what you get when `text` / `skz-text-mode` is omitted; needs `box-decoration-break`): the text goes transparent and the element gets a rounded background box. An inline element wraps into **one rounded bar per line**; a block element (`p` / `h3` / `div` / a flex item) is drawn as **one whole rounded rectangle**, whatever its length. So **put `skz-text` on an inner `<span>`** inside block elements. The bars take the shimmer band, the `fixed` background sync, the firewall, the dark theme and `--skz-radius` like any other bone. GPU is about half of clip (prototype measurement), and it does not depend on decorations taking part in `background-clip: text`, which was only verified in Chrome. Browsers without `box-decoration-break` (the `-webkit-` spelling is checked too) automatically fall back to clip; write `skz-text-mode="clip"` to choose clip explicitly. Known limits: (1) under Microsoft YaHei / Segoe UI / system-ui the bar is about 0.1–0.16em taller than clip's (the bar height is the font's content area; Arial / Georgia / Consolas / SimSun / Times match clip pixel for pixel); (2) with `line-height: 1.2` multi-line bars can overlap and leave notches (YaHei bar height 1.32em, overlap 0.12em); (3) a block-level target is one whole rectangle (a long paragraph is one big block, a short heading is stretched to the full row) and there is no pure-CSS fix: wrap an inline `<span skz-text>` inside, or choose `clip`; (4) the corner radius is fixed at `--skz-radius` (default 4px) and does not scale with the font size; (5) verified in Chrome 154 only, Firefox / Safari untested.
- **`clip`** (explicit `text: "clip"` / `skz-text-mode="clip"`; needs `background-clip: text`): the shape is one thick underline following the real text lines (shorter last line; mixed text such as `Price: <b>$5</b>` is covered too), the fill is the background gradient, so the text bars get a real shimmer band and move under the svg engine as well. It works by making the text and its decoration transparent while the decoration still takes part in `background-clip: text`, which clips the background into a 1.22em thick underline. Pixel for pixel what 0.1.x drew by default. Costs: more expensive than `underline` and `round` (numbers in [Comparison](#comparison)); the spec requires decorations to take part in the clip but it is **verified only in Chrome, Firefox / Safari untested (a known risk)**; in full, browsers without `background-clip: text` drop the clip rules via `@supports not` and fall back to `underline`; inside a `skz-auto` region, bare text outside the text-tag list (e.g. text directly in a div) gets no bone.
- **`tofu`** (full only; needs `skeletonizer/tofu.css`, already in `all.css`; write `text: "tofu"` / `skz-text-mode="tofu"`): text elements switch to a 1.5 KB all-blocks font `skz-tofu` (every character, whitespace included, is a solid block; the font is inlined into the CSS as base64); the colour pulses (static under svg); no underline and no `background-clip`. Layout (size, line height, wrapping) is still done by the browser using the block widths: narrow block 0.52em, wide block 1em, with a 0.08em overlap on the right to hide fractional-pixel seams. GPU is close to underline (2,000-card shimmer `global`: 1.85 vs 1.63 ms) and the shape is tidy. **Costs and constraints**: (1) wrapping is not done with the real font, ~1 in 4 cases differ from the real text by a line, and loaded content shifts the layout; (2) enabling is 30–45% slower and a cold start ~3× (text reflow); (3) **without `tofu.css`, a root with `skz-text-mode="tofu"` falls back to the underline look** (the text-bar family excludes it and the generic underline rules apply as usual); (4) the font is a data URI: a strict CSP must allow `font-src data:`, and when the font fails to load or is blocked **the real text shows through in the bone colour**, with no JS fallback; (5) when the root contains an inline `skz-ignore`, the text element containing it falls back to the underline look (otherwise the ignored content would inherit the block font); (6) cmap format 13 was verified in Chrome only, Firefox / Safari untested (format 4 covers the BMP as a fallback); (7) form controls, `skz-ignore` blocks and `skz-bone` / `skz-leaf` are unaffected. The font is generated by `scripts/gen-tofu-font.py` (a dev-time tool that needs Python fonttools, not an npm dependency).
- **`underline`** (full only; explicit `text: "underline"` / `skz-text-mode="underline"`; needs `text-decoration-thickness`): one thick underline under the real text, following the real text lines with the last line naturally shorter; mixed text is covered too. **The cheapest**; the cost is no gradient: under shimmer the text uses a colour pulse (static under svg). Use it on low-end devices or when you want the lowest cost.
- **`leaf`** (full only; needs `:has()`): a `skz-text` element becomes one whole bone like `skz-bone`; inside a `skz-auto` region an element with no child elements but some text becomes one whole bone that can shimmer and has rounded corners. The cost is that multi-line block text becomes one rectangle, and bare text nodes in mixed content get no bone.

```html
<div skz skz-text-mode="leaf">...</div>
```

### Custom colours, radius, duration

Theme variables are declared on the root itself, so set them **on the root element** (inline `style` or a selector that hits the root); setting them on `:root` has no effect:

```css
[skz] {
  --skz-color: #e0e0e0; /* bone colour (default #d9dde3, dark #374151) */
  --skz-highlight: #f0f0f0; /* highlight: shimmer band, pulse peak (default #eceff3, dark #4b5563) */
  --skz-radius: 6px; /* bone radius (default 4px) */
  --skz-duration: 1.2s; /* animation duration (unset: pulse 2s, shimmer 2s / 2.8s / 3.6s by screen width; when set, both use it) */
  --skz-ul-thickness: 1em; /* underline thickness */
  --skz-ul-offset: -0.85em; /* underline offset */
}
```

Dark mode switching (`prefers-color-scheme` / `data-skz-theme`), the sweep and fit variables, reduced motion and the rest are in the "Theme variables" and "Automatic behaviour" rows of the [Feature reference](#feature-reference).

| Browser capability                                    | What you get                                                                                                                                                                                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No CSS variables                                      | Fallback: each direct child of a `skz-auto` region is one grey block, descendants hidden, static (full only; core has no fallback layer)                                                                                            |
| CSS variables                                         | Tier 0: tag-whitelist bones (`skz-auto` regions), the `skz-bone` / `skz-leaf` / `skz-ignore` marks, fade / solid / sweep, the svg scheme; core also stays at this tier below its bar (static blocks + marks + fade)                 |
| `text-decoration-thickness`                           | Tier 1: `skz-text` bars and underline text bones (full; core needs it together with `:has()` before it turns on the modern tier)                                                                                                    |
| `background-clip: text`                               | Fill of the clip text mode (and the fallback of round); in full, without it the clip rules are dropped via `@supports not` and text falls back to underline (decoration-in-clip verified only in Chrome; Firefox / Safari untested) |
| `:has()`                                              | Tier 2: leaf mode, icon detection (full; same for core), and turning off the implicit fade when the root holds an ignore region                                                                                                     |
| `@property` (detected through relative colour syntax) | root-driven pulse / shimmer (in core and full); without it core falls back to fade and full's global scheme falls back to an SVG animation by default                                                                               |
| `box-decoration-break` (also the `-webkit-` spelling) | Round text bars (the default); without it text bars fall back to clip                                                                                                                                                               |
| `:is()` / `:where()`                                  | The `skz-auto` inference and the marker rules are written with them (Chrome 88+ / Safari 14+ / Firefox 84+); without `:where()` bones also lose the default radius (it yields to the element's own `border-radius`)                 |
| `IntersectionObserver`                                | Lazy rendering and the inheritance firewall (full only; core does not use it); skipped without it (still animated, just not optimised)                                                                                              |
| iOS Safari (no fixed backgrounds)                     | shimmer becomes a colour pulse (global) or the pulse image (svg)                                                                                                                                                                    |

**The core bar**: the target line is Chrome 119+ / Safari 16.4+ / Firefox 128+ (all the capabilities in the table above are present on that line). Browsers below it step down according to what is missing: without `text-decoration-thickness` or `:has()`, core gets tier 0 static blocks (`skz-auto` regions), the `skz-bone` / `skz-leaf` marks and fade, but no `skz-text` bars; without `@property` / relative colour syntax, pulse / shimmer fall back to fade (core has no SVG fallback). To give those browsers animation or finer inference, use the full version.

**Verification status**: core and full were both tested in Chrome only; Firefox / Safari are expected to work per the specs but were not tested. Everything was verified on desktop Chrome; Safari, Firefox, iOS, Android WebView and old browsers are **untested**, and the fallback paths were only simulated in Chrome by forcing the detection to fail.

## Known limitations and constraints

### Limits of core

- **Size**: core has no inheritance firewall, so pulse / shimmer re-calculate the style of every element under the root each frame; up to about 2,000 elements under one root it runs at 60 fps in desktop Chrome at normal speed, beyond that or on a slow CPU (4× throttle) it drops frames; the numbers and the advice are in [the core size limit](#the-core-size-limit).
- **Browser bar**: the target line is Chrome 119+ / Safari 16.4+ / Firefox 128+; below it, a missing `text-decoration-thickness` or `:has()` leaves tier 0 static blocks (`skz-auto` regions), the `skz-bone` / `skz-leaf` marks and fade (no `skz-text` bars), a missing `@property` / relative colour syntax makes pulse / shimmer fall back to fade, with **no SVG fallback and no fallback layer**. **Tested in Chrome only**; Firefox / Safari are expected to work per the specs but were not tested (the decoration-in-clip behaviour above all).
- **Text**: round (default) and clip only. Inside a `skz-auto` region, text written directly inside a div gets no bone (invisible): put it in `p` / `span`, mark it `skz-text`, or use the full version's `text: "underline"`. core's rules only match roots with no `skz-text-mode`, or `round` / `clip`; a hand-written `underline` / `leaf` / `tofu` has no matching rules in core.
- **What it does not have**: inheritance firewall, svg scheme, sweep, tofu / underline / leaf modes, lazy rendering (`skz-paused`), `skz-cv`, `registerCustomElements`, the fallback layer; use the full version for those, see [Core or full](#core-or-full).
- **Types**: with core only, `text` / `engine` / `fallback` / `sweep` are type errors, see [How the types widen with the version](#how-the-types-widen-with-the-version).

### Development warnings

In development builds (`process.env.NODE_ENV` not `production`) these two misuses `console.warn` once each (one message per case); in production builds the code is stripped. `process.env.NODE_ENV` stays verbatim in the output for your bundler to replace in its own mode; loaded straight in a browser (no `process`) it counts as production and stays silent.

- **The global `skz` is taken**: someone else already owns the global name `skz`; we do not overwrite it and suggest using imports instead.
- **`engine` misconfiguration** (full): naming a scheme that is not registered, either only `global` loaded with `engine: "svg"` or only `svg` loaded with `engine: "global"`, names the entry to import (`skeletonizer/svg` / `skeletonizer/global`, or `skeletonizer/all`).

### Edge cases of the fallback layer

These limits belong to the fallback layer (the full version's `base.css` only; core has none). It only applies inside a `skz-auto` region, so the snippets below put `skz-auto` on the root. Tier 0 and above may partly or fully fix them:

1. **`video` / `canvas` / `iframe` as direct children of the root**: the real content still covers the grey block. Fix: wrap it in a `div`.

   ```html
   <!-- ❌ no -->
   <div skz skz-auto>
     <video width="160" height="100"></video>
   </div>

   <!-- ✅ do this -->
   <div skz skz-auto>
     <div><video width="160" height="100"></video></div>
   </div>
   ```

2. **`display: contents` wrappers**: with no box there is nothing to paint and the descendants are hidden by `visibility:hidden`, so that area ends up **blank**.

   ```html
   <!-- ❌ no -->
   <div skz skz-auto>
     <div style="display:contents">
       <p>Paragraph one</p>
       <p>Paragraph two</p>
     </div>
   </div>

   <!-- ✅ wrap with a normal div -->
   <div skz skz-auto>
     <div>
       <p>Paragraph one</p>
       <p>Paragraph two</p>
     </div>
   </div>
   ```

3. **Bare text**: a bare text node directly under the root is not hidden and the real text shows.

   ```html
   <!-- ❌ no -->
   <div skz skz-auto>This bare text shows through</div>

   <!-- ✅ wrap it in an element -->
   <div skz skz-auto>
     <p>This paragraph is processed</p>
   </div>
   ```

4. **Floating absolutely-positioned badges**: they get painted as a grey block. Mark them `skz-ignore` to keep them as-is.

   ```html
   <div skz skz-auto style="position:relative;">
     <span class="badge" skz-ignore style="position:absolute;right:0;top:0;">new</span>
     <div>Card content</div>
   </div>
   ```

5. **Icon-font stars** (Tier 0): the icon-font glyphs show through. Tier 2 has a heuristic that recognises icons and improves this.

### The inheritance firewall and `display: contents`

This is a known defect and is not fixed for now. It only affects the full version's `global` variant (core has no firewall).

The firewall first marks every list item it finds under the root with `skz-fw`, then an `IntersectionObserver` removes the mark once an item enters the viewport. An element with `display: contents` has no box, so the observer always reports it as outside the viewport and its `skz-fw` is never removed: **even inside the viewport, its pulse / shimmer stays static, and so do its descendants**. `fit` uses the same list items and cannot measure such an item either, so it is not hidden as expected.

```html
<!-- ❌ the list items themselves are display: contents: they never animate -->
<div skz>
  <div style="display:contents"><p skz-text>…</p></div>
  <div style="display:contents"><p skz-text>…</p></div>
</div>

<!-- ✅ use list items that have a box (display: contents further inside the item is fine) -->
<div skz>
  <div><p skz-text>…</p></div>
  <div><p skz-text>…</p></div>
</div>
```

Watch out for box-less wrappers that frameworks tend to add (for example a component root wrapping each item in `display: contents`): either give it a box, or keep that root off the `global` scheme: import the svg variant and pass `engine: "svg"` (with only `global` loaded, `"svg"` still runs global), or accept core's scale limit without a firewall.

### Colours and backgrounds in `skz-ignore` regions

Text is hidden with `-webkit-text-fill-color` and `color` is left alone, so the text colour of `skz-ignore` regions and their descendants stays as-is at every tier. Remaining points:

- Backgrounds on descendants of an ignore region are still cleared in Tier 0 and 1; Tier 2's leaf background mode preserves them exactly.
- Borders / outlines / box-shadows on containers inside the skeleton that rely on `currentColor` will show; give them explicit colours, or handle them separately in the skeleton state.
- Only in the fallback layer (old browsers without CSS variables), an ignore region with no explicit colour still inherits transparent.
- Inside a `skz-text` element or a `skz-auto` region the text of an ignore region shows on top of the bar (real text colour over the grey bar); the old "turn off the underline of ancestors that contain an ignore region" fix was removed together with `skz-has-ignore`. For a clean ignore region write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`.

### Web Component hosts

Web Component hosts (Shadow DOM) need `registerCustomElements()` to generate the host stylesheet (the `::before` bone is painted like any other bone, reading the inherited `--skz-fill` / `--skz-bg-img` / `--skz-bg-pos`, so pulse / shimmer, the `global` throttle, the `svg` engine and the firewall all apply to hosts):

```js
import { registerCustomElements } from "skeletonizer/full"; // full only (also on the global skz)

// generates the host stylesheet (adoptedStyleSheets, or a <style> fallback)
const { refresh, dispose } = registerCustomElements(document, { watch: true });
// if custom elements are added later, call refresh() to rescan
refresh();
```

Hosts get `visibility:hidden` plus a `::before` bone, and the host's own background colour is hidden by `visibility` as well.

### `inert` support

`enable()` locks interaction with native `inert` by default. With `skz-ignore` inside the root it does not lock the whole root, only the branches that contain no ignore region, so ignore regions stay clickable and focusable (if the ignore regions change after enabling, call `enable()` again to re-lock). Browsers without `inert` fall back to CSS `pointer-events:none` plus a `focusin` interceptor (ignore regions are let through too), but that branch has not been verified on real devices.

### Text modes and shimmer throttling

Constraints only; the mechanics and numbers are behind the links.

- **round (default)**:
  - a block element carrying `skz-text` is one whole rounded rectangle (short headings are stretched to the full row): put `skz-text` on an inner `<span>`;
  - under Microsoft YaHei / Segoe UI / system-ui the bars are about 0.1–0.16em taller than clip's, and with `line-height: 1.2` multi-line bars can overlap into notches; the corner radius is fixed at `--skz-radius`;
  - browsers without `box-decoration-break` fall back to clip; verified in Chrome 154 only;
  - see [Text bone modes](#text-bone-modes).
- **clip** (`skz-text-mode="clip"`):
  - inside a `skz-auto` region, bare text written directly in a div gets no bone (invisible); put the text in `p` / `span`, mark it `skz-text`, or use `text: "underline"`;
  - decorations taking part in `background-clip: text` is **verified only in Chrome, Firefox / Safari untested** (a known risk that `@supports` cannot detect);
  - browsers without `background-clip: text` drop the clip rules via `@supports not` and fall back to the underline look (static grey, no band);
  - see [Text bone modes](#text-bone-modes).
- **tofu**:
  - the CSP must allow `font-src data:`; when the font fails to load or is blocked, the real text shows through in the bone colour, with no JS fallback;
  - wrapping uses the block widths, so it can come out a line longer than the real text (~1 in 4 cases differ) and loaded content shifts the layout;
  - without `tofu.css` it falls back to the underline look; a text element containing an inline `skz-ignore` falls back to underline too;
  - see [Text bone modes](#text-bone-modes).
- **Shimmer throttling** (`--skz-shimmer-timing`):
  - under a 4× CPU throttle the default gains nothing (measured with `steps(36)`, the default is now `steps(30)`) (clip 18.4 fps, level with 18.0 before landing); set `steps(18)` (clip reaches 40 fps; underline / tofu stay at 14–15 fps);
  - it only affects the root driver (core and full's global); the svg engine's band is not throttled by this variable;
  - tiered by screen width by default (< 640px `steps(30)`, ≥ 640px `steps(42)`, ≥ 1280px `steps(54)`; 24 updates/s = seconds × 15, since the band only moves during the first 62.5% of the cycle); when you set `--skz-duration` yourself, change the step count to match;
  - see the `--skz-shimmer-timing` row of the [Feature reference](#feature-reference) and the post-landing re-test in [Comparison](#comparison).

### Buttons and form controls

- Inside a `skz-auto` region, `button` is a control and becomes **one whole bone** (outside one, write `skz-bone` on the button yourself): its background turns into the bone colour and its inner `span` / icons / text are all hidden, so no small bones are stacked on the button block.
- Radius: a `border-radius` the button sets itself is kept; otherwise `--skz-radius` applies.
- `input` / `textarea` / `select` are controls too: one whole bone each, no underline.
- A button inside a `skz-ignore` region is not turned into a bone and its content is visible again, but the button's own background is cleared to transparent (backgrounds on descendants of an ignore region are still cleared, see [Colours and backgrounds in `skz-ignore` regions](#colours-and-backgrounds-in-skz-ignore-regions)); to keep a button exactly as-is and clickable (e.g. "cancel loading"), put `skz-ignore` on the button itself (verified in Chrome 154).
- `explicit.css` has none of these inference rules: a button is only a bone when it carries `skz-bone`.

## Using with frameworks

skeletonizer is plain ESM plus a standard custom element. Vue / React / Svelte also have ready-made adapters (see "Framework adapters" above, sub-paths such as `skeletonizer/vue`); the snippets below integrate without an adapter.

Either way, load the styles once at the app entry: core users `import "skeletonizer/core.css"` (`import "skeletonizer"` also works when you call `enable()` directly); full users pick the base and the variants they need as described in [Entry points](#entry-points), e.g. `import "skeletonizer/base.css"; import "skeletonizer/global";`. Adapters and direct `enable()` calls share one core, and a variant import applies globally. The examples mark text with `<span skz-text>` (in JSX write `skz-text=""`: a bare attribute is `true` there, which React does not render on unknown attributes). The examples below are written for core; for full, replace `from "skeletonizer"` with `from "skeletonizer/full"`.

### Vue 3

Use `isCustomElement` so Vue leaves the `skz-box` tag alone (the adapter's `<SkzBox>` component does not need this step):

```js
// vite.config.js
export default {
  plugins: [
    vue({
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag === "skz-box",
        },
      },
    }),
  ],
};
```

Use it directly in a template:

```vue
<template>
  <skz-box :loading="isLoading" effect="pulse">
    <div class="card">
      <h3>
        <span skz-text>{{ user.name }}</span>
      </h3>
      <p>
        <span skz-text>{{ user.bio }}</span>
      </p>
    </div>
  </skz-box>
</template>

<script setup>
import { ref, onMounted } from "vue";
import { defineSkzBox, Bone } from "skeletonizer";

defineSkzBox();

const isLoading = ref(true);
// while loading, use mock data from Bone: empty text has no size and produces no bone
const user = ref({ name: Bone.text(8), bio: Bone.lines(2) });

onMounted(async () => {
  const data = await fetchUser(); // replace fetchUser with your own request function
  user.value = data;
  isLoading.value = false;
});
</script>
```

### React 18+

React 18 passes attributes to custom elements as strings natively, so use it directly:

```jsx
import { defineSkzBox } from "skeletonizer";

defineSkzBox();

// while isLoading is true, pass mock data from Bone as `user` (e.g. { name: Bone.text(8), bio: Bone.lines(2) })
export function CardSkeleton({ isLoading, user }) {
  return (
    <skz-box loading={isLoading} effect="pulse">
      <div className="card">
        <h3>
          <span skz-text="">{user.name}</span>
        </h3>
        <p>
          <span skz-text="">{user.bio}</span>
        </p>
      </div>
    </skz-box>
  );
}
```

On React 17, or when you need finer control, use `enable()` / `disable()`:

```jsx
import { useEffect, useRef } from "react";
import { enable, disable } from "skeletonizer";

// while isLoading is true, pass mock data from Bone as `user`
export function CardSkeleton({ isLoading, user }) {
  const ref = useRef(null);

  useEffect(() => {
    if (isLoading) {
      const off = enable(ref.current, { effect: "pulse" });
      return () => off();
    } else {
      disable(ref.current);
    }
  }, [isLoading]);

  return (
    <div ref={ref}>
      <div className="card">
        <h3>
          <span skz-text="">{user.name}</span>
        </h3>
        <p>
          <span skz-text="">{user.bio}</span>
        </p>
      </div>
    </div>
  );
}
```

### Svelte

Svelte supports custom elements directly:

```svelte
<script>
  import { defineSkzBox, Bone } from 'skeletonizer';
  import { onMount } from 'svelte';

  defineSkzBox();

  let isLoading = true;
  // while loading, use mock data from Bone: empty text has no size and produces no bone
  let user = { name: Bone.text(8), bio: Bone.lines(2) };

  onMount(async () => {
    user = await fetchUser(); // replace fetchUser with your own request function
    isLoading = false;
  });
</script>

<skz-box loading={isLoading} effect="pulse">
  <div class="card">
    <h3><span skz-text>{user.name}</span></h3>
    <p><span skz-text>{user.bio}</span></p>
  </div>
</skz-box>
```

Or use the adapter's action `use:skeleton`:

```svelte
<script>
  import { skeleton } from 'skeletonizer/svelte';

  let isLoading = true;
</script>

<div use:skeleton={{ loading: isLoading, effect: 'pulse' }}>
  <div class="card"><!-- content: mark text with <span skz-text>, images with skz-bone --></div>
</div>
```
