# skeletonizer — usage guide for coding agents

Skeleton screens from the **real component tree**: while loading, render the same components the page uses, fed with **mock data** from `Bone`, inside a skeleton **root**. You mark which elements are bones (`skz-text` / `skz-bone` / `skz-leaf`) and pure CSS paints them grey; unmarked content renders untouched. There are no separate placeholder components to write.

## Steps

1. **Pick full (default) or lite, and import exactly one of them once at the app entry.** The two are self-contained builds that each start with their own CSS import (styles come with the import). Without styles nothing changes on screen. Use the default unless bundle size matters most and the skeletons are small.

   ```ts
   import "skeletonizer"; // full (default): styles (full.css) + runtime + the global `skz`, everything built in (global / svg schemes, lazy rendering)
   // import "skeletonizer/lite"; // lite: the smaller build (styles lite.css + core runtime + the global `skz`)
   ```

   |                                            | full (default, `skeletonizer`)                                                                                                                                                    | lite (`skeletonizer/lite`)                                                                                                                                                                   |
   | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | Use when                                   | long lists / feeds / big forms (more than about 2,000 elements under one root with pulse / shimmer); old browsers must animate; you need underline / leaf text, or lazy rendering | small to medium skeletons in modern browsers, about 2,000 elements or fewer under one root; smallest bundle                                                                                  |
   | Browser bar                                | same bar for the full set; below it tiers 1 / 2 and an SVG animation fallback                                                                                                     | Chrome 119+ / Safari 16.4+ / Firefox 128+; below it: tier 0 static blocks (`skz-auto` regions), `skz-bone` / `skz-leaf` marks, fade; `skz-text` bars need the bar; **tested in Chrome only** |
   | Import                                     | `import "skeletonizer"`                                                                                                                                                           | `import "skeletonizer/lite"`                                                                                                                                                                 |
   | Effects                                    | fade / solid / pulse / shimmer; pulse / shimmer via the `global` or `svg` scheme (`engine` option)                                                                                | fade / solid / pulse / shimmer (root-driven CSS, band throttled to 24 steps/s)                                                                                                               |
   | Text modes                                 | round (default) / clip / underline / leaf                                                                                                                                         | round (default) / clip                                                                                                                                                                       |
   | Firewall · svg · lazy rendering · `skz-cv` | all available                                                                                                                                                                     | none                                                                                                                                                                                         |
   | Size (gzip)                                | 6.36 KB (JS 4.02 + CSS 2.34)                                                                                                                                                      | 4.37 KB (JS 2.38 + CSS 2.00)                                                                                                                                                                 |
   | Types                                      | widens the lite types after importing it: `text` / `shimmerMode` / `engine` / `fallback`                                                                                          | `EnableOptions`: `effect`, `fit`; `SkzEffect`: fade / solid / pulse / shimmer                                                                                                                |
   - **Never load both.** Each build carries its own copy of the core, so the extension registry and the global `skz` would split in two. Import `enable` / `Bone` from the one you picked.
   - Migrating from 0.2.x: the old `import … from "skeletonizer"` (core) is now `skeletonizer/lite`; `skeletonizer/full` · `/all` · `/global` · `/svg` are now plain `skeletonizer`; `skeletonizer/explicit` is removed (marks only is already the default, use lite); CSS subpaths are only `skeletonizer/full.css` and `skeletonizer/lite.css`.
   - SSR / Node: the `skeletonizer` and `skeletonizer/lite` JS entries start with a CSS import, so plain Node cannot import them without a bundler (the adapters and `skeletonizer/element` have no CSS import). SSR frameworks must bundle the package (Vite / Nuxt / SvelteKit: `ssr.noExternal: ["skeletonizer"]`; Next.js: `transpilePackages: ["skeletonizer"]`). Link `skeletonizer/full.css` (or `lite.css`) yourself for SSR first paint (put `skz` on the root in the server HTML).
   - Adapters (`skeletonizer/vue` · `/react` · `/svelte` · `/solid`) are glue only: no core code, no styles, no global. They read `enable` / `disable` from `globalThis[Symbol.for("skeletonizer")]`, which importing `skeletonizer` or `skeletonizer/lite` installs, so import one of them once at the app entry (otherwise development builds `console.warn` once and the adapters do nothing). Their option types come from `skeletonizer/lite` and widen when `skeletonizer` is imported.
   - No bundler in the browser: the JS starts with a CSS import the browser cannot load as a module, so serve `dist/full.mjs` (or `lite.mjs`) with its first line removed, `<link>` the CSS, and use an import map. Each `.mjs` is self-contained (no shared chunks).

     ```html
     <link rel="stylesheet" href="/vendor/skeletonizer/full.css" />
     <script type="importmap">
       { "imports": { "skeletonizer": "/vendor/skeletonizer/full.mjs" } }
     </script>
     <script type="module">
       import { enable } from "skeletonizer"; // full.mjs minus its first line; also installs the global skz
     </script>
     ```

     Files: `dist/full.mjs` + `dist/full.css`, `dist/lite.mjs` + `dist/lite.css`.

2. **Wrap the loading region in a root**, using the adapter for the project's framework:

   | Stack        | Code                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
   | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | React        | `import { SkzBox } from "skeletonizer/react"` → `<SkzBox loading={loading} effect="shimmer">…</SkzBox>`                                                                                                                                                                                                                                                                                                                                                                                  |
   | React (hook) | `useSkeleton(ref, loading, { effect })` with `ref` attached to an existing element                                                                                                                                                                                                                                                                                                                                                                                                       |
   | Vue 3        | `import { vSkeleton } from "skeletonizer/vue"` → `<div v-skeleton="loading">` or `v-skeleton="{ loading, effect: 'shimmer' }"`                                                                                                                                                                                                                                                                                                                                                           |
   | Vue 3 (comp) | `<SkzBox :loading="loading">…</SkzBox>` (register via `app.use(SkzPlugin)` or import `SkzBox`)                                                                                                                                                                                                                                                                                                                                                                                           |
   | Svelte       | `import { skeleton } from "skeletonizer/svelte"` → `<div use:skeleton={{ loading }}>`                                                                                                                                                                                                                                                                                                                                                                                                    |
   | Solid        | `import { skeleton, SkzBox } from "skeletonizer/solid"` → `<div use:skeleton={{ loading: loading() }}>` (keep a `void skeleton;` reference so TypeScript does not elide the import) or `<SkzBox loading={loading()}>`; `solid-js` is an optional peer (`>=1.6.0`)                                                                                                                                                                                                                        |
   | Angular      | No adapter: a small directive calling `enable(el, opts)` / `disable(el)` in `ngOnChanges` / `ngOnDestroy` (sample in README "Angular"), or `<skz-box [loading]="loading">` with `CUSTOM_ELEMENTS_SCHEMA`                                                                                                                                                                                                                                                                                 |
   | Vanilla JS   | `const off = enable(el, { effect })`, then `off()` when data arrives                                                                                                                                                                                                                                                                                                                                                                                                                     |
   | HTML / CE    | `import { defineSkzBox } from "skeletonizer/element"; defineSkzBox();` (a separate glue entry, no side effects on import; import `skeletonizer` or `skeletonizer/lite` once at the app entry as well) → `<skz-box loading>…</skz-box>` (`loading` on the host is the switch; `skz` lands on the first element child. SSR / no-JS: write `skz` on that child, e.g. `<skz-box loading><div skz>…</div></skz-box>`. No MutationObserver: if the child gets replaced, toggle `loading` once) |

3. **Mark the bones.** Nothing is a bone unless marked (or inside a `skz-auto` region). Put the bare attributes in the markup the loading state renders:

   ```html
   <div class="card">
     <img skz-bone src="…" width="48" height="48" />
     <h3><span skz-text>Name</span></h3>
     <p><span skz-text>A bio that may wrap onto several lines.</span></p>
     <div skz-leaf class="stats"><b>128</b> posts</div>
     <button skz-bone>Follow</button>
     <a skz-ignore href="/cancel">Cancel</a>
   </div>
   ```

   - `skz-text`: text bars along the real text lines. **Put it on an inner `<span>`, not on the block element**: the default `round` mode draws a block element as one whole rounded rectangle, an inline `<span>` gets one rounded bar per wrapped line. In JSX write `skz-text=""` (a bare attribute is `true` there, which React does not render on unknown attributes); the same goes for `skz-bone` / `skz-leaf` / `skz-ignore`.
   - `skz-bone`: this element is one bone (images, avatars, buttons, colour blocks), its subtree is hidden. `skz-leaf`: merge the subtree into one bone. `skz-ignore`: keep as-is and clickable. `skz-host`: a Web Component host (Shadow DOM) as one whole bone (host hidden, `::before` paints it).
   - Third-party components whose markup you cannot edit: write `skz-auto` on the root or on the wrapper; tag-based inference then applies to that subtree only (limits under "Markers").

4. **Feed the real components mock data while loading.** Every text node and image box needs content or size, otherwise there is nothing to paint. Build mock objects with `Bone` and render the normal component with them:

   ```ts
   import { Bone } from "skeletonizer"; // lite: "skeletonizer/lite"; or the global `skz.bone` without any import
   const mockUser = { name: Bone.text(8), bio: Bone.lines(2), avatar: Bone.image(48, 48), score: Bone.number(3) };
   const user = loading ? mockUser : data;
   ```

   - `Bone.text(n)`: exactly `n` chars of block "words".
   - `Bone.lines(k, { perLine })`: about `k` lines.
   - `Bone.cjk(n)`: CJK-width blocks.
   - `Bone.number(d)`: `d` digit-wide blocks.
   - `Bone.image(w, h)`: transparent image with intrinsic size; `Bone.image()` is a 1px GIF that needs width/height from CSS.

   All output is deterministic (SSR / hydration safe). For lists, render the expected number of mock items (e.g. `Array.from({ length: 5 }, () => mockItem)`).

5. **Done when** the page shows grey bones in the shape of the real layout while `loading` is true, and the real content with no leftover root `skz*` attributes once it is false (the `skz-text` / `skz-bone` markers may stay in the markup: they do nothing without the root's `skz`).

## Reference

### `enable(el, opts?)` and `disable(el)`

| Option     | Version   | Values                                                                                          | Default                                                    |
| ---------- | --------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `effect`   | both      | `fade` / `solid` / `pulse` / `shimmer`                                                          | `fade`                                                     |
| `fit`      | both      | boolean                                                                                         | `false`                                                    |
| `text`     | full only | `round` / `clip` / `underline` / `leaf` (lite only has round and clip, and ignores this option) | `round`                                                    |
| `engine`   | full only | `global` / `svg`                                                                                | `global` (the full build registers both schemes)           |
| `fallback` | full only | `svg` / `fade`                                                                                  | `svg` (what `global` does on browsers without `@property`) |

- `enable` returns an off function; `disable(el)` does the same (no-op if never enabled). Calling `enable` again re-syncs from the new options: omitted ones are cleared, not merged.
- Types: `skeletonizer/lite` exports `import type { EnableOptions, SkzEffect, SkzEffectMap, SkzExtension, SkzGlobal } from "skeletonizer/lite"`; `skeletonizer` (full) re-exports them and adds `SkzTextMode`, `SkzShimmerMode`, `SkzFallback`, `SkzEngine`, `SkzEngineImpl`. Importing `skeletonizer` widens `EnableOptions` (`text` / `shimmerMode` / `engine` / `fallback`) project-wide (it augments `"skeletonizer/lite"`), adapters included; with only `skeletonizer/lite` imported those are type errors.
- The CSS for `fit` is part of `lite.css` / `full.css`; nothing else to import.
- `engine` (full only): the full build registers both the `global` and `svg` schemes, so either name works; naming a scheme that is not registered (only when assembling from the source modules) falls back as before and development builds `console.warn` once.
- Extension points: `registerExtension({ name, sync, release })` (core, in both builds; `enable()` calls each `sync` in registration order) and, in full, `registerEngine({ engine, sync, release })` (what the built-in `global` / `svg` schemes register; it replaces the old `registerExtension({ engine, … })`).

### The global `skz`

Importing `skeletonizer` or `skeletonizer/lite` installs `globalThis.skz` (the same object is always also at `globalThis[Symbol.for("skeletonizer")]`, which the adapters read), also during SSR: `skz.enable`, `skz.disable`, `skz.bone` (= `Bone`). Example: `skz.enable(el, { effect: "shimmer" })`, `skz.bone.text(8)`. An existing `skz` that is not ours is never overwritten and development builds warn once (suggesting imports); the adapters do not install it. `import skz from "skeletonizer"` (also `skeletonizer/lite`) returns that same object, and still works when the global name is taken.

### `<skz-box>` attributes

`loading` (the switch: present and not `"false"`; also `el.loading = true | false`), `effect`, `text`, `fallback`, `engine`, `fit` (present and not `"false"`). Same values as the options above; without the full extensions loaded, `text` / `engine` / `fallback` are ignored.

### Adapter exports

Adapters are glue only (no core code, no styles, no global `skz`): they call the implementation that `skeletonizer` or `skeletonizer/lite` installed on `globalThis[Symbol.for("skeletonizer")]`; their option types come from `skeletonizer/lite` and widen when `skeletonizer` is imported.

| Import                 | Exports                                                                                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skeletonizer/vue`     | `vSkeleton` (`v-skeleton="loading"` or `="{ loading, effect, text, fallback, engine, fit }"`), `SkzBox` (props `loading`, `effect`, `text`, `fallback`, `engine`, `fit`, `as` = `"div"`), `useSkeleton(elRef, loadingRef, opts?)`, `SkzPlugin`, type `SkzBinding` |
| `skeletonizer/react`   | `SkzBox` (props `loading`, `as` = `"div"`, `className`, `children` + every option), `useSkeleton(ref, loading, opts?)`, type `SkzProps`                                                                                                                           |
| `skeletonizer/svelte`  | `skeleton` action: `use:skeleton={{ loading, effect, text, fallback, engine, fit }}`, type `SkzParams`                                                                                                                                                            |
| `skeletonizer/solid`   | `skeleton` directive: `use:skeleton={{ loading, effect, text, fallback, engine, fit }}`, type `SkzParams`; `SkzBox` (props `loading`, `as` = `"div"`, `class`, `children` + every enable option), written without JSX                                             |
| `skeletonizer/element` | `defineSkzBox(tag?)` registers `<skz-box>` (attributes `loading`, `effect`, `text`, `fallback`, `engine`, `fit`), class `SkzBox`; glue only, no core code, no CSS, importing has no side effects                                                                  |

### Markers (HTML attributes)

| Attribute       | Where                      | Effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skz`           | root                       | Skeleton on. Set by every adapter; write it yourself only for pure HTML / SSR output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `skz-effect`    | root                       | `fade` (default) / `solid` / `shimmer` / `pulse`. Adapters take it as the `effect` option.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `skz-text-mode` | root                       | **Full only** for the `text` option; lite also reads a hand-written `round` / `clip`. `round` (default when omitted; needs `box-decoration-break`, browsers without it use clip): text goes transparent and gets a rounded background box, an inline element wraps into one rounded bar per line, a block element becomes one whole rounded rectangle; GPU about half of clip. Known limits: bars are ~0.1–0.16em taller than clip's under YaHei / Segoe UI / system-ui; with `line-height: 1.2` multi-line bars can overlap into notches; the radius is the fixed `--skz-radius`; verified only in Chrome. `clip` (underline shape filled by `background-clip: text`, the 0.1.x default look; costlier than underline, see [the benchmark report](https://github.com/icodejoo/codejoo/blob/main/apps/skeletonizer/docs/reports/2026-10-09-benchmark-matrix.md); in full, browsers without `background-clip: text` fall back to underline via `@supports not`; decoration-in-clip verified only in Chrome) / `underline` (bars follow real text lines; colour pulse only, static under svg; the cheapest, pick it for low-end devices) / `leaf` (a `skz-text` element becomes one whole bone; in `skz-auto` regions a rounded block per text leaf, needs `:has()`) (an unknown value, including the removed `tofu`, looks like underline). Renamed in 0.2.0 (it used to be `skz-text`). |
| `skz-text`      | element                    | Text bars for the element's whole subtree, along the real text lines (last line shorter); on a container it also covers mixed content. Works inside and outside `skz-auto`, not read on the root itself. **Put it on an inner `<span>`** inside block elements. Needs `text-decoration-thickness` (`lite.css` also needs `:has()`); below that the real text shows.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `skz-bone`      | element                    | Force this element to be one bone. Use it on a `div` acting as an image, avatar, icon or colour block (empty divs are never inferred, even in `skz-auto`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `skz-leaf`      | element                    | Merge the whole subtree into one bone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `skz-host`      | element                    | A Web Component host (Shadow DOM): the host gets `visibility: hidden` and its `::before` paints one bone (same variables and animation as `skz-bone`); static CSS in lite and full, ignored on a `skz-ignore` host.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `skz-auto`      | root or any element inside | Turns on tag-based inference for that subtree only (for third-party components you cannot mark). Limits: it works from a tag allow-list and CSS cannot select text nodes, so bare text directly inside a `div` / custom element / `code` is not covered (invisible under round / clip): wrap it in `p` / `span` or mark it `skz-text`; a block-level text tag is one whole rounded rectangle under round.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `skz-ignore`    | element                    | Keep as real content and keep it clickable/focusable (e.g. a "cancel" button). Inside a `skz-text` element or `skz-auto` region its text shows on top of the bar; for a clean one write siblings: `<span skz-text>Price</span> <span skz-ignore>live</span>`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

Inside a `skz-auto` region (lite and full) bones are inferred from: text tags (`p` `span` `h1`-`h6` `a` `li` `label` `td` `th` `strong` `b` `em` `small` `dt` `dd` `blockquote` `figcaption`), media (`img` `video` `canvas` `picture` `iframe` `svg`), **controls (`input` `textarea` `select` `button`: one whole block each, no underline; a `button`'s inner `span` / icons are hidden, its own `border-radius` is kept, otherwise `--skz-radius`; put `skz-ignore` on the button itself to keep it as-is; inside an ignore region it is not a bone but its background is cleared)**, empty `<i>` and empty elements whose class contains `icon`. Internal markers, never write them: `skz-engine`, `skz-paused` (full), `skz-fw`, `skz-fit`, `skz-fit-hide`, `skz-x` (a specificity placeholder in the CSS).

### Editor hints for `skz-*` attributes

WebStorm reads `web-types.json` automatically (declared in `package.json`). VS Code needs `"html.customData": ["./node_modules/skeletonizer/html-custom-data.json"]` in `.vscode/settings.json`. In JSX / templates, importing an adapter (`skeletonizer/react`, `/solid`, `/svelte`, `/vue`) types the `skz-*` attributes (shared type `SkzHtmlAttributes` from `skeletonizer/lite`): bare attributes take `""` (React / Vue) or `""` / `true` (Solid / Svelte), never `false`; enums are checked (`skz-effect="nope"` is an error).

### Choosing an effect

- `fade`: root-level opacity pulse, composited, free at any size. The default.
- `shimmer` / `pulse`: the most polished look (shimmer: every bone sweeps a fixed 300px band across its own box, all bones start and finish together, 2s / 2.8s / 3.6s cycle by viewport width, same on iOS; in clip mode the direct parent of a `skz-text` takes over the background (its own background is covered) so all lines sweep together; a `skz-text` directly under the root, or inside an inline parent, still sweeps line by line; round text sweeps each line together); they work out of the box in `lite.css` and `full.css` (a root-driven CSS animation, needs `@property` + relative colour syntax, i.e. Chrome 119+ / Safari 16.4+ / Firefox 128+; below that they fall back to `fade`, except that in full the `global` variant attaches an SVG animation from JS, `fallback: "fade"` keeps the base fade instead, and before JS runs / when the blob cannot be built they show `fade`). Each shimmer cycle ends with a 0.4s rest outside the bone and sweeps the rest; the cycle follows the viewport (`2s` below 640px, `2.8s` from 640px, `3.6s` from 1280px; `fit` mode a fixed `2s`), pulse / fade stay `2s`, and a `--skz-duration` you set replaces it for all of them. The band updates 24 times per second by default (`--skz-shimmer-timing` defaults to `steps(38)` / `steps(58)` / `steps(77)` for the three tiers: steps = sweep seconds × 24, sweep seconds = total × the tier's share (80% / 85.714% / 88.889%), because timing functions apply per keyframe segment, so change it together with `--skz-duration` if you set one); set `--skz-shimmer-timing: linear` on the root for per-frame smoothness or `steps(18)` for cheaper. The svg engine is not throttled. **lite has no inheritance firewall: in desktop Chrome at normal speed pulse / shimmer hold 58-60 fps up to about 4,000 elements under one root (6,000 elements: pulse 46 fps, shimmer 58 fps; 16,000: 18 / 17 fps), but under a 4x CPU throttle 504 elements already give only 41-52 fps and 2,000 elements 16-21 fps (full with the firewall at 2,000 elements: 55-60 fps). Plan for about 2,000 elements under one root with lite, move to full beyond about 4,000 elements on desktop, or beyond a few hundred when slow devices matter**
- `solid`: no animation.
- Lists (cards, rows) with `shimmer` / `pulse` beyond lite's size limit (full): the `global` scheme is the default in `skeletonizer`; nothing else to configure. `enable()` / the adapters automatically "firewall" off-screen items so only visible items animate (16,000 elements stays at 60 fps). Keep the items as children of the root or of a single wrapper inside it.
- Large skeletons without list structure (full): use `engine: "svg"` (one shared animated SVG background; exact theme colours when enabled through JS; explicit `underline` text stays static, round / clip text moves). Pick svg per root via `engine: "svg"`.
- Marks only, no inference rules at all: that is the default (inference needs `skz-auto`), and `skeletonizer/lite` has the smallest, cheapest rules; mark every bone (`skz-text` / `skz-bone` / `skz-leaf`). The former `explicit` entry was removed in 0.3.0.
- Large skeletons in pure CSS (no JS, so no firewall; `skz-cv` is in `full.css`, not in `lite.css`): add `skz-cv` on the root so off-screen children skip rendering (clips each child's overflow; set `--skz-cv-size` to the typical child height). Do not combine it with `enable()`: the firewall is already faster, and `skz-cv` makes enabling about 3.5× slower (measured with underline text).
- Placeholder lists of unknown length (e.g. 100 mock rows): pass `fit: true` (`<skz-box fit>`, also accepted by the adapters). The root is capped to the space left in its nearest scroll container (or the viewport), rows fully outside get `display: none`, and it re-measures on resize, so the skeleton itself never causes a scrollbar. If the boundary scrolls anyway (content below, or the skeleton starts below the fold) it relaxes to one screen. Enabling costs one extra layout (about 0.77 s for 16,000 elements with clip text (the pre-0.2.0 default), vs 85 ms without `fit`; measured with underline: 0.52 s vs 61 ms; see [the benchmark report](https://github.com/icodejoo/codejoo/blob/main/apps/skeletonizer/docs/reports/2026-10-09-benchmark-matrix.md)).

### Theming

Variables are declared on the root itself, so override them **on the root element** (inline `style` or a selector that targets the root), not on `:root`:

```html
<div skz style="--skz-color:#e5e7eb; --skz-highlight:#f3f4f6; --skz-radius:6px; --skz-duration:1.2s">…</div>
```

| Variable                                       | Default                                                  | Notes                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| `--skz-color`                                  | `#d9dde3` (dark `#374151`)                               | bone colour                                                                                                                                                                                                                                                                                             |
| `--skz-highlight`                              | `#eceff3` (dark `#4b5563`)                               | shimmer band / pulse peak; for the svg engine call `enable()` again after changing it                                                                                                                                                                                                                   |
| `--skz-radius`                                 | `4px`                                                    | an element's own `border-radius` wins; round text bars read it too (fixed, no scaling with the font size); underline / clip text bars have no radius                                                                                                                                                    |
| `--skz-duration`                               | `2s`                                                     | animation duration                                                                                                                                                                                                                                                                                      |
| `--skz-shimmer-timing`                         | `steps(38)` / `steps(58)` / `steps(77)` by viewport tier | shimmer band timing, 24 updates/s during the sweep (steps = sweep seconds × 24, sweep seconds = total × the tier's share; change both together when you set `--skz-duration`); `steps(18)` cheaper, `linear` smooth; root driver only (core and `global`), not the svg engine                           |
| `container-type: inline-size` (not a variable) | —                                                        | even-mode shimmer travel = max(bone width, 100cqw) + 300px; 100cqw = nearest query container, viewport width without one, 100vw in browsers lacking cq units. ## Gotchas

- **Vue component name is `SkzBox`.** In templates write `<SkzBox>`; `<skz-box>` resolves to the native custom element instead (the switch there is the `loading` attribute / property on the host; the skeleton state lands on its first element child).
- **Unmarked content is untouched.** If nothing turns grey, the markers are missing: add `skz-text` / `skz-bone` / `skz-leaf`, or `skz-auto` on a third-party subtree.
- **`skz-text` goes on an inner `<span>`.** On a block element (`p`, `h3`, `div`) round draws one whole rounded rectangle, short headings stretch to the full row.
- **Bare text in a `skz-auto` region is invisible under round / clip** when it sits directly in a `div`, custom element or `code` (the inference works from a tag allow-list): wrap it in `p` / `span` or mark it `skz-text`.
- **Empty elements produce no bones.** A `div` with no text and no size renders nothing; give it mock text, a size, or `skz-bone`.
- **Images:** pass `Bone.image(w, h)` as `src` so the box keeps its size; real image URLs still download and may show through.
- **Pure HTML attributes skip the JS features.** Writing `skz` by hand gives the CSS look only: no `inert` lock, no off-screen pause. Use an adapter or `enable()` when those matter.
- **Off-screen roots pause** (full only: `skz-paused` is added automatically by the full extensions and styled by `full.css`; lite does not pause). One huge root keeps animating while any part is visible; split long pages into several roots.
- **`skz-ignore` inside a root disables the implicit `fade`**, since fading would dim the ignored content. Set `effect="fade"` explicitly to force it.
- **The CSS needs no JS.** With `skz` written on the root by hand, the markers render correctly; only the lock (`inert`), lazy pause, firewall and runtime SVG need JS.
- **Old browsers (no `@property`) and `pulse` / `shimmer`?** With the `global` scheme (full) they get a JS-attached SVG animation by default (`fallback: "svg"`); pass `fallback: "fade"` to keep the base fade. They show `fade` until JS runs. The SVG is a blob URL, so a strict CSP needs `img-src blob:` (`data:` is only needed by `Bone.image`).
- **Shadow DOM components** (third-party web components) are opaque to page CSS. Write `skz-host` on the host element; it becomes one bone (static CSS, nothing to call). Styles inside the shadow root are yours to import.
- **React `useSkeleton`**: pass `effect` / `text` as plain values; the hook re-runs when they change.
- **`prefers-reduced-motion`** stops all animations, including `fade`. This is intended.
- **full and lite are two builds, not layers.** Pick one per project and never import both. lite drops frames on big roots (no firewall, see "Choosing an effect"); full has a much higher limit (inheritance firewall).
- **Development warnings** (`process.env.NODE_ENV` not production, once each; every call site is behind a `try { if (process.env.NODE_ENV !== "production") … } catch {}` guard, so a production bundle drops the calls and message text): the global `skz` is already taken by something else; an explicit `engine` that is not registered (only when assembling from the source modules); an adapter used with neither `skeletonizer` nor `skeletonizer/lite` imported.
- **Verified on desktop Chrome only.** Safari, Firefox and mobile are untested; lite's "works in Firefox / Safari" is by spec only.
